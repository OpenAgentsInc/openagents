# World residency and resource ownership

The [native category-pressure qualifier](../../docs/verification/aethyr-streaming-12990/walk-category-pressure.md)
now requests a real source-derived texture companion against the live
corridor's budget/inbox/renderer. Its refusal preserves the existing image
and owners, and CPU replay records the counted admission boundary. The later
native backing qualification covers physical allocation admission; browser
transport/transient planning stays open. Native
[allocation/source/decode failures](../../docs/verification/aethyr-streaming-12990/walk-native-load-failures.md)
now complete and retire through the shared owner before retry. Its
[checked Vulkan resource factories](../../docs/verification/aethyr-streaming-12990/walk-native-factories.md)
unwind partial creation, with actual successful carrier adoption.
[Owned native transfers](../../docs/verification/aethyr-streaming-12990/walk-native-transfers.md)
now retain buffer/image views and staging through completion, with actual
held-observation guards and exact CPU replay on both tiers/backends.
The [integrated SDK qualifier](../../docs/verification/aethyr-streaming-12990/walk-native-sdk-failures.md)
adds 136 scoped staging/destination/submission/poll error histories, including
upload deadline stops and exact CPU replay. Pending owners and sources stay
retained until terminal observation; stopped attempts publish no ready data.
These inputs do not qualify physical OOM or a driver reset.
The [backing-budget component](../host/backing-budget.md) and admitted Vulkan
factories now reserve measured allocation sizes before `vkAllocateMemory`.
The actual corridor now adopts these entry points for streamed, staging,
fixed-renderer, replacement and readback allocations, with device-bound
[plans and allocation histories](../host/native-backing.md). Browser transport,
container and transient planning remains separate required work.
The [transport companion](../host/transport-manifest.md) now derives whole
container/source spans and reader/raw page peaks. The shared loader prepays
raw transfers and public packs with known lengths, with atomic admission
before reactor/fetch effects. The [HTP1 carrier](../../docs/verification/aethyr-streaming-12990/walk-transport-binding.md)
now binds the actual packed/raw corridor loads and records original tickets,
allocation/source/join/release histories with independent reconstruction.
Remaining auxiliary transient planning and the final consumer audit stay open.
The [actual callback qualifier](../../docs/verification/aethyr-streaming-12990/walk-callback-retirement.md)
holds image/buffer responses across unwanted-state cancellation, observes
physical join/retirement before a newer generation, then redelivers the old
callback. Current storage, canonical state and pixels survive all eight raw
old-key/wrong-epoch refusals. Both tiers replay every accepted paid step.

`cells.coax` is the historical #12847 controller: 64 m cells, separate
resident/simulate/draw states, hysteresis, persistent sleeping bodies,
edge admission, floating origin and recorded completion envelopes.
`owners.coax` is the separate distributed cell-owner contract. Neither is
replaced by the resource-cost work.

These files are source parts so a composed host has one owner of the
existing unmoduled image decoder. The companion does not change VPK1/VPK2
or any published renderer/host ABI. RCM1 has at most 64 resources and eight
dependencies per resource. Entries name earlier owners in strictly
increasing order. Identical content with a different category, image side
or backend is a different concrete layout owner; identical content/spec
pairs must share one entry. Every dependency also carries its full source
SHA-256. A trusted world root names the complete manifest SHA-256.
Digest fields serialize `AssetId`'s eight numeric SHA-256 words as
little-endian u32 values; conventional hex identity still uses `asset_hex`.

The manifest builder derives plans from actual bytes. Reading a trusted
manifest validates its encoding and closure; readiness additionally needs
`resource_matches`, successful real decoding, completion of platform
effects and the stream's tick/epoch/wanted gate. A successful image plan
alone does not authenticate later compressed image data.

Existing version-1 model bytes and identities remain unchanged. Packed VPK
vertices use format 8 and cost-model version 2, with a separate pinned model
digest. Their encoded/GPU bytes include the complete 48-byte records; no
retained CPU expansion is declared. Packed color/layer/spare fields are not
floating-point attributes. Manifest reading requires the canonical model
digest for its actual formats, so an old model header cannot admit this new
layout. `ResourcePlan` remains 168 bytes.

Admission charges encoded bytes, retained decoded bytes, one physical
168-byte `ResourcePlan` and logical GPU bytes to the resource's category.
Decoder work and an explicit native upload span charge staging. The host
must retain a separate plan object if it uses this allocation profile;
the manifest and fixed controller/host storage are additional owners.
The retained plan object follows its generated ABI alignment; the cost's
alignment field describes the resource payload.
Browser queue writes borrow the retained source span. The measured native
carrier maps its granted transfer span through submission completion; its
actual Vulkan backing requirements are reported separately from logical
RCM1 GPU bytes and admitted through device-bound backing leases. Opaque SDK,
driver, Wasm arena and allocator overhead are separate observations.

Physical allocations and GPU creation follow a successful grant. The
original 64-ticket/32 MiB inbox and 512-slot/1 GiB renderer ceilings remain
in force. A cancellation cannot settle scratch. Only actual effect
completion permits settlement, and final borrowers plus physical
destruction precede retirement. Duplicate lease copies cannot release
retained CPU bytes twice. A lost GPU handle cannot release a replacement.

Each concrete parent retains one edge to each dependency, regardless of
how many root claims use that parent. The edge survives cancellation and
retirement through the parent's actual physical destruction. Current demand
is computed separately from live root claims; an old upload can retain a
dependency without wanting it published. Loading owners retain their full
reservations until actual effect completion. A successful decode remains
unpublished until a later fixed-step publication can also admit every
dependency. Insufficient output capacity leaves the prior state and events
unchanged. Destruction receipts, rather than cancellation signals, release
retained tickets.

The stream has 64 claims, 64 immutable borrows and at most four unfinished
loads. It retains its expected manifest identity and owner epoch throughout
cleanup. Closing rejects new demand but still accepts the old owner's
matching completion and final-borrow receipts. Reused slots and retried
loads require new serials. Render borrows use a separate serial counter and
a different reference type, so display frequency cannot change logical load
generations. Exhausted counters refuse instead of wrapping.

The platform must queue completion facts. Its fixed-step coordinator calls
the controller, records every applied result including failures and cleanup,
then publishes readiness. Host callbacks cannot mutate the simulation or
replace an old stream's backing state. The retained manifest is immutable
until the stream finishes; queue/registry arguments remain the concrete
owners supplied to admission. The corridor consumer implements these
obligations; its exact measured scope is recorded below.

`CellRings` and `cell_step_profile` add a checked profile entry without
changing `CellWorld`, `CellStep` or the legacy entry points' default rings.
Bad profiles, manifests, positions and an incompatible cap reduction refuse
atomically. Prior work must drain before switching to smaller caps. The
shared ask loop refuses a spent request counter instead of wrapping it.

Profile 1 declares four resident cells and one new cell request per paid
step, with 32/64/96 m draw/simulate/resident rings and 8 m hysteresis. Near
actors update every paid tick and farther simulated actors every fourth
tick. Texture, baked-lighting and audio collection use independent 96/80/64 m
radii with hysteresis. An 8 m neighbor-edge trigger returns a placement hint
under a declared 4 KiB/one-root prefetch quota; the caller still has to admit
and charge that quota. The hint never writes cell state, answers a load or
permits simulation. The intended active pools are four streamed actors, one
persistent player and two voices; animation, sensors, effects and dynamic
lights are zero in this initial profile. Player/camera/HUD are the three
persistent services. The corridor adopts the player, camera, texture-free
HUD and separate collection/update policies. The HUD reads only player
distance and remains drawable before any area resources and while cells
retire. Its 98,304-byte CPU vertex span, matching GPU vertex buffer and
256-byte GPU uniform buffer belong to persistent display storage. They do
not borrow an area resource or charge its dynamic category.

`coax/web/tool.sh aethyr/tools/streaming-assets.coax NEW_OUTPUT_DIR` builds
the original CC0 corridor fixture: 12 cells, 13 admitted VPK1 packs, raw
collision/body records, and 64 source resources. Four RCM1 companions cover
both backend transfer models and both image tiers while preserving all source
identities. `scene.json` records full content/container hashes and admitted
source spans. Existing output directories refuse. The independent
`python3 aethyr/tests/streaming_assets_oracle.py OUTPUT_DIR --fault-checks`
recomputes the geometry, PNG pixels/CRCs, PCM, dependency digests and all
declared cost lanes, including rehashed deliberately broken fixtures.
This qualifies asset preparation, not active residency or physical memory.

The [HUD record](../../docs/verification/aethyr-streaming-12990/walk-persistent-hud.md)
qualifies both image tiers at browser rasters 320×180 and 640×360, plus
native 320×180 hardware and sanitizer routes. The display profile is
`aethyr.stream-walk-display.v1`: world and HUD compose in linear
`rgba16float`; the final pass performs no tone/gamma transform. This is
the corridor's declared linear-display fixture, not a general color-managed
renderer. Its fixed HDR target costs eight logical bytes per pixel, in
addition to the existing four-byte depth and display targets. Native SDK
backing extents remain separate measured values. Complete HUD raster
comparison uses a fixed two-level channel bound with no masks or shifts;
the world-only base remains a frozen GPU observation.

The optional paid-step observer uses canonical state profile
`aethyr.stream-walk-state.v1`. It serializes explicit little-endian 64-bit
words (IEEE bits for floats, zero/one for booleans), never struct padding or
pointer addresses. State includes the pending frame schedule and paid-step
ordinal, player/camera/input history, the named profile, physical surfaces,
logical cells and sleeping bodies, entity-store fields, retained decoded
collision/body values, resource generations/claims/admission leases and
budgets, inbox entries, counters and live command/event outboxes. The
immutable manifest identity binds source formats and cost models.

Observations follow complete application of queued facts. GPU handles and
registry state, render-borrow serials, overwritten query/navigation scratch,
unused capacity and observer storage are outside this simulation profile;
actual SDK ownership has separate traces. Pending callbacks do not enter a
digest before their recorded paid boundary. Each observer digest uses a
bounded 128 KiB local serialization buffer inside the separately reserved
reactor arena; its eight retained digest slots are fixed controller storage.
Replaying the same accepted history compares each paid step, including the
steps between a frame's start and endpoint. Different live completion
schedules still need not produce identical simulation.

The [automatic browser-loss record](../../docs/verification/aethyr-streaming-12990/walk-automatic-loss.md)
adds actual device-loss callbacks, three losses per minute, an absolute
ten-second replacement deadline and stale-attempt fencing. Both rebuilding
and stopped sessions refuse paid frames through the checked Coax face;
cleanup requires the session's actual closing state. Failed replacement
retains CPU/source owners until explicit close. The additive
[whole-reactor rescue carrier](../../docs/verification/aethyr-streaming-12990/walk-persistent-rescue.md)
now checkpoints C statics and allocated source spans too. Its exact-build
IndexedDB restore recreates GPU handles without applying a simulation step;
unfinished source effects resume against their existing allocations. Pending
facts survive in the image but remain outside the accepted-state digest
until their ordinary paid boundary. Native rescue and broader failure and
memory profiles remain unqualified. The ordinary host contract is unchanged.

The [native-history replay record](../../docs/verification/aethyr-streaming-12990/walk-native-cpu-replay.md)
extends the actual CPU receiver to the Vulkan carrier's v1/v2 histories.
It selects their original native manifest and emits an explicitly versioned
v3 receipt. Every paid-step digest, completion record, position bit and final
actor value is compared; this is offline CPU/codec replay, not recreated GPU
effects. Replay's malloc scratch follows accepted completion boundaries,
so its independently reconstructed physical peak differs from synchronous
Vulkan effects. The existing browser input/output identities remain valid.

The [native reported-loss record](../../docs/verification/aethyr-streaming-12990/walk-native-loss.md)
adds owned Vulkan submissions and result-driven draw recovery. A timeout
retains the command pool, fence and all drawn resource borrows until actual
completion is observed. Rebuilding reuses the existing CPU sources and
GPU-generation replacement. Actual Vulkan rendering plus explicitly labelled
SDK-result injections cover both tiers; no physical GPU reset, ordinary-host
migration, factory/upload recovery or native persistent rescue is claimed.
