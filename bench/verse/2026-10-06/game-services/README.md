# Persistent realm game services

`checks.json` binds the changed source, source patch, pinned toolchain, target,
and test executable to the retained checks. The final source commit is rebased
on main; its Rust files and direct dependency manifests match the tested source.
`loop.json` comes from the actual two-listener TLS fixture in
`service::realm::services::tests`. `sha256.json` seals the retained artifacts.

The loop authenticates two original test characters in separate admitted realm
instances, creates a party, freezes host-authorized loot recipients, claims and
repeats a quest, and exchanges individually identified gear by consent. It
checks foreign access and exact retries, derives resource limits for an authored
guardian fixture, transfers between zones, reconnects after explicit logout,
resumes, and restarts the realm. Final experience remains 200 after retries.
The full world run also covers guild invitations, decline and membership,
changed definition refusal, expired offers, ownership changes before consent,
quest abandonment, recovery, and all five trade publication crash boundaries.

The fixture uses temporary private state, generated TLS certificates, and fixed
public test keys. It creates no tasks or chats on an owner's host. Its grant
adapter supplies authored outcomes; it does not establish automatic party combat
attribution, a complete commerce UI, large-party throughput, or phone/browser
presentation. Existing standalone REACH chambers require a realm adapter before
these service operations are available there.
