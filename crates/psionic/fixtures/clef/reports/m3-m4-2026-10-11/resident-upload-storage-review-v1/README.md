# Bounded file reads for resident Metal weight upload

This is an unexecuted capacity proposal. It changes how packed weights reach the existing Metal conversion kernel, not their bytes or arithmetic. It does not establish a 52 GiB limit or a speed improvement. Keep the owned-process guard as the maximum of RSS and physical footprint, with the existing host-memory floor.

## Evidence

The current resident 27B load retains one mmap-backed GGUF through the CPU model's quantized tensor ranges. Each resident Metal projection separately copies mapped packed bytes into a temporary Vec and a temporary Metal buffer, converts to resident f16, waits, then drops both temporary packed copies. There is no permanent packed Metal copy in resident mode.

A header-only inventory finds 496 quantized trunk projections containing 17,316,085,760 packed bytes and 48,701,112,320 resident f16 bytes. The largest packed matrix is 66,846,720 bytes; the largest half matrix is 178,257,920 bytes. Dense block tensors total 10,561,536 bytes. Token embeddings and output rows occupy 715,161,600 and 1,042,944,000 packed bytes respectively; these remain readable after loading.

The historical resident run's peak RSS is 69,623,676,928 bytes, versus physical footprint of 52,375,259,128 bytes at the same sample. Their difference, 17,248,417,800 bytes, is close to the packed trunk size. This supports the file-backed residency explanation but is not a per-mapping attribution. Subtracting the entire packed trunk gives only a hypothesis, not a measured peak. The historical run did not load the image tower. Later embedding-row faults, image weights, request scratch, prefix or batching caches, and allocator retention still require budget checks.

`accounting.json` preserves the exact descriptors, source hashes, and selected historical sample. It reads only the existing GGUF header; no tensor payload or model executes for this review.

## Existing reads and ownership

- `psionic-catalog/src/lib.rs`: `LocalBlob::open_path` maps one open File but drops the File after construction. `LocalBlob` clones share an `Arc<BlobBacking>`; `PagedBlobRange` retains a clone. Its borrowed `bytes` and `read_range` APIs require the mapping to remain valid. `PreferBuffered` calls `fs::read` on the entire file and is unsuitable for this proposal.
- `psionic-models/src/lib.rs`: `GgufContent::read` parses the header. `GgufWeightBundleLoader::describe_artifact` hashes metadata, not tensors. `paged_tensor` and its range validation form slices without accessing payload. `PagedTensorStorage` forwards borrowed reads.
- `psionic-serve/src/qwen35.rs`: `load_quantized_matrix` and `HostProjectionGroup::load` save tensor ranges and shapes. Dense norms and convolution tensors load eagerly. Tokenizer state owns parsed metadata. `QuantizedMatrix::decode_row`, CPU matvec, and CPU prefill still need the borrowed interfaces.
- `psionic-serve/src/qwen35/clef_metal.rs`: `upload_matrix_with_placement` is the bulk mapped read: `read_range(0, len)?.to_vec()`. It handles all quantized trunk projections, including non-FFN matrices. The resident f16 conversion and wait already bound temporary-buffer lifetimes.
- `psionic-serve/src/clef/mod.rs`: both the initial/head artifact and CPU model use `LocalUnverifiedLabel` without an expected digest. The final artifact digest uses an independent 8 MiB buffered SHA stream. This proposal does not remove or weaken that hash. Auto's CPU fallback occurs during initial device selection; a subsequent GPU request error does not silently execute the CPU trunk.
- Serial and batched Metal requests read token embedding rows from the CPU model. The head's lexical thread reads output rows concurrently. Retain the same CPU model and mapping for these readers and for CPU use after initial GPU-load failure. The vision runtime owns separate safetensor-derived weights; leave it unchanged.

## Small opt-in patch

1. Add an owned positional-read path to the existing local blob, without replacing its borrowed APIs. Retain the original open `File` beside the mmap in the shared backing. A Unix `read_range_into(offset, destination)` validates the range against the original blob length and reads through `FileExt::read_exact_at`. It never reopens the pathname or changes a shared seek cursor. Forward it through `PagedBlobRange` and `PagedTensorStorage`; compute absolute offsets with checked arithmetic. Read errors and short reads fail loading. Cloned tensor views share one file handle and release it with the backing.
2. Parse a single explicit Metal upload mode once, for example `PSIONIC_CLEF_METAL_WEIGHT_UPLOAD=mapped-copy|positional`. Keep `mapped-copy` as the default. Initially require `resident-f16` when positional upload is selected, and require the actual backing to be memory-mapped; the existing buffered fallback already contains the whole file and cannot satisfy the intended capacity benefit. Pass the mode through all resident matrix upload calls, not just FFN gate/up/down.
3. In positional mode, allocate the same checked per-matrix Vec and fill it with the new positional read. Keep format selection, source buffer creation, dequantization, command completion, and resident buffer publication unchanged. Continue holding the source buffer through completion. Do not prefetch or scan the mapped packed range as part of this path. This avoids mapping touches instead of discarding pages or altering system policy.
4. Preserve all integrity behavior. The actual Clef opens skip the mapping-wide hash by existing policy and later stream SHA. For a generic caller using `Sha256` or `expected_sha256`, the present open path still touches the whole mapping; document that the capacity benefit does not apply unless an independently reviewed same-file streaming hash replaces that implementation with identical digest checks. Do not disable verification. File handle identity protects against pathname replacement, not modification of the already-open inode. Weight immutability remains required; add before/after metadata consistency checks and retain full artifact identity validation, without pretending metadata checks prove content immutability.

The patch affects catalog storage, the models forwarding API, and the Metal serving loader. It needs no kernel change, no CPU decoder change, no row-reader rewrite, no model-copy destruction, and no change to prefix/batch execution. In particular, adding a generic `pread` backing to the borrowed-slice API would be a larger redesign and is unnecessary for this upload-only experiment.

## Bounds and verification

The additional permanent storage is one file descriptor per shared mmap backing. The owned packed Vec already exists today; filling it positionally does not add a second Vec. For the inspected model, its largest allocation is about 63.75 MiB. A packed Metal source and the destination f16 matrix overlap temporarily exactly as before. Neither the logical CPU memory plan nor the process guard should subtract file-backed memory on assumption.

Before a full model run, test byte equality for aligned, unaligned, tail, and empty ranges; overflow and out-of-range refusal; short-read/truncation failure; independent concurrent reads; view-clone lifetimes; and the same opened inode after atomic pathname replacement. Cover Buffered explicitly, so it cannot be mistaken for an economical path. A synthetic quantized Metal fixture must compare mapped-copy versus positional source bytes, resulting resident f16 bytes, and output bits for Q4_K, Q6_K, and Q8_0. Test drop-on-conversion failure and successful publication only after completion.

Then qualify a single model with unchanged inference flags, explicit startup and request bounds, no caches, identical request bytes, exact logits and tops, and full memory receipts through loading and the longest request. Include repeated distinct token/option rows and a separate image-capacity check if images are in scope. A large-model 52 GiB run is authorized only after root reviews the allocation estimate and available-memory preflight; this note grants no execution. The point is a possible capacity improvement to resident execution. It does not remove GEMM work or establish the remaining M3 latency target.
