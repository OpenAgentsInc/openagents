# Security and trust boundaries

Status: proposed security architecture. Each boundary requires adversarial
verification before untrusted public creation is enabled.

Aethyrforge accepts source code, shaders, imported assets, model proposals, and
networked players. Treat all five as hostile inputs. Budget does not remove
browser vulnerabilities, GPU-driver faults, denial of service, or the creator's
need to control access. See [platform support](platform-support.md),
[scripting](scripting.md), and [verification](verification.md).

## Threat model

**SEC-001.** Protect project confidentiality and integrity, creator identity,
publication authority, personal data, service credentials, player state, and
bounded service expenditure. Consider malicious collaborators, game scripts,
models, packages, asset parsers, compromised workers, and stolen publisher keys.
The initial model does not claim protection from a compromised browser,
operating system, physical device, or intentionally authorized plaintext export.
Document those limits without using them to excuse avoidable boundary failures.

Every authority decision checks tenant, project, role, requested capability,
object scope, expiry, and present revocation. Online privileged decisions use the
current authority. Offline creation and cached play use only explicitly permitted
local capabilities and their latest verified trust snapshot; they cannot assert
fresh remote revocation status, publish, or spend remote funds. Reconnection
rechecks current remote authority before uploading or invoking integrations.
Viewer, commenter, editor,
publisher, and administrator permissions are independent. Permission changes,
exports, builds, and channel updates leave attributable audit records. The
service derives actor identity from authentication, never a client-supplied
display name.

## Origin separation

**SEC-002.** The trusted editor and credential broker use a different
registrable domain from untrusted preview/player content. Each project receives
an isolated player origin; private previews may use short-lived origins. No
domain-wide authentication cookie is shared with player hosts. The editor never
imports game modules into its JavaScript realm or grants them a handle to its
DOM, storage, filesystem, authenticated fetch client, or GPU resources.

This boundary follows the browser's origin model: actors sharing an origin are
assumed to have the same authority. A worker or Wasm module inside the trusted
origin does not establish the required project boundary.
[HTML origins](https://html.spec.whatwg.org/multipage/browsers.html#origin).

A preview uses a sandboxed frame with only the tested flags required for input,
rendering, and supported storage. It denies navigation, popups, downloads,
camera, microphone, clipboard, and device APIs by default. A distinct-origin
frame may retain its own origin for approved browser APIs; it must never share
the editor's origin. Response-header Content Security Policy (CSP), Permissions
Policy, and cross-origin policies are generated by trusted hosting code. Project
HTML cannot weaken them. CSP restricts fetch and script destinations, but is a
defense in depth rather than proof that arbitrary scripts are harmless.
[CSP specification](https://www.w3.org/TR/CSP3/).

## Capability broker

**SEC-003.** The editor authenticates the initial frame handshake by exact origin,
window identity, fresh nonce, and protocol version, then transfers a dedicated
message port. All messages use closed schemas, bounded buffers, request IDs,
generation IDs, deadlines, and response limits. Reject stale ports after frame
replacement. Never use a wildcard target for credential-bearing messages.
The [HTML messaging security rules](https://html.spec.whatwg.org/multipage/web-messaging.html#security-9)
require origin checks; Aethyrforge additionally binds the active frame instance.

The broker grants narrow operations such as reading a permitted immutable asset,
submitting a bounded simulation input, or requesting a reviewed project command.
It does not grant generic filesystem, shell, arbitrary URL fetch, raw database,
or authenticated HTTP capabilities. Capability handles are unguessable,
project-scoped, expiry-bound, quota-bound, and revocable. Possessing a handle is
insufficient when its current permission check fails.

Cloud API keys, signing keys, refresh tokens, and editor bearer tokens never
enter game code, asset metadata, shader source, telemetry, or published bundles.
Remote integrations execute behind an authorized server adapter. Model output
is untrusted proposal data: it cannot choose credentials, widen a capability,
approve its own action, or execute shell commands.

## Execution and resource budgets

**SEC-004.** Compile the approved safe TypeScript behavior subset to owned
bytecode and execute it in a Rust/Wasm virtual machine in a replaceable worker
hosted by the untrusted origin. Each instruction consumes fuel; every host call
has a bounded input, output, and work allowance. Bytecode validation rejects
unknown instructions and invalid control flow. The VM bounds stack, heap, and
per-tick work, then reports budget exhaustion without partially applying a
behavior's commands. Arbitrary JavaScript evaluation, dynamic imports, and native
plugin execution are outside this profile. See [scripting](scripting.md).

A separate watchdog terminates a nonresponsive worker and restores accepted
state if the VM or a host binding has a defect. Fuel bounds VM work; it does not
promise hard wall-clock CPU scheduling or GPU preemption on a creator's device.
Trusted engine code and any later native plugin profile need their own admission
and isolation policies and cannot inherit the bytecode VM's claims.

Only trusted render code owns the renderer's device and command submission.
User shaders pass parsing, interface checks, binding restrictions, static
complexity limits, compilation, and a staged warm-up before replacing the last
working pipeline. Static limits cannot prove a shader's execution time. GPU
timeouts and device loss trigger a degraded recovery path; cloud validation of
untrusted shaders uses disposable GPU workers with process/machine isolation.
See [rendering](rendering.md) and [performance](performance.md).

Enforce byte, geometry, texture, sound, entity, script-message, simulation-work,
network, compiler-time, and spending limits independently. Check limits before
allocating or decompressing. Canceling a client request does not establish that
a remote paid job stopped; the service records and terminates or settles it.

## Imports and the software supply chain

**SEC-005.** Import workers have no ambient network access or production
credentials. Native and server import jobs process allowlisted formats in
isolated OS processes with memory, CPU, file-count, expanded-size, and time
limits. Supported browser-only imports use bounded Rust/Wasm decoders in
dedicated workers on an isolated import origin, with supplied input buffers,
bounded output, and no editor capability. The containing page's CSP denies
ambient network requests. Unknown formats require the companion or service;
they never fall back to executing imported JavaScript. Worker termination remains
a recovery backstop, not a guaranteed memory or wall-time quota. Reject archive traversal,
symlink escapes, decompression bombs, malformed buffers, and external URI loads.
External resources require a separate explicit fetch step that blocks private
network destinations, metadata endpoints, and redirect-based bypasses.

Pin compiler tools, package dependencies, and converter versions by digest.
Record input digests, toolchain identity, declared dependencies, generated
outputs, and build evidence. SLSA provides a vocabulary for verifiable build
provenance; adopting its format does not establish a particular assurance level.
[SLSA provenance](https://slsa.dev/spec/v1.2/provenance).

An asset record stores source, author, license evidence, acquisition reference,
attribution, and redistribution constraints. Unknown rights block public
publication until resolved. Purchased vendor files remain in authorized storage,
not this source repository or public test fixtures. A hash match neither grants
a license nor permits cross-tenant asset discovery. See
[asset compilation](asset-compilation.md).

## Incident and abuse response

**SEC-006.** Provide revocation for sessions, capability grants, workers, and
publisher keys; suspend a harmful public channel without deleting evidence.
Rate-limit admission before expensive processing. Maintain creator reports,
appeals, retention limits, and scoped operator access. Strip sensitive content
from diagnostics and require explicit consent before capturing source or world
contents. The security gate includes cross-project token reuse, malicious import
corpora, frame navigation, spoofed messages, script infinite loops, expensive
shaders, stale permissions, and prompt injection. Findings block the affected
capability until verified fixed; a signed release never bypasses these checks.
