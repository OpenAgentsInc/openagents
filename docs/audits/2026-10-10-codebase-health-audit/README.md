# Codebase health audit: 2026-10-10

The OpenAgents monorepo is in fair health, graded C overall. Code inside individual functions is usually careful: production code outside tests has few panics, most `unsafe` blocks are small and annotated, many security boundaries already fail closed, and the root workspace has about 15.9k tests. The problems are structural. The repo grew from 10 crates to 184 in about three weeks, and the work to consolidate shared code, enforce checks and remove leftovers did not keep pace. Of the 34 sections, 5 grade B, 25 grade C and 4 grade D (all four D grades are in the psionic import). The audit has 709 verified findings: 1 critical, 57 high, 332 medium and 319 low.

Seven themes recur across sections:

1. **Nothing is enforced automatically.** There is no CI. The pre-commit hook is opt-in and only checks file size. The scoped gate passes invalid `-p` arguments for the excluded psionic and mobile workspaces, never includes dependent crates, and skips crates that compile top-level files. The dependency gate already fails with 29+ errors and stops passing entirely on 2026-10-20 when the `paste` advisory waiver expires (X-TEST-01, X-TEST-02, X-TEST-03, OPS-02, OPS-04, X-DEP-01, X-DEP-06, X-LINT-01, X-LINT-12).
2. **The psionic import is mostly dead weight on the serving path.** `psionic-serve` links about 630k–1M lines of training, eval and Tassadar research code to use a few dozen symbols. Most fixture paths in those crates point at files that were never imported, so hundreds of tests fail by construction, and nothing builds or tests `crates/psionic` (PS1-01, PS1-02, PS2-01, PS3-01, PS3-02, PS4-01, PS4-02, X-DEAD-01, X-DEAD-02, X-SIZE-09).
3. **Hub crates and giant files.** `coder` (262k lines, 24 dependents), `gym` (110k), `gateway` (72k), `tenancy` (39k), `verse` (~60 dependencies), `nostr` (85k, ~60 dependents) and `openagents-cli` each mix several products. The production web and gateway servers link all of `coder` for a few domain modules. 89 files exceed 3k lines and 353 functions exceed 300 lines (CD-03, GY-03, GW-02, PAY-06, VE-02, NO-02, CLI-04, X-DEP-02, X-SIZE-01, X-SIZE-03).
4. **Shared infrastructure is copied instead of shared, and the copies drift.** Atomic and private file writes (20+ copies with different durability and permissions), canonical-JSON digests (16 private copies outside psionic, hundreds inside), git spawning, NIP-42 handshakes, credential scrubbing, time and hex helpers. Several copies have already lost hardening the original had (CX-11, CS-08, CE-01, PAY-08, X-DUP-03, X-DUP-07, X-DUP-17, X-CONC-08, AGT-02, CD-07, CX-12).
5. **Trust checks at input boundaries have gaps on live paths.** `openagents mcp serve` exposes wallet spend to MCP callers, the Nostr relay trusts the client-controlled leftmost `X-Forwarded-For`, openagents-web grants local privilege from the `Host` header, the Coder self-updater on Linux and Windows trusts an unsigned checksum file, Pylon's mainnet spend ceiling fails open, and the pay front runs a hand-rolled HTTP parser (CLI-01, X-SEC-01, X-SEC-02, CX-04, AGT-01, PAY-02, NO-01, VE-01).
6. **Failures are discarded or flattened.** About 1,900 `let _ =` discards (including budget metering, receipts and journal writes), about 2,476 public functions returning `Result<_, String>`, three different mutex-poisoning policies, no structured logging in server crates, no graceful shutdown in the web server or gateway, and a wallet path that tells the user "Nothing was paid" when the outcome is unknown (X-ERR-01, X-ERR-02, X-ERR-06, X-ERR-08, GW-01, CD-06, WEB-01, GW-11).
7. **Repo bloat and stale policy records.** HEAD tracks 1.82 GB with an 8.2 GiB pack, mostly bench output and repinned 10–28 MB `.vtp` packs that the size guard exempts. 603 `.pyc` files are tracked and `crates/psionic/target` (448 MB) is not ignored. INVARIANTS.md (378 KB) cites tests that no longer exist, and the workspace guide routes agents to paths that do not exist (OPS-01, GY-01, VW-01, OPS-06, X-DEAD-08, X-ROUTE-06, X-DOC-01, X-DOC-04). Separately, keyword matching still routes some user intent, including a crew-agent path that runs a real merge, against the workspace semantic-routing rule (X-ROUTE-01, X-ROUTE-02, CD-01, CLI-05).

Bottom line: the codebase is not in crisis, but most of its safety comes from careful authors, not from checks. The cheapest high-value work is a short list of security and money-path fixes (Phase 0) and making the existing gates actually run and pass (Phase 1). After that, the biggest payoff comes from removing the psionic research code from the serving build and replacing the copied infrastructure helpers with one shared version each. Splitting the hub crates and giant files is worthwhile but should follow, because a lot of it becomes mechanical once the shared helpers and gates exist.

## Scope and method

- **Snapshot:** commit `3168c986aa11e18a8bd30f52c270f609e49b3815`, audited 2026-10-10.
- **Size:** about 3.6M lines of source across 184 crates, including about 1.2M lines in `crates/psionic`. There are three Cargo workspaces: the root, `crates/psionic` and `crates/openagents-mobile` (plus the small standalone `mc-bridge`).
- **Sections:** 34 in total, 23 area sections (one per group of crates) and 11 cross-cutting lenses (dependencies, error handling, duplication, size, tests and CI, concurrency, lints and build config, dead code, security, workspace policy, docs drift). Missing sections: none.
- **Process:** each section was reviewed, then each candidate finding went through adversarial verification against the source, then the section was written up. Claims the verifier refuted are recorded in a "Refuted during verification" list in each section, and severities or counts the verifier corrected are used in their corrected form.
- **Static only:** no builds, tests or benchmarks were run. Counts come from source inspection, `git` and file listings. Findings that depend on runtime behavior say so.
- **Totals:** 709 verified findings (1 critical, 57 high, 332 medium, 319 low).

Finding IDs use the section code as a prefix (for example `CD-07` or `X-SEC-01`). Each ID below links to its section file, where the finding has its location, failure scenario and step-by-step fix.
