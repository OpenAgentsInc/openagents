## How to use this register

- Each row is one finding that was checked during verification. Findings that were refuted are not listed here; each section file says what it dropped.
- IDs are stable. Section codes (for example `CD`, `X-SEC`) match the section files and do not change if rows are reordered.
- The ID links to the section file. The evidence, the full multi-step action, and how to verify the fix are there; this table keeps one condensed sentence per action.
- To check a finding off, put its ID in the commit message or issue title (for example `Fix X-SEC-01: ...`), so `git log --grep` finds it later.
- Effort: S = under a day, M = a few days, L = a week or more, XL = a multi-week or cross-crate project.
- Several findings describe the same problem from different sections (for example the untracked `crates/psionic/target`, bench bloat, and `INVARIANTS.md` citations). Fix once and reference every matching ID.
