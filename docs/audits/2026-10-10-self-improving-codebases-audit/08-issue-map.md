# Open and recently closed work

The issue snapshot contains **47 open issues** and **917 issues closed since 2026-10-03 00:00 UTC**, collected on October 10. An explicit closed-date search with a 2,000-result limit returned the same 917 issues as the original listing. The [inventory](evidence/issues.csv) records every issue's title, state, URL, dates, labels and body hash. Issue bodies were screened for relevance; relevant bodies and selected closing discussions informed the chapters. Not every comment on every issue was retrieved.

GitHub status describes implementation workflow. It is not a substitute for source inspection, checks, a deployed version, a paid customer or a measured recursive gain. This repository intentionally closes code-complete work while keeping owner-only activation in [NEEDS_OWNER.md](../../../NEEDS_OWNER.md). That is a useful distinction, not evidence that the issue was closed incorrectly.

## Missing work visible from the join

The open inventory covers many components but does not by itself provide one owner and acceptance packet for the complete S1–S3 loop. The most consequential unjoined work is the verifier repair, complete attempt/cost adapter, cross-feed partition enforcement, gated ranker activation, protected two-cycle study, purpose-specific customer data admission, and post-acceptance regression tracking.

Use the [action register](09-roadmap-and-acceptance.md) to scope those gaps. Before opening issues, inspect current main, check the existing issue and claim state, and account for changes since this snapshot. Do not open 709 duplicate health issues, reopen already shipped work solely for owner activation, or make every open payment/client issue a blocker for this product.
