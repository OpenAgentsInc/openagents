# Coder 1.0.0 big-bang release: agent brief (owner, 2026-10-16, binding)

Paste this to every agent working the release. For each issue's status and
which agent takes it, read the
[master delegation](2026-10-16-master-delegation.md).

## The decision

- **The Coder binary freeze is lifted** (owner, 2026-10-16). The rules in
  [`docs/coder/1.0-freeze.md`](../coder/1.0-freeze.md) no longer apply.
- **The release published on 2026-10-15 (`coder-v1.0.0`, commit
  `3230ded511`) is withdrawn.** Nobody uses it: each GitHub asset shows 0
  downloads, and launch moved to **Monday 2026-10-19**.
- **We ship one big-bang Coder 1.0.0 on Monday**, built from `main`. It
  includes the full OpenAgents SDK integration and is aligned with the
  OpenAgents desktop and mobile apps (the Zeron fork in `apps/openagents/`).
- **Every open issue closes in the next 24 hours**, by Saturday
  2026-10-17, 21:00 local. That's 54 issues as of this writing. Then the
  release gate runs through Sunday, and 1.0.0 publishes on Monday.

## What changes for you

1. **Binary work is in scope.** Build the feature in `coder`, `openagents`,
   `microcoder`, or `coder-boundary` when that's the right place. Don't route
   around the binary any more.
   - Drop "1.0-compatible" workarounds that exist only because of the
     freeze. Build the real thing instead: the Labs loopback bridge (#11885),
     asking Foreman through `chat send` only (#11934), and the loopback mode
     in #11880.
   - If an issue body says "waits for the next release" or "activation:
     owner lifts the freeze", that condition is met. Do the work.
2. **[`docs/coder/next-release.md`](../coder/next-release.md) is now 1.0.0
   scope.** Every row ships in Monday's build, starting with the security fix
   #11771.
3. **Server compatibility.** Only the withdrawn build calls the
   compatibility surface listed in the freeze doc, and nobody runs that
   build. You may change those routes when the new client changes with them.
   Two rules still hold:
   - Old addresses (`openagents.com/v1`, `openagents.com/api/v1`) keep
     answering. Keeping them costs nothing, and the apps and docs still
     reach them.
   - A route change lands in the same push as the client change that
     uses it, so `main` always builds a working pair.
4. **From Monday's publish, the new 1.0.0 is the compatibility
   baseline.** Server changes after launch are additive for the routes it
   calls. No new binary freeze applies unless the owner says so.
5. **The usual rules stand:** claim the issue first (`openagents issue claim
   N`, `scripts/dev/issue-board.sh claim N`), work in your own worktree,
   run `cargo test -p` for the crates you changed, run `cargo fmt` on your
   files, push to `main`, and close the issue with
   `scripts/dev/issue-board.sh close N "..."`. Never test on the owner's
   account.
6. **Close on code, not on live checks** (owner, 2026-10-16). An issue closes
   when its code is on `main` and its own checks pass. Deploys, live checks,
   and test-account end-to-end runs go to "After-close checks" in the
   [master delegation](2026-10-16-master-delegation.md), and the deploy lane
   runs them. A defect found there becomes a new issue.

## Aligning the terminal with the desktop and mobile apps

The merge audit
([`2026-10-16-coder-desktop-monorepo-merge.md`](2026-10-16-coder-desktop-monorepo-merge.md))
calls the terminal "unchanged", sharing only domain crates. For 1.0.0, that
changes: a Coder chat is a normal OpenAgents chat. Concretely:

- **One chat list.** A terminal chat appears in the desktop and phone apps
  and on openagents.com. It can be resumed there, and "where it runs" is a
  property of the chat (#11894, #11896, #11897, #11898).
- **One session path.** Live sessions are Loro documents in `coder-sync`
  rooms. NIP-HOST grants decide which device joins which room (#11854). Don't
  add a second session path from the terminal.
- **One harness layer.** `apps/openagents/crates/harness` and
  `crates/coder-delegate` both drive Claude Code, Codex, and the other
  engines. The agent that takes #11894 decides in its first hour which of
  them the other calls. It records the decision in the merge audit and
  in a comment on #11896. Everyone else builds on that decision. Never keep
  two drivers for the same engine.
- **One SDK.** Coder reaches the account, history, chats, computers, Labs,
  and Agent Lab through `crates/openagents-sdk`, the same client the apps
  use (#11823, #11876). Don't make direct HTTP calls from Coder for anything
  the SDK covers.
- **One card layer.** Lab, approval, and other cards are Rust Native views
  (#11877, #11883, #11884). Coder's terminal renders them through its
  adapter. Don't write the card again for the terminal.
- **Two workspaces.** `apps/openagents/` is its own Cargo workspace (Rust
  1.98.1). A domain crate that both use must build in both.

## Re-cutting 1.0.0

`scripts/release/coder.sh` refuses to republish a version: it stops when
`SHA256SUMS-coder-1.0.0` exists, and it uploads with `--no-clobber`. Withdraw
the old build first. The release agent does this on Monday, after the gate is
green and before the publish:

1. In `gs://openagentsgemini-cli-releases/coder/`, move every
   `coder-1.0.0*` and `SHA256SUMS-coder-1.0.0` object to
   `withdrawn/2026-10-15/`. Keep them, don't delete them.
2. Point `coder.stable` at the last rc while the slot is empty, so
   installers never see a missing version.
3. Delete the GitHub release `coder-v1.0.0`. Rename its tag to
   `coder-v1.0.0-withdrawn` (push the new tag, then delete the old one), so
   commit `3230ded511` stays findable.
4. Run `scripts/release/versions.py` and `scripts/release/coder.sh --version
   1.0.0 --publish --channel stable --publish-installers` from the green
   commit. Then tag `coder-v1.0.0` on that commit and create the GitHub
   release.
5. The archives carry GCS's default `public, max-age=3600`, so a cache may
   serve the old bytes for up to an hour. Check each archive against the new
   `SHA256SUMS-coder-1.0.0` through `?nocache=1` and the public URL. Hold
   the announcement until the public URL matches.
6. Any copy of the old 1.0.0 (staging and production smoke homes, team
   machines) won't update itself, because the updater sees the same version.
   Reinstall those with the public installer.
