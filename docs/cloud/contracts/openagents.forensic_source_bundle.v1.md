# OpenAgents forensic source bundle v1

This contract materializes an immutable, private source snapshot for a forensic
run without giving the analysis guest an SCM credential, provider credential,
external IP, or Internet route. The production API is the authenticated,
default-off `POST /api/forensics/source-bundles` endpoint.

## Authority boundary

The source materializer accepts an immutable GitHub repository, commit, and Git
tree pin. An owner-scoped control process, not the caller or guest, resolves
that pin through the GitHub commit, recursive-tree, and archive APIs. It binds:

- every `.gitmodules` declaration to its observed gitlink, repository URL, and
  exact commit/tree, including explicit exclusions and stale declarations;
- selected source bytes to their recomputed SHA-256 digest; and
- generated bytes to explicit parameters, the materialized source commit, an
  admitted generator implementation digest, and exact toolchain pins.

Archive transport is streamed under hard response, expansion, entry-count, and
per-file limits. Every extracted regular file is verified against its Git blob
object ID from the exact recursive tree; the tarball is not an independent
source of truth.

Source selection rejects duplicate repository identities and is bounded to
4,000 entries, 10 MiB of selected file bytes, and a 16 MiB canonical bundle.

SCM access remains outside the guest. The controller obtains the owner's GitHub
identity token from server-side authority and measures its own network bytes;
neither the token nor arbitrary staged bytes are accepted in the request. An
incomplete recursive tree, mismatched commit/tree, undeclared gitlink, URL
drift, archive parse failure, or byte drift fails closed.

## Materialization

`ForensicSourceMaterializationRequest` binds the target snapshot, declared
submodule pins, expected paths, manifest digest, optional expected source
digest, retention deadline, sandbox generations, and exact
`forensic_source_delivery` capability. Decoding is strict and excess fields
fail closed.

Every expected path is classified as `target`, `dependency`, `generated`,
`excluded`, or `oversized`. Required absent inputs make the coverage manifest
`incomplete`. In that state no source bundle is stored or delivered, the
evidence receipt is `inconclusive`, and durable authority blocks dispatch.

For present inputs, materialization checks:

- target commit and Git tree equality;
- exact submodule declaration, URL, gitlink commit, and repository tree;
- generated-input parameter/source binding, generator implementation,
  toolchain, and byte equality; and
- canonical manifest and optional final bundle digest equality.

Entries and pins are sorted before canonical JSON and SHA-256 calculation, so
identical inputs produce identical source digests. The checked-in Coldcard
manifest pins the real vulnerable commit and Git tree, all six observed
gitlinks, and the stale bootloader declaration. Its materialized analysis
inputs include `external/libngu`, `external/micropython`,
`external/ckcc-protocol`, and `external/mpy-qr`; both GPU gitlinks are verified
before their explicit exclusion.

## Private delivery

The canonical bundle is stored in the private artifacts bucket as an
operator-only, no-store, authority-specific object whose bytes still hash to
the requested content digest. Separate authorities never share a deletable
object. Delivery resolves the exact ready
managed-sandbox generation and active, unexpired
`forensic_source_delivery` capability. It obtains a fresh native isolation
probe for that generation, then invokes the dedicated source-install operation;
generic file writes cannot install a forensic bundle.

The guest operation checks its byte ceiling and secret scan, rejects symlink
traversal, verifies the bundle and every entry digest, writes beneath
`workspace/source/`, verifies the post-copy digest, makes the source tree
read-only, and creates a separate writable `workspace/scratch/`.

The materialization receipt binds owner, tenant, work unit, sandbox and
generations, capability, bundle, coverage, manifest, retention, artifact,
source digest, SCM receipts, and delivery receipt. Zero external IP, deny-all
egress, and no guest credential come from the native generation probe; they are
not API-assigned receipt literals.

## Dispatch authority

Successful materialization persists an owner-scoped authority that binds the
run, work unit, sandbox and attachment/resource generations, bundle and source
digests, coverage ref and digest, receipt, capability, and retention deadline.
The prompt dispatch path acquires a compare-and-set lease, verifies the private
artifact and exact guest source proof, and holds the lease through broker/model
dispatch. Cleanup cannot race that call. Missing, incomplete, cleaned, expired,
or mismatched authority is a hard refusal. Controller-observed time, not caller
timestamps, governs capability and retention decisions.

## Cleanup

Materialization stores pending recovery authority before artifact or guest
mutation. Explicit cleanup, failed-attempt recovery, and the retention-expiry
sweep acquire their own compare-and-set lease, delete the private
authority-specific artifact, and verify absence. The dedicated guest removal
operation deletes and reads back source and scratch absence for the same
generation, and
the durable authority records and reads back capability revocation. The cleanup
receipt records each proof separately. Any missing proof returns
`recovery_required`; it is never treated as success and remains retryable.
Guest install/readback rejects unmanifested files, directories, symlinks, and
special nodes. Exact installs and operation scratch directories are restart-safe
after a controller or guest-helper crash.
