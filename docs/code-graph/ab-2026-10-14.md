# Code Graph A/B, 2026-10-14 (#11622)

Does Coder spend fewer tokens when it has the `graph_*` tools? We measured
two kinds of task on real code, with and without the tools, on the same
model and the same commit.

**Result.**

- **Impact questions: the graph helps.** "Every caller of `X` must change;
  find them." With the tools, Coder used **63% fewer tokens in total**
  (495,336 → 185,413), a median of 17.1k instead of 34.7k per trial, and
  read a median of **1 file instead of 6**. Both arms were correct in all
  10 trials. The cost fell from $0.56 to $0.31.
- **Localization from an issue: no measurable effect.** "Here is an issue;
  which files does the fix change?" On the 6 issues where every trial
  finished, the two arms used the same tokens (14.63M against 14.67M), read
  the same number of files (113 each), and were equally often correct (12
  of 12 each). The graph was called in 12 of 16 trials, but the issue text
  names behaviour, not symbols, so Coder still found the files with Grep
  and Read.
- **Where it did not help.** On #10368 all four trials (both arms) hit the
  15-minute limit without an answer, and on #10078 one trial in each arm
  did. The graph made no difference to either.

## Setup

| | |
| --- | --- |
| Harness | [`scripts/bench/code-graph-ab/ab.py`](../../scripts/bench/code-graph-ab/ab.py) |
| Agent | Coder's own loop, headless: `openagents coder chat --mode coder --in-place --json`, `CODER_NO_HARNESS=1` |
| Model | `google/gemini-4-argon`, every call, through Google's Gemini API with the company Gemini key (no OpenAgents account signed in, so no gateway door) |
| Arms | **A**: `OPENAGENTS_CODE_GRAPH=0`. **B**: `OPENAGENTS_CODE_GRAPH=1`: the six `graph_*` tools and their guidance. Nothing else differs. |
| Isolation | One shallow clone per task holding only the fix's parent and 50 commits of history (no later commit, so no arm can see the fix), a fresh worktree and a fresh `HOME` per trial, no browser |
| Graph | Built once per base before the trials, standing in for the published graph: 0.9-6.5 s per commit (median 1.6 s) |
| Limit | 15 minutes per trial; 4 trials at a time |
| Raw data | [ab-2026-10-14-trials.json](ab-2026-10-14-trials.json) (52 trials) |

**Tokens** are the sum over the trial's model calls of prompt and
completion tokens, from Coder's ATIF trajectory. Most of a long trial's
prompt tokens are the same context sent again; Gemini served about 90% of
them from its cache, which is why cost moves less than tokens. **Cost** is
Argon's list price ($2 input, $0.10 cached input, $10 output per million).
**Files read** counts distinct files opened with `Read` or with `cat`,
`sed`, `head` or `tail` in `Run`.

### Localization tasks

Eight closed issues from the briefed-agent bench (`scripts/bench/briefed-ab/tasks`),
each replayed at its fix's parent. Prompt: the issue's title and body, then
"Do not edit any files and do not run cargo. Find where in the code this has
to change. Reply with the existing source files a fix would change, most
important first (at most 6)". The truth is the fix's modified `.rs` files
that are not tests. A trial is correct when its answer names at least half
of them. **Tokens to first fix file** is the running total when the agent
first opened a file the fix changed.

### Impact tasks

Five functions in `crates/coder-new` at `d0dc736500`, each with 3-6 calling
files. Prompt: "`X` (defined in `F`) is about to gain a new required
parameter. Find every place that calls it directly", answered as
`path:line - calling function` rows. The truth is the files with call sites,
found with `git grep` and checked by hand, not with the graph. One of the
five, `resolve_composer_rails`, has a namesake in `crates/coder-ui`, so a
name-only search finds wrong callers. A trial is correct only when it
names every calling file.

The lower median "tokens to first fix file" for B is not a real effect: it
comes from #10078 and #10281, while B was slower to reach a fix file on
#10188, #10248, #10256 and #10304. Two trials per arm cannot separate a
difference this small from the run-to-run spread, which is large (on
#10281, the A arm's two trials used 342k and 907k tokens).

## What we learned

- **Use it for structure, not for search.** The graph answers "who calls
  this" in one call where Grep and Read take several, and the saving grows
  with the number of calling files. It does not turn an issue's prose into
  file names; that is file finding's job (#11210).
- **The rule matters.** In the pilot, with a softer first wording ("for
  structure and impact questions, query the graph"), the B trial made no
  graph call at all. The guidance now starts "Query the code graph before
  opening source" and says to begin with `graph_symbol` when a task names
  a function, type, module or file. After that change, B called the graph
  in 12 of 16 localization trials and all 10 impact trials.
- **Localization trials are long and noisy.** Most of their tokens are
  context sent again on each step. A next experiment should hand B the
  briefed agent's file list (#11211) and ask for the edit itself, so the
  graph is used where the edit's reach is the question.

## Not measured

- Edits and their correctness: the tasks ask for an answer, not a change.
- Other languages: the graph covers Rust only.
- A model other than Argon, and more than 2 trials per arm.
- The published-branch path's fetch time: every trial read a graph built
  before the trials, as a checkout would after fetching the branch.
