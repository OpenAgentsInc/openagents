# Coder 1.0 binary freeze (2026-10-15 to 2026-10-16, lifted)

> **Lifted by the owner on 2026-10-16.** The rules below no longer apply.
> The 2026-10-15 build is withdrawn, and one Coder 1.0.0 ships on Monday
> 2026-10-19. Read
> [the big-bang release brief](../audits/2026-10-16-coder-1.0-big-bang.md).
> This page is kept as a record.

**The Coder programs are frozen at 1.0.0.** Until the owner lifts this, we
make 1.0 better from the server, the website, the docs and the apps, not
with a new binary.

- **Frozen:** `coder`, `openagents`, `microcoder` and `coder-boundary`
  1.0.0. Tag `coder-v1.0.0`, commit `3230ded511`. Published on all 7
  platforms through the installers, `/download` and the
  [GitHub release](https://github.com/OpenAgentsInc/openagents/releases/tag/coder-v1.0.0).
- **Why:** we're about to announce 1.0. Everyone who installs it in the next
  weeks gets exactly that build. Improvements have to reach those people
  without asking them to update, and nothing we deploy may break them.

## The rules

1. **No new Coder release** (no rc, no 1.0.1) unless the owner asks for one.
   The `coder.stable` and `coder.rc` channel files stay at `1.0.0`.
2. **Don't land work whose value needs a new binary.**
   - If a change only reaches people through a new Coder build, it waits:
     add it to [next-release.md](next-release.md) with its issue, and leave
     the issue open with a comment saying it waits for the next release.
   - **Exception:** a security fix. Tell the owner the same day; they decide
     whether it ships.
3. **Everything Coder 1.0.0 talks to stays compatible.** Server changes are
   additive only:
   - **Routes:** never remove or rename a route 1.0.0 calls, or a field it
     reads (list below). Add fields freely.
   - **Errors:** keep the error codes it acts on (`quota_exhausted`,
     `invite_only`, `signup_disabled` and the like).
   - **Old addresses:** they keep answering. `https://openagents.com/v1` and
     `https://openagents.com/api/v1` are deprecated in favour of
     `https://api.openagents.com/v1`, but 1.0.0 still calls both (one
     `openagents.com/v1` call, and the Decisions API at
     `openagents.com/api/v1/decisions`), so neither goes away while 1.0 is
     current.
   - **Models:** a model id a 1.0.0 picker has cached (its `gateway-model.json`
     pick) keeps working. Retire a model by aliasing it to its replacement,
     never by returning an error. `openagents/auto` is always there.
   - **Decisions:** the `/v1/decisions` request and answer shapes stay.
   - **Installers:** `install.sh` and `install.ps1` keep installing the
     1.0.0 files. They may get clearer messages, never a different build.
4. **Test against the real 1.0.0.** Before deploying a change to any route in
   the list below, run the released binary against staging:
   - install it into a scratch home with the public installer;
   - run `coder --version`, `openagents coder status`, and the route's command.
     The frozen 1.0.0 terminal UI does not expose `coder doctor`.

   The staging and production smokes already install and run `coder
   --version`; keep them green.
5. **The apps are not frozen.** The website, OpenAgents mobile and
   OpenAgents desktop can change, but they talk to the same server, so rule 3
   holds for them too. Desktop and TestFlight builds still wait until the
   owner asks (desktop development mode).

## What Coder 1.0.0 gets from our servers

These are the levers that improve 1.0 without a new binary. Every one of
them is served from code we deploy:

| What 1.0.0 does | It calls | We can improve, with no new binary |
| --- | --- | --- |
| `/models` lists models; picking one sends turns through our gateway | `GET /v1/models`, `/v1/responses`, `/v1/chat/completions`, `/v1/messages` | Which models are listed, their names, speed and prices, and the gateway's fallbacks |
| Auto (`openagents/auto`) picks a model per turn | the gateway's router | Routing quality: Clef first, better cost per accepted change |
| Guards and second looks ask a yes/no question | the Decisions API (`openagents.com/api/v1/decisions`, Clef first) | Decision accuracy and speed, with no client change |
| Prices and balance | `/v1/rates`, `/v1/balance`, `/v1/keys` | Pricing, free-tier limits, top-ups (Lightning via x402) |
| Paid plugins and x402 resources | `/v1/plugins/{id}/invoke`, x402 challenges | New plugins and resources, LND receive (#11762) |
| Cloud computers and Mac jobs | `/v1/computers`, `/v1/mac-jobs` | Boot time, capacity, images, Environments |
| Projects, sharing, files, Drive | `/v1/projects/*`, `/v1/files/*`, `/v1/threads/*`, `/v1/connections/google/drive` | Web screens for projects and invites, sources, search |
| `coder doctor` | `/healthz`, `/v1/models`, `/v1/balance` | Clearer answers when something's wrong |
| Docs and agents | `/docs`, `/mcp/docs`, `llms.txt`, the agent card | Everything |

## Opportunities: making 1.0 more powerful now

In rough order of value to someone who installs 1.0 this week:

1. **A better Auto.** Every 1.0 turn on Auto goes through our router and
   Decisions API. Improving Clef's routing and judgments, and adding a
   cheaper strong model to the list, lowers cost and raises the accept rate
   for every installed copy at once.
   - Measure it with the brief + verify harness and the outcome ledger
     ([outcomes](../research/outcomes/README.md)).
2. **Open the door.** Open GitHub login (done 2026-10-15, being deployed),
   a smooth first run on the website, and agent self-signup on the one API
   address. More people reach 1.0 with no binary change.
3. **The model list.** Curate `/v1/models`: clear names, a fast cheap
   choice, a strongest choice, honest prices from `/v1/rates`. The picker
   shows whatever we serve.
4. **The website as 1.0's other half.** Everything the CLI can do with
   projects (sharing by GitHub username, sources, files, Drive) gets a
   matching web screen. People manage it in the browser and use it from
   Coder.
5. **Cloud computers.** `coder remote delegate --on boat` and Mac jobs call
   our server. Faster first turns (today about 77 s; the SPACE spike #11728
   aims under 2 s to create) are a pure server win.
6. **Paying with Bitcoin.** Top-ups and paid plugins over x402 work from
   1.0's `openagents x402` commands. Moving receive to our own LND node
   (once funded) is server-side.
7. **Plugins and paid resources.** New server-side plugins and x402
   resources are usable from 1.0 the day they're deployed.
8. **The outcome ledger and `/efficiency`.** Record every task, attempt and
   cost on the server, and publish our own cost per accepted change.
9. **Docs, blog and agent docs.** Every how-to with its link or one command;
   tutorials for the things 1.0 already does that people don't know about
   (headless `openagents coder chat`, `--mode opencode`, worktrees, sharing).
10. **Mobile and desktop.** Improve them against the same server: chats,
    projects, approvals (Y/N holds) from the phone. They ship when the owner
    asks for a build.
11. **Listening.** Server-side counts of the errors 1.0 hits (refusals,
    timeouts, which harness failed) to build the list for the next release.
    Counts only, no request text.

## Not now

- Coder features, terminal UI changes, new harnesses, new CLI flags: they
  go in [next-release.md](next-release.md).
- Removing or renaming anything 1.0.0 uses, including old API addresses and
  model ids.
- Moving the update channel off 1.0.0.

## Lifting the freeze

The owner lifts it, by saying so, when they want the next Coder release.
Then the next-release list becomes that release's scope, and it goes through
the usual release gate.
