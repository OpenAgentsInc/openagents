# Coder v0.2.0 scope: local (Ollama) lane

Date: 2026-08-28
Status: scope proposal. Not implemented. Companion to
`docs/2026-08-28-qwen38-and-ollama-audit.md`, which carries the evidence and
line references this document leans on.

Owner framing that produced this document: the TypeScript coder had Ollama
support; the Rust port must carry it into coder v0.2.0. The audit's finding
is the headline: **the Rust port already has the support** — lane, streaming,
tool loop, budget reporting, images, tests, benchmark adapter. What v0.2.0
should carry is the missing measurement, two behavior decisions the port left
implicit, and the request controls a local lane needs to be tunable.

---

## 1. What already works (no work needed)

- `--model ollama:<name>`, `--lane local`, and `--local` all select
  `Lane::Local` (`crates/openagents-cli/src/runtime.rs:383,406-408`;
  `cli.rs:672-690`).
- Model resolution against the local server: exact name, then family prefix
  (`qwen3.8` → `qwen3.8:27b-mtp-q8_0`), then most-recently-modified
  (`runtime.rs:3147-3223`).
- Full harness loop on the local lane: NDJSON streaming, `thinking` as
  reasoning, parallel tool batches, budget notices, budget-report ending,
  images (`runtime.rs:3225-3486`, `absorb_ollama` `:3689`,
  `ollama_message` `:3919`).
- No thread, no grant, no metered spend; transcript stays local by default.
- Stub-server test section (`tests/runtime_test.rs:878-1120`), coder-api
  `lane:"local"` (`coder-api/src/routes.rs:166-178`), bench adapter mapping
  `ollama/<model>` (`bench/adapters/openagents_coder.py:97-107`).

Nothing in this document re-proposes any of that.

## 2. The v0.2.0 list

Each item names its files and its acceptance gate. Order is by independence;
V1 can run while V2–V4 are coded.

### V1 — a graded local `tb2-cross-section` row for Qwen 3.8

The suite's local-lane invocation is already written down
(`bench/suites/tb2-cross-section.md`, the `ollama/qwen3.8:27b-mtp-q8_0`
block). The run has simply never been recorded. Hosted comparison rows on the
board: `gpt-5.6-luna` 9/12 (75%), `glm-5.3-flash` 7/12 (58.3%). This row is
what puts the local Qwen 3.8 lane on the same board.

- Files: `bench-results/tb2-cross-section.jsonl` (append), `bench-results/README.md` (table row + note).
- Run shape: the documented Harbor invocation, `--n-concurrent 1` (the model owns the cores), real `OPENAGENTS_TOKEN`, one trial per task.
- Acceptance: a real run digest row lands in the store with `lane: local`, `models: ["qwen3.8:27b-mtp-q8_0"]`; README records wall clock honestly (the 2-task `tb2-quick` rows took ~1396 s; budget for a long cross-section run — overnight, not interactive).
- Gate rule from the store's own README applies: no seeded rows; whatever the run produces is what lands, including a bad one.

### V2 — Ollama request controls

Today the local lane sends no `options` and no `think`; everything is the
server's default. Two consequences the audit names: context can silently
resolve below what a long session needs, and a thinking-default model spends
context on scratch nobody asked for.

- `num_ctx`: new `--num-ctx <n>` coder flag (and `OPENAGENTS_OLLAMA_NUM_CTX` env, matching the `OPENAGENTS_OLLAMA_HOST` pattern at `runtime.rs:1110-1114`). Sent as `options.num_ctx` on every local chat call, including the budget-report round (`runtime.rs:3249-3260`, `step_local_report` `:3432`). Unset sends nothing — Ollama's default stays the default, and the flag is additive.
- `think`: local lane honors the existing `--reasoning` vocabulary. `minimal`/`low` → `"think": false`; `medium`/`high`/`max` → `"think": true`. Rationale: Qwen3.8 thinks by default (psionic `docs/qwen38/MODEL_FACTS.md`); a coder harness that asks for low effort should not pay a thinking budget. This also revives the TS-era intent (`8502aaa7d9`, "qwen starts thinking low").
- Files: `cli.rs` (flag), `coder/interactive.rs` (plumb), `runtime.rs` (`run_local_turn`, `step_local_report`), `tests/runtime_test.rs` (assert `options.num_ctx` and `think` reach the wire when set, and never when unset).
- Acceptance: stub-server tests pin all four cases; `--reasoning` on a local session no longer silently does nothing.

### V3 — decision D1: default-local probe (restore or retire)

The TS CLI probed `/api/tags` (300 ms) before the first prompt and answered
from the most recent local model when no model was named; the owner's commit
(`f296672580`) called that "the cheaper and more private default, and the one
a reader who installed Ollama meant". The Rust port defaults to `flash` and
requires an explicit local choice. The audit flags this as an undocumented
port divergence; this document makes it a decision with a recommendation.

- **Recommendation: restore the probe.** No `--lane`/`--model`/`--local`/`--offline` given → probe `GET /api/tags` with a 300 ms timeout via the existing `installed_local_models`; on a hit, open on `Lane::Local(<most recent>)`. On a miss or timeout, behave exactly as today (`flash`). Skip the probe entirely when anything was named or `--offline` was passed.
- The choice must be visible: welcome-card line "answering locally with `<model>` — `--lane flash` for hosted" (card lives in `coder/tui.rs:1128-1170`; mind the seven-line ceiling at `tui.rs:33`).
- Files: `coder/interactive.rs:65-70,1719` (lane resolution), `tui.rs` (card line), `tests/` (probe hit, probe miss, explicit-flag-skips-probe).
- Acceptance: a machine with Ollama running gets a local answer with no flags and is told so; a machine without gets today's behavior with no added latency beyond the bounded probe; every combination refuses nothing that works today.

### V4 — mid-stream cancellation on the local lane

`tool_cancellation` reaches tools and a cancelled batch ends the turn, but
the stream read itself has no cancellation path: a 30 GB Q8_0 model
mid-decode owns the turn until it finishes. The TS original aborted the fetch
on signal.

- Change: `run_local_turn`'s read loop (`runtime.rs:3286+`) selects over `bytes.next()` and the cancellation watch (`set_tool_cancellation`, `runtime.rs:1303`); on cancel, settle the turn as cancelled (`CANCELLED` path, `runtime.rs:791`), keep usage accumulated so far, do not record a failure.
- Files: `runtime.rs`, `tests/runtime_test.rs` (cancel mid-stream → turn settles cancelled, partial usage kept).
- Acceptance: cancelling a local turn during a long decode returns control immediately and the transcript records a cancellation, not a provider failure.

### V5 (stretch, only if the above land early) — naming hygiene

`max_steps` outcome vs `MAX_TOOL_STEPS` constant is the audit's §2.6.4; a
doc-comment cross-reference costs nothing. Not a release gate.

## 3. Explicitly NOT in v0.2.0

- **Psionic native wiring.** The `openagents inference` lifecycle plan
  (`docs/coder/2026-08-26-psionic-local-inference-integration-analysis.md`)
  stays its own track. Its premise that Psionic streams only after
  generation completes needs re-verification against the post-`1b539a48`
  tree before anyone builds on it.
- **A Qwen3.8-vs-Ollama matrix in Psionic** (R13). Separate repo, separate
  claim; until it exists, the comparison doc stays Qwen3.5-only and no
  beat-Ollama claim is made for 3.8 anywhere in this repo.
- Local-lane vision (the capability exists on the served artifact; no image
  path has been graded here), delegation-lane changes, coder-api catalog
  changes.

## 4. Release mechanics

- The manifest stays `0.1.0` (`crates/openagents-cli/Cargo.toml`); release
  versions are threaded at build time via `OPENAGENTS_CLI_RELEASE_VERSION`
  (`lib.rs:11`), non-release builds stay `0.0.0-dev`. `v0.2.0` ships as
  `ops/release-cli.sh --version 0.2.0(-rc.N)`; rc numbering follows the
  0.1.x pattern.
- Changelog: entries accumulate in `docs/changelog/UNRELEASED.md` per
  CLAIM-RELEASE; `pnpm changelog roll` cuts the dated file.
- The idle "New in v0.1.1" card (`coder/tui.rs:1162`) becomes a v0.2.0 card
  naming the local lane: local Ollama support called out in one line.
- Rust-side bumps for this scope are `Cargo.toml`-independent; no new
  external crates are required (the lane is hand-rolled HTTP today, and the
  controls above are request-body fields, not a client library).

## 5. Risks and notes

- **V1 wall clock.** The cross-section is 12 tasks; the local lane ran the
  2-task suite in ~23 minutes. Run it `--n-concurrent 1` on a box where
  nothing else wants the GPU/RAM (the 30 GB Q8_0 model is resident), and let
  it be slow. A row that lands is worth more than a row that is fast.
- **`think` mapping is a product choice**, not a protocol fact. If the owner
  wants Ollama's own default (thinking always on for capable models) instead
  of the reasoning-effort mapping, V2 shrinks to `num_ctx` only and the
  mapping paragraph is deleted — the flag must not half-exist.
- **The probe adds a failure surface** to first launch. The 300 ms timeout
  and the no-name-no-thread probe contract keep the miss path identical to
  today; the welcome card must say which model answered, never assume.
- The shared checkout at `~/work/openagents` sits mid-rebase with an
  unresolved `surfaces.rs` conflict from another session; landing happens in
  a separate worktree and merges into `main` by fast-forward only.
