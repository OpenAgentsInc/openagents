# Roadmap for a TypeSafe-native Coder

Status: target delivery plan. Coder specializes the
[general agent architecture](../../agents/README.md) for coding. The
[source proposal](thoughts-on-a-typesafe-coding-agent.md) motivates the
opportunities; [semantic programming and optimization](../../optimization/README.md)
define how to realize and improve them without fixing the system to one model.

The [single proposed-issues document](../../optimization/proposed-issues.md)
is the unfiled integration backlog. Its local IDs identify work, not promises
of implementation or authorization for paid experiments.

## Delivery strategy

Deliver a complete useful workflow around attributable evidence. Define each
AI operation's meaning and protected constraints before selecting its inference
strategy. A typed decision is useful where measured; deterministic behavior,
generation, or a bounded composition may better serve another operation.

Protect authority, mandatory instructions, disclosure, reservations, effect
confirmation, and independent acceptance in code. Permit measured variation
of model-specific wording, examples, parameters, routing, and bounded internal
decomposition. More model calls do not establish a better agent.

## Phase 0: establish a reliable consumer baseline

Define task and operation schemas, explicit refusal/unknown outcomes, a simple
working implementation, and a representative evaluation. Keep input, output,
model, policy, and receipt identities observable through one host path.

Separate semantic AI signatures from concrete implementations. Define the
complete functional closure and a materialization record that proves which
candidate was loaded at the declared assurance level. Do not introduce a
large search framework before one changed candidate can be executed and scored.

Acceptance requires deterministic authority checks, truthful partial/unknown
states, and a workload capable of detecting the intended improvement.

## Phase 1: preserve evidence and answer repository questions

Build task frames, immutable captures, source references, scope/retention rules,
and recipient-specific context manifests. Include mandatory instructions
independently of relevance ranking. Start with bounded deterministic retrieval
and explicit expansion.

Define the semantic task “supply sufficient evidence for this answer.” Compare
supported selectors under the same contract, including typed decisions and
joint selection. Evaluate citation quality, retrieval and selection recall,
missing constraints, expansion cost, and the complete answer.

Acceptance requires attributable results and a useful coding workflow. A
document/research fixture must exercise the same lifecycle without Git or shell.

## Phase 2: close the native coding loop

Add admitted read, search, edit, test, and review operations. Generation proposes
typed artifacts or arguments. The host validates them, checks authority and
source preconditions, dispatches under bounds, and records outcomes.

Separate execution completion, domain verification, and accepted integration.
Protect checkers and expected evidence from candidate changes. Unknown writes
remain unknown until reconciled; retries do not infer nonexecution from silence.

Optimization may improve proposals or bounded inference while leaving these
transitions fixed. Acceptance includes harmful errors and full-task outcomes,
not only successful tool calls.

## Phase 3: make context and operation selection economical

Implement progressive operation discovery, optional guidance, context
representations, supported model routing, and explicit cache observations.
Evaluate omitted useful operations, false activation, argument errors,
disclosure refusals, stale context, and complete cost/latency.

Connect a bounded DSPy/GEPA authoring bridge to the runtime and Gym. Freeze
search space, data rights, metrics, labels, grader, and acceptance policy.
Measure actual candidate bytes and all proposal/reflection/evaluation costs.
Use development selection followed by protected confirmation and separate
operator adoption.

Acceptance permits a no-win or inconclusive study. It does not require an
optimizer to beat a baseline; it requires honest execution and measurement.

## Phase 4: share context across parallel and background work

Use scoped immutable evidence, task dependencies, resource claims, fencing,
shared reservations, and explicit assimilation. A semantic independence
proposal cannot override a known write conflict. Final acceptance remains
independent of child success.

Background views and optimization require admitted subscriptions, recipients,
data use, and budgets. Findings identify freshness and intended use. They
cannot rewrite a running task, activate a candidate, or train on traces by
implication.

Acceptance includes foreground latency, total work, duplicate avoidance,
contention, stale findings, useful outcomes, and unknown effects.

## Phase 5: durable programs and a reusable ecosystem

Deliver typed program composition, bounded Wasm plugins, immutable extension
packages, scoped skills, local and relay discovery, durable jobs, and explicit
adoption/rollback. Installations are inert; updates affect new admissions.

Support semantic signatures and AI implementations as distinct components.
Broader strategy, composition, or source search produces complete candidates
that pass the same protected contract. Unsupported foreign serialization,
unbounded loops, or missing dependencies refuse.

Acceptance requires role-specific protocol conformance, local/remote identity
continuity, privacy across query surfaces, cancellation/recovery evidence,
and a non-coding profile using the same contracts.

## Model rollout and evaluation

A schema-compatible model change still needs evidence for quality, calibration,
cost, privacy, and workload fit. Record alias-only identity as a limitation.
Pin judges, students, reflectors, adapters, and inference settings independently.

Follow the [experiment lifecycle](../../optimization/experiments.md): explicit
partitions and exposure, frozen candidate selection, bounded confirmation,
negative results, total cost, scoped adoption, and eligible rollback.

## What to defer

Online self-modification, federated learning, weight training, richer media,
and event-triggered studies require additional scoped designs. Durable waits
and external business effects require their own domain guarantees. Do not
make these implicit consequences of a generic optimizer capability.

The [proposed integration issues](../../optimization/proposed-issues.md) define
dependencies and acceptance for the complete loop. Documentation checks remain
limited to prose, links, and contract consistency.
