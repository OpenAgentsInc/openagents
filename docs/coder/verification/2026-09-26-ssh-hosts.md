# SSH-launched hosts verification

Date: September 26, 2026. Scope:
[#9709](https://github.com/OpenAgentsInc/openagents/issues/9709), a wave 1
child of the [remote access program](https://github.com/OpenAgentsInc/openagents/issues/9704).

**The launcher passes its acceptance tests against a fake `ssh`.** It
installs a pinned archive over SSH, reuses it, refuses mismatched and
unsupported input, reclaims a dead owner's lock, adopts an external host,
relaunches a managed host after a runner change, and keeps the host running
through tunnel death and client exit. All evidence is synthetic: no real
`sshd`, remote machine, or Linux host was used.

## What landed

- The [SSH-launched hosts section](../../../nips/openagents/NIP-ENV.md#ssh-launched-hosts)
  of NIP-ENV: `create` versus `adopt`, `managed` versus `external` ownership
  recorded on the remote account, `destroy` only for launcher-owned hosts and
  `detach` otherwise, the lifetime rules, and enrollment authorized by SSH
  once.
- The [`coder-ssh` crate](../../../crates/coder-ssh/README.md): the
  `Launcher`, the fixed remote script in `src/remote.sh`, the loopback
  `Tunnel`, and the one-shot askpass helper.

The implementation is new Rust and POSIX `sh` written for this issue. It
reuses the digest-named, staged version layout of the
[portable host bundle](../runtime/portable-host.md) and the process-group
contract of [`supervise`](../runtime/subprocesses.md).

## Acceptance evidence

Commands ran on macOS 26.4 (arm64) with Rust 1.97.1 and a separate target
directory for the worktree, against base `cfc08f81b8`:

```sh
cargo test -p coder-ssh
cargo clippy -p coder-ssh --all-targets -- -D warnings
cargo fmt -p coder-ssh --check
```

| Check | Result |
| --- | --- |
| Unit tests | Nine passed: destination validation, shell quoting, connection options, `ssh -G` parsing, result-line parsing and error mapping, release and runner validation, and invitation redaction. |
| Integration tests | Eighteen passed, one helper ignored by design. The run was repeated three times, including once with 16 test threads, with no failure and no leftover test process. |
| Clippy and format | Clean. |

The integration tests in `crates/coder-ssh/tests/remote.rs` map to the
issue's acceptance list:

| Acceptance case | Test |
| --- | --- |
| Fresh install | `fresh_install_then_reuse`: one upload, a verified version directory, no leftover lock or upload. |
| Reuse | Same test: the second launch uploads nothing and reuses the same managed process. |
| Checksum mismatch | `checksum_mismatch_installs_nothing` corrupts the upload in transit; nothing is installed or started. `a_local_archive_that_does_not_match_its_pin_is_not_sent` refuses before any upload. |
| Unsupported platform | `unsupported_platform_is_named` and `a_release_without_this_platform_is_refused`. |
| Lock reclaim | `a_lock_left_by_a_dead_owner_is_reclaimed`; `a_lock_held_by_a_live_owner_is_waited_for_and_then_refused` leaves a live owner's lock untouched. |
| Adopt external | `a_running_host_is_adopted_as_external_and_never_stopped`: adopted even after a runner change; remove detaches and the host keeps running. |
| Relaunch after a runner change | `a_runner_change_relaunches_a_managed_host`, and again under `dash` in `dash_runs_the_same_script`. |
| Ownership rule: tunnel death | `tunnel_death_leaves_the_host_running` kills the tunnel with `SIGKILL`, then closes and drops every client value; the host keeps running and the next launch reuses it. |
| Ownership rule: client exit | `client_exit_leaves_the_host_running` runs a separate client process that launches, connects, and exits without destructors; the host keeps running, and only an explicit remove stops it. |
| Binary proof | `a_binary_that_does_not_run_is_not_installed`. |
| Reused process identifier | `a_reused_process_identifier_is_never_stopped`: records that name an unrelated live process are treated as stale, and that process is never signaled. |
| Password prompts | `a_password_goes_through_a_one_shot_askpass_pipe`: batch mode without a prompter, one helper per invocation, no password in the environment or arguments, every helper directory removed, and a wrong or refused answer fails. |
| Enrollment seam | `an_invitation_is_returned_to_the_caller`: the invitation returns to the caller and its debug form is redacted. |
| Resolution | `a_destination_resolves_through_ssh_g`. |
| Loopback `sshd` | `loopback_sshd` is skipped: a real `sshd` needs host keys and an authorized key for an account whose home the test may write, and tests may not touch the real `~/.ssh` or `~/.openagents`. Set `CODER_SSH_LOOPBACK_DESTINATION` to a disposable account to run it by hand. |

The fake `ssh` records its arguments, answers `ssh -G`, optionally prompts
through `SSH_ASKPASS`, and runs the remote command in `sh` or `dash` with
`HOME` set to a temporary directory. Every recorded invocation carries
`ControlMaster=no`. The fake `coder` binary is a shell script that writes
the runtime record and sleeps; the tests stop each one by its recorded
process identifier.

## Limits

- No real `sshd`, remote machine, or Linux host was exercised. The Linux
  path that detaches the host with `setsid` is untested here; macOS uses the
  separate-process-group path.
- The serve and invite commands are the resident host's job
  ([#9712](https://github.com/OpenAgentsInc/openagents/issues/9712)); the
  tests use a stand-in that follows the runtime-record contract.
- Invitations are returned to the caller, not redeemed. Redemption through
  `coder-access` ([#9705](https://github.com/OpenAgentsInc/openagents/issues/9705))
  is wired in #9712.
- The launcher returns typed local results and does not sign NIP-ENV
  request, lease, or cleanup artifacts.
- Password prompts repeat for each invocation because connection sharing is
  disabled. A crashed client leaves its local `ssh -N` process running; the
  host is unaffected.
