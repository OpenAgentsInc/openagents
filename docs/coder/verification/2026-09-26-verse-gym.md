# Verse Gym verification — September 26, 2026

[Issue #9700](https://github.com/OpenAgentsInc/openagents/issues/9700) adds a
shared desktop/iOS Gym building. Its first sources are Microcoder and
Terminal-Bench. The [Gym guide](../../verse/gym.md) covers setup and controls;
the [bridge reference](../../../crates/gym-bridge/README.md) defines the host,
source formats, private protocol, and exact launch authority.

## Delivered behavior

The Gym stands east of the plaza with a west-facing entrance, physical walls,
a readable 3D sign, and three bulletin boards. The portable world defines the
interior and interaction range; desktop and iOS use the same geometry and
boundary. Entering while foregrounded starts a separate bounded observation
worker. Leaving or backgrounding cancels it and drops its socket. Old visit
responses cannot overwrite the current board. No Gym workload starts on entry.

The boards display host-reported status, progress denominators, recorded time,
known cost, actual metric series, and provenance. Missing costs and completion
evidence remain unknown. Microcoder and Terminal-Bench precede optional model
training summaries. Native charts and desktop plots render the received values;
they do not create learning curves or infer benchmark success from process exit.

A Gym grant is independent of the chat-reader grant. It binds the device key,
host, relay, source-root digest, recipe revisions, and expiry. Signed encrypted
Nostr messages carry observations and requests. The host admits only locally
configured executables and arguments; the phone cannot supply commands.

Launching requires selecting a recipe, reviewing its limits, and confirming.
Confirmation consumes that review. A durable logical request ID deduplicates
retries; lost replies remain unknown. Host restart preserves unknown intents
and blocks new work until the operator resolves them. Wall time and launch
counts are enforced; an enforced provider-dollar budget is not claimed.

## Verification

The [retained evidence](../../../bins/coder-ios/verification/2026-09-26-gym-building/README.md)
separates portable Rust, desktop GPU, relay/host, simulator UI, and distribution
checks. All fixtures are synthetic. The launch fixture is a harmless local
executable, not a model or benchmark. No private benchmark outcomes were opened
for this feature.

The original nine-test native suite passed. A focused two-test Gym rerun covers
the final confirmation behavior and amber chart styling, alongside the final
mobile Rust tests and strict Clippy. Native tests walk through the real doorway,
open the board, inspect recorded values, reject execution in preview mode, leave,
and verify that observations stop. They also check background/resume behavior.

Host fixtures cover authenticated relay requests, wrong identities, changed
executables, source confinement, expiry, revocation, same-ID recovery, and
retained unknown launches. Source fixtures cover Microcoder records and real
Terminal-Bench record shapes, incomplete data, and unavailable cost components.
A decimal round-trip regression ensures signed metric values survive JSON
serialization without a digest mismatch.

Review found and corrected missing cost components being treated as zero,
blocking opens of replaced executable paths, a desktop chart scroll bound,
and the possibility of confirming a second launch without reopening its review.
Earlier failed checks remain in the evidence directory with their explanation.

## Coverage limits

These tests do not establish a physical iPhone session against an operator's
live benchmark host, sustained thermals, background delivery, or a new model's
performance. The production relay must accept the existing encrypted private
message profile and its traffic. A host needs explicitly configured source
roots and recipes; existing chat pairing does not automatically expose them.

The connection is stored in device-only Keychain storage. Pending launch IDs
survive leaving and re-entering during the current app session, but are not a
persistent mobile outbox across process death. A fresh app does not resend
unknown work. The host's durable ledger remains the source for reconciliation.
An unknown host launch blocks new launches; the operator must inspect the
underlying process and retained state. This delivery does not add a general
crash-reconciliation or remote cancellation UI.

Executable pinning covers the admitted executable, arguments, and working
folder identity. It does not pin every file a trusted runner might read or act
as a filesystem sandbox. Source observations are bounded file-derived claims;
recent modification does not prove process liveness. These limits appear in
the host reference and board provenance.
