# Host `wss` verification — September 27, 2026

The "`wss` without a forwarder" item of
[issue #9723](https://github.com/OpenAgentsInc/openagents/issues/9723) lets
`coder host serve` terminate TLS on its WebSocket listener, so a `wss` hint
needs no forwarder.

## Decision

The host terminates TLS itself, with a certificate chain and private key the
operator supplies as PEM files (`--websocket-tls-cert FILE
--websocket-tls-key FILE --websocket-name NAME`). The host does not obtain
or renew certificates; `tailscale cert` or an ACME client does. The
listener's own hint becomes `wss://NAME:PORT/`, and with TLS configured the
listener serves only `wss`. Without the three flags nothing changes: the
listener serves plain `ws`.

The host reads and checks both files once, at start, before it binds or
publishes anything. It refuses a key file that is missing, unreadable, not a
regular file, not owned by the user, or open to group or others; a file
with no usable PEM item; a key that does not match the leaf certificate;
and a leaf certificate that is not valid for `NAME`. It does not reload
rotated files: to rotate, replace them and restart the host.

The client verifies a `wss` certificate with WebPKI against the bundled
public roots, through `tokio-tungstenite`'s `rustls` connector. A test
replaces those roots with `client::WebSocketTls::test_roots`.

TLS is added on top of the direct channel, not in place of its security.
The channel already proves both keys, checks the grant, and encrypts and
sequences every frame. TLS lets clients that accept only `wss` connect and
hides the handshake's plaintext fields, such as the device key, host key,
and grant ID, from observers on the path. Those observers still see the
address, the TLS server name, and message timing and approximate sizes. A
certificate proves nothing about the host key.

## Evidence class

All evidence is synthetic. Tests run on one macOS computer. Sockets bind
`127.0.0.1` port 0 and connect over loopback. The certificates are
test-only fixtures in `crates/coder-host/tests/fixtures/tls`, issued by a
test CA whose private key was discarded; `rcgen` is not in the dependency
graph, so the fixtures are checked in. The host tests use the in-process
relay fixture from `coder-control`. No public certificate, browser, second
computer, LAN, or tailnet was involved.

## Checks that ran

Each command ran from the worktree with `CARGO_TARGET_DIR` set to the
worktree's own target directory and `CARGO_PROFILE_DEV_DEBUG=0`:

```sh
cargo test -p coder-host
cargo clippy -p coder-host --all-targets -- -D warnings
cargo clippy -p coder-host --no-default-features -- -D warnings
cargo fmt -p coder-host --check
```

Results: `coder-host` passed 14 unit tests, 3 CAP/CJ tests, the end-to-end
scenario, 5 headless enrollment tests, 3 serve tests, the plain WebSocket
test, and 3 `wss` tests. Clippy reported no warnings for the host build or
the client build, and formatting matched. The workspace gate did not run,
and the consumers of the client build (`coder-computers`, `coder-mobile`)
were not rebuilt; their API is unchanged except for additions.

The first test advertises one `wss` endpoint through a TCP byte relay that
does not terminate TLS, so the connector chooses the `wss` route over the
host's TCP listener. It also dials the host's own listener URL directly and
proves a second channel there; revocation closes both with `revoked`, and a
new handshake over the host's own URL completes TLS and then receives the
host's signed `revoked` verdict.

## Limits

- The files are read only at start; rotation needs a restart.
- The host does not check the chain against a root or the certificate's
  validity period; only the client does. The host does not warn before the
  certificate expires.
- The key-owner check was not exercised with a key owned by another user,
  which needs a second account.
- No browser or web client connected; the client that ran is the Rust
  connector in `coder-host`.
- No certificate from a public CA was used; the default WebPKI path was
  exercised only by refusing the test CA.
- Evidence is from one machine over loopback.
