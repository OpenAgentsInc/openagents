# JevBench, and the public tier vendored from it

**Status:** the suite is vendored and loads; no door has been scored on it
yet. Written 2026-09-20 alongside openagents#9463.

## What it is

[JevBench](https://github.com/fstandhartinger/jevbench) is an independent
benchmark for this contract, run by Benchmark Heaven and not affiliated
with TypeSafe AI. A system under test reads a state and a rubric with an
exact label set and returns a typed answer with a probability per option —
`noul`, `choice`, and `score` over `POST /v1/systemone`, the same shape
every door here serves.

Its v1.2 board scores 534 decisions per system on four axes — intelligence,
calibration, speed, and cost, combined as a geometric mean — and ranks Jev
1.13.0 first at 75.4. The upstream Python kev is ranked at 66.7
(`kev-0.6b`), 63.1 (`kev-0.5b`), 62.2 (`kev-4b`), and 58.3 (`kev-8b`), each
run through the author's own server on a rented RTX 3090.

## What we took

231 of the 534 decisions are public and carry a per-item MIT licence. They
are vendored as `crates/gym/suites/external-jevbench-v1.json` — 48 easy, 72
standard, and 111 hard items — built by `build_external_jevbench_v1.py`,
which pins the upstream commit (`484d414e`) and the file hashes JevBench's
own `datasets/manifest.json` records, and refuses anything else. The
question text lives in the question set of the same name, keyed by item id
because every item carries its own option set; `QuestionSet::ask` reading
an item id before a family is the only code this needed.

The suite is `external-v1`'s stronger sibling. The labels cannot have been
fitted by our authorship either, and the items were written for this
contract rather than adapted to it — the question text is theirs, so
nothing on the page is ours at all. The hard tier's `long_policy` states
run 2–4k tokens, and its `adversarial`, `trap`, `multi_hop`,
`temporal_numeric`, and `probability` families reach failure modes the
support-style suites do not.

## What it cannot do

- **Produce a JevBench Score.** 303 decisions are held out upstream — the
  146 judge items are not redistributable at all — so nothing here
  reproduces the composite. A run of this suite reports public-item
  accuracy under our gates, and that is all it reports.
- **Stay external forever.** The items are public; a door whose weights
  were trained after the 2026-09-19 freeze may have seen them. The suite's
  provenance names the commit so the claim is checkable.
- **Separate the port from the weights.** JevBench publishes per-item
  outcomes for every system it ran, including upstream kev at commit
  `20fa626` — the current Hub weights, not the historical checkpoints
  `crates/kev` pins. Diffing our port's rows against theirs measures
  checkpoint drift and implementation together; running both weight sets
  through `kev-serve` on these items separates them.
