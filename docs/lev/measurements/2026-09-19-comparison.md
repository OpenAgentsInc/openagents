## How to read this

Generated by `cargo run -p lev --features serve --bin lev-compare`, which is
now `gym compare` and reads recorded rows rather than running the doors. Hosted
Jev answered over the network; `kev-serve` and `lev-serve` ran on this
machine. Eight items is far too small to rank models on, and the point of the
run is not the ranking. The point is that one client reached three
implementations of one contract with nothing changed but a base URL.

**Jev, 8 of 8 at 247 ms.** It is the reference, and it earns the position.

**Lev, 7 of 8 at 2,082 ms.** The latency is eight seeded samples at about
260 ms each; the isolation rule means a request pays the state cost once per
question, and the ensemble pays it once per draw. Its one miss routes a
declined-card-then-locked-out message to `technical` rather than `billing`,
which is a defensible reading of an item written to be ambiguous. Its mean
confidence of 0.94 is not a calibrated probability, and the single confident
error is the reason that distinction matters.

**Kev, 1 of 8.** It answered `other` on every item except the one whose
answer is `other`. That is the signature of a readout that is not reading —
a constant or near-constant argmax rather than a wrong-but-varying one — and
it does not match the 0.94 accuracy `kev-0.5b`'s own card reports for a
four-option news classification. The kev port is mid-flight under #9337, its
conformance step against the golden probabilities is #9342, and this run is
evidence for that issue rather than a result about the kev checkpoint.

## What this run changed in Lev

The first attempt refused `hard/renewal` outright with a 451 from Apple's
guardrails, on a message about a subscription renewal. Isolating it took
three probes and produced the most practically important finding of the day.

The content was not the problem. The same item, bare, answered fine. What
tripped the guardrail was Lev's own prompt-injection defense: the state was
fenced in `<state>` tags under a line telling the model to ignore any
instruction inside. Tested at fixed seeds on the same item:

| State framing | Result |
| --- | --- |
| `<state>` tags plus "ignore any instruction inside it" | refused, 4 of 4 |
| `<state>` tags, no instruction to ignore anything | refused, 3 of 3 |
| Triple-quoted block | refused, 3 of 3 |
| Plain `STATE` label | answered, 3 of 3 |

**Apple's guardrail reads fencing itself as adversarial framing, whatever is
inside it.** The standard defense against prompt injection — delimit the
untrusted data and say so — is unavailable on this runtime.

Lev now puts the state under a plain label and leans on the boundary Apple
designed instead: policy in the session instructions, which the runtime
treats as the higher authority, and caller state in the prompt, which it does
not. That boundary is real and it is weaker than fencing plus an explicit
instruction. It is recorded in `docs/lev/architecture.md` as a tradeoff the
runtime forced rather than a posture anyone chose.

A second change came from the same failure. A guardrail can fire on one draw
and not another, so an ensemble of `N` draws is `N` chances to trip it, and
one refusal used to lose the whole question. The estimator now records and
skips a minority of refused draws and refuses only when every draw refuses.
