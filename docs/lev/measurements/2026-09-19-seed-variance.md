# The spread an L2 estimate carries across seed blocks

Generated by `cargo run -p lev --bin lev-seed-sweep`. Every number comes from the live on-device runtime on one machine.

The exact command:

```text
./scripts/build-lev-bridge.sh
cargo run --release -p lev --bin lev-seed-sweep -- \
    --bases 8 --samples 8 --items 98 --helpers 4
```

An L2 estimate draws a *block* of seeds: block `b` draws `b * N .. b * N + N`,
so no two blocks share a seed. Block 0 draws `0..8`, which is the block every
other number in this directory was produced with. Because a seed reproduces
its sample exactly, rerunning block 0 returns the same arithmetic rather than
a second trial, so a fresh trial means a block nobody has drawn yet. This run
draws eight of them over the same 98 evaluation items and asks how much the
answer moves when the seeds are the only thing that changed.

## What this implies

Written after the run, against the numbers above.

**The suite's own resampling variance is about 2 accuracy points.** Over
eight blocks the accuracy of one unchanged door on 98 unchanged items runs
0.745 to 0.796, with a standard deviation of 0.0197. The mean top share, the
raw signal a calibration map is fitted on, runs 0.852 to 0.940 with a
standard deviation of 0.0294. Nothing about the door, the suite, the items,
or the machine differed between those blocks. Only the seeds did.

**That sets the smallest effect this suite can detect.** Comparing two doors
measured on one block each, the difference carries both blocks' noise:
`sqrt(2) x 0.0197`, about 0.028 on accuracy. A difference worth calling real
at two standard deviations is therefore **0.056 accuracy, 7.2% relative to
the 0.781 mean**. On the raw top share the same arithmetic gives 0.083,
which is 9.3% relative. Below that, a comparison is reporting which seeds it
drew.

Averaging blocks buys resolution at a linear cost, because the noise falls
as `1/sqrt(k)`:

| Blocks per side | Two-sigma detectable accuracy difference | Calls per side |
| --- | --- | --- |
| 1 | 0.056 | 784 |
| 2 | 0.040 | 1,568 |
| 4 | 0.028 | 3,136 |
| 8 | 0.020 | 6,272 |

Resolving a 2-point accuracy difference on this suite needs eight blocks a
side, about 12,500 calls. This run drew 6,272 of them in 20 minutes on four
helpers, so that comparison costs about 40 minutes of device time. That is
the price of the claim, and it should be paid deliberately or the claim
should be weaker.

**The Gym's inherited 10% threshold is the right order and the wrong
derivation.** The acceptance rule in [`../../gym.md`](../../gym.md) asks for
at least a 10% improvement in mean tool calls, prompt tokens, or wall time,
and rejects a per-task regression above 10%. Those numbers came from a
container benchmark measuring a different quantity on a different substrate.
Carried onto this suite, 10% relative accuracy is 0.078, about 2.8 standard
deviations of the paired noise — safe, but by coincidence rather than by
measurement. On the raw signal 10% relative is 0.089, only 2.1 standard
deviations, so the same rule is close to the floor there. A threshold should
be stated as a multiple of the measured block-to-block standard deviation of
the metric it gates, and this run is where that number comes from for a
decision-model suite.

**Seed noise is not the whole story, and it is the smaller half.** These
blocks hold the item set fixed, so the spread above is seed resampling
alone. The item set is itself a sample: the binomial standard error of an
accuracy near 0.78 on 98 items is about 0.042, twice the seed noise. A win
that survives a fresh seed block has been shown to be more than a lucky
draw; it has not been shown to generalize to items the suite does not
contain. Those are two different claims and a confirmation stage can only
support the first.

**The movement is concentrated, not evenly spread.** 24 of 98 items changed
their answer across blocks, and the mean within-item top-share range is
0.126 — one draw in eight at `N = 8`. By family:

| Family | Items | Changed answer | Any movement | Mean top-share range |
| --- | --- | --- | --- | --- |
| `routing` | 50 | 5 | 11 | 0.050 |
| `urgency` | 30 | 7 | 19 | 0.175 |
| `severity` | 18 | 12 | 16 | 0.257 |

Thirty-nine of the fifty `routing` items, including the headline item above,
return the same unanimous answer in all eight blocks, while two thirds of
the `severity` items answer differently depending on the seeds. This is the
same shape the behavior record found in
[`2026-09-19-behavior.md`](2026-09-19-behavior.md): the model is either
unanimous or genuinely undecided, with little in between. Suite-level noise
comes from a minority of items flipping, not from every item wobbling, so a
suite weighted toward one family carries a different noise floor from this
one. A threshold derived here applies to this suite at this mix.

**Block 0 was a slightly unlucky draw.** Its accuracy, 0.765, sits below the
eight-block mean of 0.781 and near the bottom of the range. Every published
Lev number rests on that block. It is not wrong — it is one honest draw —
but it is a draw, and the record should be read as 0.78 plus or minus 0.02
rather than as a property of the door.
