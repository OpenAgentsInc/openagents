# Genesis lessons for Verse physics zones

**Status:** Research and adaptation proposal, 2026-09-27. No runtime integration or change to zone authority is approved by this document.

## Recommendation

Improve **Lagrange 1's local construction interactions first**: contact geometry for drifting parts, grasp and latch constraints, and a fixed-step simulation clock with reproducible state. Keep its Sun–Earth orbital model and station-keeping controller in Rust. Use Genesis as an **offline reference and experiment harness** for the local mechanics before considering a Python service. Its robot-training throughput and differentiability do not, by themselves, make a persistent multiplayer Verse zone more realistic.

This comparison uses [Genesis v1.4.2 at `f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492`](https://github.com/Genesis-Embodied-AI/Genesis/tree/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492) (Apache-2.0) and OpenAgents `989e5d27fa7881c77f380b30974b529ef40a44e3` (2026-09-27). The Genesis clone is reference material only; no Genesis source or assets are copied into Verse. This is a source review, not a measured performance comparison or a Genesis run.

## What exists in Verse

The [zone contract](../verse/zones.md) runs Lagrange locally on desktop and mobile. [`verse-lagrange`](../../crates/verse-lagrange/src/lib.rs) owns renderer-free physics; the [`Lagrange` adapter](../../crates/verse/src/zones/lagrange.rs) maps input and generates meshes; [`WorldRuntime`](../../crates/verse/src/zones/runtime.rs) enters, ticks, and drops the zone. The [L1 physics guide](../verse/lagrange-1.md) lists its approximations.

| Scale | Implemented behavior | Limit for a construction scene |
| --- | --- | --- |
| Orbital | [`orbit.rs`](../../crates/verse-lagrange/src/orbit.rs) integrates a nonlinear circular restricted three-body model with RK4 and periodic unstable-mode correction. The mission clock runs at 3,600× local time. | The model assumes circular primary motion; solar radiation pressure and planetary perturbations are absent. Genesis's scene gravity cannot replace this trajectory or the two-clock contract without an explicit external-force/orbital model. |
| Local flight | [`Station::step`](../../crates/verse-lagrange/src/station.rs) applies a 40 N translational velocity controller, propellant use, a linearized L1 tide, and a 140 m range clamp. | Astronaut attitude is yaw-held; pack thrust has no application point or rotational response. A taut tether clamps position rather than transmitting a finite force. |
| Free parts | [`RigidBody::rotate`](../../crates/verse-lagrange/src/body.rs) integrates torque-free Euler rotation; drifting parts move in the L1 field. | [`step_parts`](../../crates/verse-lagrange/src/station.rs) approximates each envelope as a sphere against six axis-aligned station boxes. There is no part–part contact, swept collision, or contact torque. |
| Assembly | [`grab` and `release`](../../crates/verse-lagrange/src/station.rs) account for translational momentum at capture and require distance and speed for latching. | Carrying sets part pose and velocity to the astronaut's each step; latching snaps it to a fixed slot. Neither is a force/torque-transmitting joint; release assigns a preset spin. |
| Time and state | [`WorldRuntime::tick_with_mode`](../../crates/verse/src/runtime.rs) bounds frame time; `Station::step` caps its input at 0.1 s. Returning to the plaza drops the zone and reentry constructs a new `Station`. | A large frame interval is truncated, and there is no L1 checkpoint or authoritative shared construction state. Renderer and simulation consume the same applied frame interval. |

The existing tests cover orbital/Jacobi behavior, propellant and velocity hold, momentum at capture, latch thresholds, and station collision ([Lagrange tests](../../crates/verse-lagrange/src/tests.rs); [rigid-body tests](../../crates/verse-lagrange/src/body.rs)). Preserve these proofs when changing local mechanics.

## What Genesis contributes

The [Genesis simulator](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/genesis/engine/simulator.py) owns solver stepping, substeps, a coupler, sensors, and a separate visualization path. Its [options](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/genesis/options/solvers.py) expose timestep/substep counts, rigid contact model, friction, constraint iteration, and hibernation; the [SAP coupler](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/genesis/engine/couplers/sap_coupler.py) handles contact across supported solver types. This is a useful architecture for zone-specific simulation, with numerical tradeoffs made explicit.

The [1.4.2 release notes](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/RELEASE.md) describe sleeping contact islands and constraint-solver improvements; [the example](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/examples/rigid/hibernation.py) shows when isolated bodies can sleep. `use_hibernation` is **off by default**, and its [option documentation](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/genesis/options/solvers.py) still warns that it has not been robustly tested. In microgravity, a free part with nonzero velocity must not be put to sleep merely because its speed is small; installed parts and a settled contact group are better candidates.

The [1.4.0 scene and trajectory API](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/genesis/engine/scene.py) distinguishes scene description, built state, checkpoints, and replay. Its release note restricts portable trajectory replay to the rigid solver. The scene code rejects exports with undescribed force fields or emitters, and omits some sensors, callbacks, and visual runtime state. The [1.3.3 deterministic setting](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/RELEASE.md) promises bit-exact behavior **on a given machine**; do not assume cross-device lockstep between iOS, Android, desktop, and Python.

Genesis also has [batched environments](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/genesis/engine/scene.py) and `requires_grad` for optimization experiments. Its [rigid solver](https://github.com/Genesis-Embodied-AI/Genesis/blob/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/genesis/engine/solvers/rigid/rigid_solver.py) supports a differentiable path with restrictions (including no hibernation, several friction and coupling modes). The earlier description of differentiation as MPM/tool only is outdated for this release. Use batch runs to tune a controller or test tolerances offline; a claimed benchmark on one GPU does not describe a six-part zone or mobile frame time.

## Adaptation order

1. **Make stepping and evidence repeatable.** Give the local station a fixed physics step (for example, 1/120 s) with a bounded accumulator and interpolation for rendering. Specify what happens when the budget is exceeded instead of silently dropping time. Keep `orbit.advance(local_dt * ORBIT_WARP)` on the same accounted local steps and retain the two displayed clocks. Define a versioned `Station` snapshot that includes orbit state, station-keeping schedule, bodies, grasp/installation state, propellant, targets, and simulation tick. Replay commands against that state and compare pose, momentum, propellant, and mission time at named ticks. This adapts Genesis's scene/state/replay distinction within Verse's Rust lifetime.
2. **Model contact before adding more matter.** Add bounded collision shapes for station panels, trusses, astronaut, and free parts, with broad-phase pairs, swept or substepped tests for thin geometry, stable manifolds, restitution, and normal/tangential impulses that apply torque. Exclude only explicitly non-solid lattice. Record contact pairs and impulse traces for debugging. Reuse a reviewed Rust collision/constraint library if it meets the mobile and deterministic-state requirements; do not port a GPU contact solver merely to serve six parts. Calibrate against Genesis rigid-contact experiments for the same geometry, mass, initial pose, and timestep, then compare observable motion, penetration, and solver cost.
3. **Replace teleport-like interactions with constraints.** A grab should constrain a contact point on the part to a hand pose, transferring both linear and angular impulse; reject impossible captures or apply an explicit inelastic capture rule. A latch should require position **and orientation**, low relative linear **and angular** speed, then make a fixed joint to the jig. Model the EVA tether as an anchored, finite-length unilateral constraint with impulse/force limits; keep the existing distance cutoff as an emergency boundary. Thruster placement can then produce attitude torque and propellant use. These changes are the largest source of visible physical realism in Lagrange.
4. **Scale only when measurements demand it.** Profile awake dynamic bodies, narrow-phase pairs, contact iterations, CPU frame time, and allocation on desktop and mobile. Make installed parts static; sleep only dynamic bodies in settled contact islands and wake them on contact, grasp, thrust, or joint removal. Do not sleep freely drifting bodies because orbital microgravity supplies no settling surface. Evaluate a Genesis Python service only for isolated training/calibration jobs, with a versioned input/output contract and recorded scene parameters; local offline zones should not depend on its availability.

### Proposed acceptance experiments

- A released spinning tank strikes a solar panel edge and a drifting truss: no tunneling or persistent interpenetration at the selected maximum speed and timestep; angular and linear impulses are observable, and restitution stays within the authored range.
- A loaded astronaut grasps, rotates, releases, and docks each part: momentum changes account for the grasp impulse and pack thrust; docking refuses excess angular speed or misalignment; latched parts remain fixed to the jig.
- A tethered EVA at the 140 m limit neither teleports inward nor gains energy without thruster input; the tether tension and propellant change are recorded.
- Two replays from the same versioned snapshot and command stream match within a stated numeric tolerance on each supported platform; desktop and mobile may use tolerances rather than cross-platform bit identity. Compare a Rust contact scenario against a pinned Genesis reference run before declaring fidelity.
- Existing CR3BP, Jacobi, station-keeping, and propellant tests continue to pass; the local step budget meets a measured device frame-time target.

## Boundary and later options

Preserve the existing Rust physics crate and the [`ZoneId`/zone lifecycle](../verse/zones.md). Genesis is Python/PyTorch/Quadrants based, so embedding it in both native clients or running it as a live server adds packaging, platform, latency, versioning, and shared-state concerns. A networked world needs an admitted authority model before its physics becomes shared; replay or a GPU simulation alone does not supply that authority.

For a future pressurized habitat, cloth, liquid, or granular area, prototype only the necessary solver and coupling: Genesis's [materials and couplers](https://github.com/Genesis-Embodied-AI/Genesis/tree/f5b2b41f6aa736e26ec4f8d9e9c31ae105c0c492/genesis/engine) show how to isolate it. Vacuum EVA does not need ambient fluids, SPH, MPM, or FEM. If improving the orbital model later, evaluate ephemerides and solar radiation pressure against the [named CR3BP approximations](../verse/lagrange-1.md#approximations) as a separate orbital study; generic rigid-body gravity is not an orbital ephemeris.
