# Archived teardowns: Nostr coverage review

Status: completed source review and draft protocol design, 2026-09-26.
Implementation and conformance remain separate work. The
[Coder integration plan](../coder/design/teardown-nostr-integration.md)
contains the product assessment, vertical architecture diagram, delivery order,
and measurement gates. The [protocol index](../../nips/openagents/README.md)
links the resulting specifications.

## Source and method

The September 18 [Nuke commit](https://github.com/OpenAgentsInc/openagents/commit/dabc08102fddd72118d710d644a69c5c4eab95a2)
removed `docs/teardowns/`. This review uses all **81 Markdown documents** in
its parent, [8f84d05896](https://github.com/OpenAgentsInc/openagents/tree/8f84d05896ef14edee491621bf977ee5315cc8ed/docs/teardowns):
**4,077,845 bytes**, including the archive README, synthesis documents, and
seven files under `cc/`. The [source inventory](teardown-source-inventory.json)
records every path, exact byte count, and SHA-256 digest. Each source appears
once in the tables below. Links pin the original commit rather than a deleted
path on main.

The review examined the archive's architecture, persistence, recommendation,
authority, failure, and verification sections, then compared their transferable
ideas with all three current NIP lanes. These are historical observations and
proposals; this review did not rerun the donor products or establish that their
current versions behave identically. Earlier implementation claims, marketing,
and speculation retain their source's limitations. The archive's Effect,
TypeScript, Electron, Omega, proprietary backend, and vendor-specific deployment
choices do not override the current Rust/Nostr design.

The tables distinguish an existing contract, a newly specified missing
contract, and a local implementation or product decision. “Covered” means the
protocol responsibility has an owner; it does not mean the current runtime
implements every role. No private donor code, prompts, credentials, or backend
endpoints are imported. The archive stays in Git history rather than being
restored as current instructions.

## Reuse across the three NIP lanes

The pinned official and Block sources remain unchanged. Their source commits
are recorded in [the manifest](../../nips/manifest.json). The earlier
[cross-lane review](2026-09-26-openagents-gap-review.md) gives the complete
identity, market, control, and storage mapping. The teardown pass adds these
consumer-specific distinctions:

| Existing source | Useful role | What Coder must add or enforce |
| --- | --- | --- |
| Official 01, 42, 44 | Signed events, authenticated relay access, recipient encryption. | Durable application admission, current scoped authority, complete history, and resource fencing; transport does not supply them. |
| Official 17, 29, 44, 59; Block OA, AA, AP | Conversations, groups, identity, and persona metadata. | SESS/WORK/LIVE preserve actual principal and scope. Room membership, owner attestations, or a display name cannot approve actions or expose a private context. |

| Block AE, RS, CW, WP, DV, IA | Memory heads, read state, channel visibility, appearance, and archival. | POL governs learned-preference activation; WS owns repairable projections. Mutable memory is not authority, and dismiss/archive is not task completion. |
| Block AO, AM | Ephemeral activity and attributable turn metrics. | RUN/SESS retain authoritative history. Missing telemetry cannot prove quiescence; estimated usage cannot prove billing or release a reservation. |
| Block ER, PL; official 40 | Reminders, client wakeups, and event expiry. | AUTO supplies admitted occurrences; ENV supplies execution leases. Push delivery, a timer, or event disappearance cannot authorize or cancel work. |

Official and Block NIP identifiers in this table refer to the corresponding

separate virtual-world profile, not a physical-device authorization scheme.
Pinned deprecated or unrecommended formats retain compatibility meaning and
do not become the basis of the new profiles.

## Remaining work and deliberate boundaries

The archive contributes durable queue semantics, source-preserving history,
workspace collaboration, productive planning, autonomous bounded work,
portable execution, private learning, reusable components, media interaction,
and useful agent labor. The new profiles assign their missing wire contracts.
They do not turn every desirable algorithm or screen into a NIP.

Implement renderers, Markdown/diff views, focus/keyboard/accessibility behavior,
stream batching, document algorithms, PTY/LSP/DAP adapters, native packaging,
OS isolation, model serving, and retrieval in the appropriate Rust components.
Cross-client records preserve the facts those components need. Use current
`coder-terminal` and runtime abstractions; do not restore an older application
stack just because a teardown recommended it.

Some features require a later explicit profile: collaborative CRDT/OT mutation,
provider-specific terminal binary streams, calendar/DST schedules, general
PRG suspension, organization threshold approval, brokered external calls from
Wasm, additional domain anchors, and device-specific timing/interlocks. The
first versions cover conditional edits, admitted adapters, finite occurrences,
and observation-bound proposals without falsely claiming those wider
semantics. Native partial support is visible; unsupported required behavior
refuses.

The implementation plan prioritizes a complete local session/workspace path
and high-priority tracked labor, followed by fault-tested automation,
environments, media, and measured reuse. Release requires negative fixtures,
actual host enforcement, independent clients/operators, retained failure and
cost evidence, and workload results. Source coverage is not an agent-quality
result or proof that any new role is already deployed.
