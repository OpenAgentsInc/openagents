# FI RS256 candidate policy v1

This selects the first NIP-FI implementation profile, `fi-rs256-policy-v1`.
It implements typed candidate policy in Coax, before signature and transport
integration. It is not an advertised FI verifier or identity authority.

The defining upstream remains [the pinned NIP-FI](../../nips/block/NIP-FI.md).
RS256 means RSASSA-PKCS1-v1_5 with SHA-256, as specified in
[RFC 7518 §3.3](https://www.rfc-editor.org/rfc/rfc7518.html#section-3.3).
Algorithm allowlists and mutually exclusive token classes follow
[RFC 8725](https://www.rfc-editor.org/rfc/rfc8725.html). This profile supports
no P-256, Ed25519, RSA-PSS, symmetric algorithm or `none` fallback. HOST grants
may later reuse arithmetic, but select their own authority and JOSE contract.

## Current implementation and authority boundary

- `coax/lib/nostr/block/fi-policy.coax`: exact community/issuer selection,
  configuration, class and claim/time predicates.
- `fi-addresses.coax`: complete pinned IANA special-purpose address refusal
  for public HTTPS and NIP-FI's explicit mesh allowlist.
- `fi-jwks.coax`: trusted fetch-observation predicates, bounded public RSA-key
  selection, installed-generation and snapshot binding, and candidate ordering.
- `coax/lib/net/uri.coax`: shared bounded DNS URI syntax; no normalization.

`fi_assertion_candidate` resolves Host, checks the exact community issuer
allowlist, selects its issuer policy, rejects class/claim violations, and reads
only the current local snapshot. It performs no network effect. Configured Host aliases may intentionally map to a different canonical URI host;
this trusted mapping is exact, unique and part of the future policy identity.
A successful
`FI_CANDIDATE` selects a key to try; it proves neither signature nor possession.
`FI_UNAVAILABLE` and `FI_REJECTED` preserve NIP-FI's dependency/evidence distinction.

The C test adapter supplies fixture observations only. There is no shipped
JWKS HTTP adapter, compact JWS/JWKS parser, RSA verifier, full AssertionPolicyId
builder, NIP-42 pairing or live FI authorization integration in this slice.
Transported proto fields and remote booleans never become trusted observations.
The task `fi-jws-verifier` explicitly owns those next steps and their independent
vectors, actual adapters and target evidence.

## Selected bounded representation

All ranges are byte limits. Original signed bytes must be retained by the later
bounded decoder. Its typed projection must preserve presence, reject duplicate
keys, and establish the field types before calling these predicates. Numeric
conversion cannot turn missing, fractional, infinite or out-of-range numbers
into an admitted integer. No protobuf reserialization becomes a JWS preimage.

| Dimension | Selected profile |
| --- | --- |
| Communities / issuer policies | 1–16 each; exact DNS Host, no port alias in this initial Host profile |
| Community audience | One exact HTTPS or WSS URI without query; no shared audience between communities |
| Community issuer allowlist | 1–16 unique nonempty ASCII visible strings, each at most 2048 bytes; selection is exact against a configured HTTPS issuer URI |
| Issuer and JWKS URI | Shared DNS URI subset, at most 2048 bytes; exact issuer, no issuer query; key-source rules below |
| Subject / access client ID | Opaque nonempty ASCII visible string, at most 256 bytes; never interpreted as email/display identity |
| Audience claim | 1–16 unique nonempty ASCII visible strings, each at most 2048 bytes; exact expected value must be a member |
| Nostr / agent-owner key | Exactly 64 lowercase hex bytes; curve validity and fresh possession are later verifier gates |
| NumericDate / clock | Explicit presence, integer seconds in 0…2^53−1; other NumericDate forms unsupported by this profile |
| Assertion age / connection lifetime | 1…31536000 seconds; skew 0…300 seconds |
| JWKS refresh / hard deadline | Refresh at least 1 second, strictly below hard deadline; hard deadline at most 31536000 seconds, so refresh is also below one year |
| Token marker | One configured name up to 128 visible ASCII bytes; resource-owner and client sets each 1–8 unique values of up to 128 bytes, disjoint |
| JWKS keys / kid | 1–16 keys before lookup; exact unique nonempty ASCII visible `kid`, at most 128 bytes |
| RSA key | `kty=RSA`, mandatory `alg=RS256`, mandatory `use=sig`; optional key_ops exactly `["verify"]` when present |
| RSA integers | Minimal unsigned big-endian n, 2048–4096 bits, odd; e exactly 65537 (01 00 01); no private parameters |
| Fetch observation | 1–16 DNS answers, one resolution/connection, first answer pinned, no redirect/proxy, status 200–299, 1–524288 streamed bytes, elapsed 0–9999 ms |

JWK integers above are the decoded values. The future parser must additionally
require canonical unpadded base64urlUInt and reject every unknown/private key
parameter under this selected closed profile. A modulus-shaped value is not a
validated RSA signature or proof of modulus construction. Unsupported mixed-key
snapshots refuse as a whole; algorithms are not inferred from a matching kid.

A dedicated token has exactly `nip-fi+jwt` or `nip-fi-agent+jwt`. Only the
agent type permits an owner, which must be distinct and properly encoded.
A human token refuses owner presence with any value. The access-token class has
exactly `at+jwt`, a client ID and an unambiguous configured marker; it always
refuses owner presence. Client-subject admission additionally needs explicit
allowance and the issuer's non-collision posture. There is no class fallback.

Times enforce now < exp, iat ≤ now + skew, now < iat + maximum_age and, when
present, nbf ≤ now + skew. Equality at expiry/age is expired. The validated
safe-time domain plus the one-year caps fits signed int64 arithmetic.
The internal, unexported session deadline helper computes the minimum of connection+lifetime,
exp, iat+maximum_age and snapshot hard deadline. It requires those prior
validated nonnegative time/configuration candidates; it is not a general
arbitrary-int arithmetic entry point or a session lifecycle implementation.

## Key-source transport contract

Both transports use the shared DNS-only URI subset: no IP literal, credentials,
fragment, raw controls/non-ASCII or backslash. Percent escapes are preserved;
this subset is deliberately narrower than general URI syntax.

For `public_https`, HTTPS and authenticated TLS endpoint identity are mandatory.
Every DNS answer must be outside every pinned IANA special-purpose range.
IPv4 multicast additionally refuses. IPv6 must be inside 2000::/3 and outside
all special-purpose ranges there; every other catalog row is outside the
required prefix and therefore refused. Globally reachable exceptions within
special-purpose ranges also refuse conservatively. This is not a routability
claim. The complete original CSVs, source URLs, hashes and collapsed policy
coverage are in `coax/tests/nostr/data/iana-2026-10-28/`.
The [IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry) and
[IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry) registry
pages were retrieved on 2026-10-28 and both report update date 2025-10-09.

For explicit `mesh`, HTTP with no query is permitted only under trusted operator
configuration. IPv4 permits 10/8, 172.16/12, 192.168/16, 100.64/10, 127/8 and
240/4 except 255.255.255.255. IPv6 permits fc00::/7 and ::1. IPv4-mapped,
compatible and standardized translation addresses gain no embedded-v4 allowance.
Selecting mesh asserts externally enforced mutual peer authentication,
integrity, endpoint authorization and egress restrictions. HTTP and this pure
policy cannot establish those properties; the observation's endpoint posture
must come from trusted deployment state, never the response body.

Every answer must be eligible before the first is pinned; an empty, mixed,
unsupported-family or oversized answer set refuses. The peer must match the
pinned address and family. One resolution and one connection are permitted;
redirects, proxies and alternate/fallback paths refuse. The whole-fetch timer,
streamed byte cap, peer pinning and TLS/posture truth must be enforced by the
actual effect adapter. Merely constructing matching observations proves none
of those effects happened. A browser cannot inspect/pin its DNS answers or
actual TLS peer through ordinary fetch: use an authenticated broker or report
unavailable. Do not claim browser SSRF enforcement from these fixtures.

## Snapshot, rotation and policy identity

A snapshot is an immutable local provider result bound to exact issuer,
key-source URI, expected full policy digest and the currently installed positive
generation. Relabeling an issuer/source/digest or supplying an older cached
generation refuses before kid lookup. The provider atomically replaces a
snapshot only after an authenticated bounded fetch and complete key parsing.
It increments the installed generation and revalidates dependent sessions.
Generation comparison is policy here; the durable provider and session
revalidation effects remain the next implementation gate.

Added keys become candidates on installation; removed keys cease to be
candidates on the next revalidation against the installed generation. Duplicate
kids or any malformed/private/unsupported key make the snapshot unavailable.
Unknown kid in a well-formed snapshot is rejected evidence. An unavailable,
revoked, future-dated, hard-expired or refresh-failed snapshot is unavailable.
This selected implementation is stricter than a soft cache: a recorded refresh
failure allows no stale-on-error continuation. A fresh authenticated successful
replacement is required to clear the failure.

The caller supplies the expected digest and generation from trusted local
policy/provider state. They are not input claims, and this slice does not
construct or advertise the full `AssertionPolicyId`. Before live verification,
that ID must hash a versioned canonical contract covering the selected issuer,
community Host/audience/issuer association, class, algorithms, URI and transport,
marker/identity/key mapping, presence/size/time rules, and compiled verifier
behavior. Policy changes invalidate existing policy bindings; key rotation
changes snapshot generation rather than policy identity. Compiled RSA/JWS
verification is not present yet, so its behavior cannot honestly be certified
by a current local configuration hash. The follow-up task includes this gate.

## Evidence and remaining work

All three Coax policy files carry `#authority`; checks precede their code.
The full reachable fi-jwks closure passes 46 groups and 782/782 mutants with
no exemptions. The retained source/artifact hashes are in
`coax/tests/nostr/data/fi-policy-evidence-2026-10-28.json`.
The address policy's original complete IANA rows are checked by independent
Python ipaddress membership, not only a parity copy of a former implementation.
`coax/tests/nostr/fi_policy.py` exercises checked/release native C, ASan/UBSan
and actual Wasm with host effects denied. It covers community/class/time,
fetch observations, add/remove/duplicate/revoked/stale/relabeled snapshots,
secret parameters, limits and the pure complete candidate chain.

These are finite correctness/refusal fixtures, not an independent security
audit, machine-code constant-time proof, real authenticated network trace or
production identity approval. The primary remaining gates are original-byte
parsing and RSA correctness, actual transport/provider enforcement, full policy
identity, fresh NIP-42 pairing, authenticated revocation/session lifecycle and
per-target integration. No NIP-FI support bit or production cutover changes here.
