# Native workspaces and account chat library v1

Connected computers own repositories and GitHub credentials. The phone renders shared GPU controls and sends typed operations over the existing authenticated HOST app.rpc carriage. This profile does not extend the frozen environment runtime or grant arbitrary filesystem access. Workspace references identify worktrees of the locally adopted repository; a supplied path is never an adoption. No operation is translated into a Claude prompt. `workspace-enable [--grant ID]` is an explicit local profile opt-in, stored through the existing immutable private environment-configuration codec in a separate exact-grant sidecar. Each request reloads it and requires the same device, grant and canonical adopted root. Existing realm/browser grants do not acquire these controls automatically. The owner’s deployment enables the requested profile on the already enrolled computers.

`openagents.environment.workspace.v1` requests name a method, workspace, branch/base/title/body, expected state digest, command ID and validity window. Reads page through worktrees (8), branches (16), status/diff and GitHub pull requests (3). Page and cursor accompany requests and replies; next=0 marks the end. The selected workspace is resolved against the complete bounded Git registry independently of the visible page. Canonical selected path is shown in confirmation. Each page fits the frozen 49,152-byte HOST body. Large/non-UTF8 diffs are explicitly shortened, never interpreted as a clean tree. Writes create/remove a worktree, create/switch a branch, push the selected branch, create/edit a pull request. Writes require an explicit confirmation of the selected computer/workspace and retain exact request bytes through unknown outcomes. A changed HEAD or working tree refuses with stale_state. Dirty or active worktrees cannot be switched or removed. Removal never forces or deletes a branch. Commands are durably claimed before effects and never executed twice; an interrupted effect reports unknown. Git and gh execute argument vectors, never an interpolated shell. Hooks, pagers, credential prompts and optional network fetches are disabled. GitHub tokens remain on the computer.

`openagents.chat.library.sync.v1` is private account presentation metadata at GET/POST `/api/chat/library/v1`. Its snapshot contains revision and the existing local-v1 library document. A write carries command (32 lowercase hex), expected_revision and document. The authenticated principal owns the record; body ownership is not accepted. Commands are replayable with identical bytes, conflicting command reuse refuses. Compare-and-swap prevents lost updates. The client retains its base and exact pending write, merges remote updates with changed local fields (including clearing defaults), and retries conflicts against the new revision. Concurrent edits of the same field resolve to the later accepted local intent; unrelated fields are preserved. A response from a previous login cannot affect a new account. Reads run on foreground and at bounded intervals. Offline local edits and pending writes survive relaunch. Archive only hides a row; it neither deletes transcripts nor changes an agent's execution. Metadata is not an access grant.

Guests retain local preferences. On first account sync, locally saved aliases/flags migrate without removing remote-only entries. Existing local-v1 bytes and frozen runtime schemas remain unchanged.

GitHub PR calls use the validated origin owner/repository explicitly, rather than gh’s inferred upstream. That origin participates in confirmation digests. API references: [create](https://cli.github.com/manual/gh_pr_create), [edit](https://cli.github.com/manual/gh_pr_edit), [paged PR reads](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests).
