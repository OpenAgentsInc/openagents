# TypeScript lane deletion — Rust-only repository

- Date: 2026-08-28
- Class: owner-accepted plan / work-packet ledger
- Status: admitted
- Baseline: `e8484027d4` (`openagents/main`)
- Dispatch: this document. Live forge issues under it are execution
  receipts, not a second policy.
- Owner direction: delete the TypeScript lane of `OpenAgentsInc/openagents`.
  This repository becomes Rust-only.

This document supersedes the TypeScript-retention clauses in
[`2026-08-26-codebase-deletion-audit.md`](./2026-08-26-codebase-deletion-audit.md)
and the "named TypeScript consumer may stay" language in `AGENTS.md`.
A TypeScript path in this repository is not a candidate to keep. Git
history is the archive.

Phoenix and Elixir in `OpenAgentsInc/openagents.com` are out of scope.
They are a different repository and a different language. This plan does
not move web, API, forum, or forge work back into this tree.

## End state

The active tree of `OpenAgentsInc/openagents` contains:

- Rust crates under `crates/` (CLI, coder API, contracts, managed-computer
  daemons, Claude Agent SDK)
- Rust/Wasm plugins under `plugins/`
- JSON, Markdown, specs, fixtures, and release/ops scripts that are not
  TypeScript
- Harbor Python confined to the digest-pinned `harbor-runner` image
  (`bench/adapters/`, `docker/harbor-runner/`)

It does not contain:

- `apps/**` TypeScript applications
- `packages/**` TypeScript packages
- `types/**` TypeScript ambient packages
- `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `vite.config.ts`
- `tsconfig*.json`
- `.ts`, `.tsx`, or workspace `*.mts` product or tooling source
- a Node/pnpm/Vite Plus completion gate
- npm publish runbooks for packages this repository no longer ships

The completion gate is Cargo. Name it in `AGENTS.md` in the same commit
that stops invoking `pnpm run check`.

## Rules

1. **No new TypeScript.** Do not add a `.ts` / `.tsx` file, a workspace
   package, or a `pnpm` script. A follow-up that needs a tool writes it in
   Rust (crate, `plugins/`, or a `cargo` binary/xtask).
2. **Do not keep TypeScript because something still imports it.** Reachability
   inside the pnpm graph is the loop this plan destroys.
3. **Do not keep TypeScript because Phoenix might call a Cloud Run service
   that was built from it.** Drain the service or transfer the workload to
   Phoenix. Then delete the source here.
4. **Do not keep TypeScript as a schema authority.** JSON Schema, fixtures,
   and generated bytes that Rust already compiles may stay as data. The
   TypeScript generator that produced them does not stay.
5. **Do not wait on npm deprecation to delete source.** Deprecate published
   `@openagentsinc/*` artifacts with an OTP when an owner is present. Source
   deletion does not depend on that OTP.
6. **Do not wait on a perfect Terraform apply to delete source.** Live
   infrastructure drain is a parallel lane with its own receipts. Abandoned
   HCL is a follow-up, not a reason to keep Node applications in the tree.
7. **Rust crates are not TypeScript.** `crates/oa-codex-control`,
   `crates/oa-node`, `crates/oa-workroomd`, `crates/openagents-cloud-contract`,
   and `crates/oa-cloud-run-bridge` stay or go under a computer-product
   decision, not under this plan. This plan may delete TypeScript that only
   existed to talk to them (`apps/pylon/deploy/agent-computer` and similar).
8. **Harbor Python is not TypeScript.** It stays inside the pinned image.
9. **Every wave lands with the then-current completion gate green.** Until
   Wave 0 rewrites the gate, that is still `pnpm run check`. After Wave 0,
   it is the Cargo gate below. Do not describe a partial gate as green.

## Why Wave 0 is first

`pnpm run check` is `fmt:check` → `lint` → `check:fast` → `typecheck` →
`test:rust` → `test`. Most of that command exists to type-check and test
the TypeScript graph. Deleting applications while that gate still requires
them forces every packet to keep dead packages alive.

The 2026-08-26 audit already named this closed loop: stale applications
import stale packages, and the aggregate suite treats both sides as
required. Wave 0 cuts the loop. Waves 1–4 then delete without negotiating
with Vite Plus.

- It does not delete `docs/transcripts`.

  "thin Effect remaining surface."

## Execution

Fresh worktree per wave off current `openagents/main`. Claim the wave on
the matching forge issue, or on this document when the issue is already
the wrong shape. Push the wave to `main`. After Wave 0, do not run
`pnpm` to prove green.

Order is Wave 0, then 1, then 2, then 3, then 4, then 5. Do not start a
later wave in the same tree as an unfinished earlier wave. Waves 2 and 3
may proceed in parallel after Wave 1 if their paths stay disjoint
(`apps/openagents-audio*` vs `packages/*` that voice does not own). Wave
3 must include any package Wave 2 left behind.
