# Audit: today's apps work against the Exact research

Written 2026-11-10. It compares the apps work started today with what this
folder's research said Exact does and what Coax should take from it:

- the apps roadmap ([docs/apps/2026-11-10-apps-roadmap.md](../../apps/2026-11-10-apps-roadmap.md));
- the component system ([components/spec.md](../../../components/spec.md));
- OpenAgents for desktop on Linux (`apps/shared/host/linux/`,
  `components/raster/`, `apps/openagents-desktop/linux/`);
- the one agent stack (`coax/lib/agent/engine`, `session`).

All of it is tracked in GitHub #13153.

How this was done: I read the four documents in this folder in full and the
code written today. I did not read Exact's source again; every statement
about Exact here is taken from [01](01-what-exact-is.md) to
[03](03-what-to-adapt.md). Numbers about our side were measured today on
`coderos-4080` and say so.

## Verdict

Today's work agrees with the research on structure and ignores it on the
agent loop.

- **Agrees:** one set of components over thin hosts, one GPU painter, a
  terminal backend, an element tree with ids, and no second UI language.
- **Ignores:** the research's first three phases (one driver, an
  agent-owned clock, drive scripts). The new Linux host has its own step
  language instead, the same mistake the Mac host already made.
- **Leaves open:** layout. The research says CSS-named flex written in
  Coax and checked against Chrome. The component spec does not mention
  it.

Seven changes are recommended at the end. The first two cost little now and
a lot later.

## Where today's work follows the research

| The research | Today |
| --- | --- |
| Exact's shape: a compiled description, a kernel that lays out, hosts that present | The spec's layers: core (state and rules), layout, paint (a display list), skin, backend. The same split, in one language |
| Ink: one shader that draws rounded rectangles, rings, shadows and glyphs from an atlas, for hosts with no native toolkit | `backend/gpu`: one shader in Coax for every pixel target. The shader already exists (`apps/openagents-web/gpu/chat.coax`) and today it was emitted as SPIR-V for the first time and drew the desktop app on Vulkan |
| A terminal host that lays out the same tree into cells | `backend/terminal`, planned, so Coder's terminal stops carrying its own Markdown |
| "What not to adopt: a second UI language" | Kept. Components are Coax procedures over caller-owned state |
| "What not to adopt: platform-native controls" | Kept. The Linux host draws everything; there is no GTK or Qt |
| Item 4: grow `aethyr/ui/tree.coax` into the tree every element is in, with a stable id, role and label | The spec puts that table in `core/` and makes drawing, hit tests, focus and accessibility read it. Not built yet |
| "Fix loops get three rounds" | In `AGENTS.md`, and followed today (the browser's WebGPU adapter took three rounds, then stopped) |

Two results from today bear on the research directly:

- **Thin hosts work.** Exact's hosts are its largest directory: 822K lines,
  398K for Apple alone, because each host maps the tree onto a platform
  toolkit. Our Linux host is 290 lines of C written today, on 1,520 lines
  of existing Vulkan and Wayland helpers (`verse/gpu/vkc.c`, `vks.c`,
  `vkp.c`, `vkw.h`), plus 285 lines of app glue. That is what drawing
  everything ourselves buys.
- **Text in Coax works.** The atlas the Mac builds with CoreText is built
  on Linux by 694 lines of Coax (`components/raster/atlas.coax`,
  `svg.coax`) over the existing TrueType reader. The demo conversation
  goes from process start to a written picture in 0.23 to 0.28 seconds
  offscreen at 1320 by 880 (three runs).

## Where today's work departs from the research

### 1. A second, private driver

The research's first item is one driver with a small fixed set of
operations, the same on every host, with targets named by id. Phase 1 of it
exists for the web (`coax/web/drive.coax`). Phase 7 is the native hosts
answering the same operations over a local socket.

Today's Linux host did not do that. `apps/openagents-desktop/linux/main.c`
has its own `--do` steps (`click X,Y`, `type`, `send`, `key`, `wait`,
`status`, `last`), copied from the Mac host's (`Sources/Zeron.swift`
`step`). So there are now three ways to drive an OpenAgents surface, and
two of them click at pixel coordinates.

This is the departure that will cost the most. Every check written against
`--do` is a check that has to be rewritten.

### 2. Real time, not an agent clock

The research's second item: between two driver operations nothing moves.
Today's `--do wait N` sleeps for N seconds of real time while an engine
answers, and a picture taken "mid-turn" depends on how fast the machine
is. The Mac host has `--still-clock`, which freezes the desk's "now"
labels and nothing else.

The web's agent clock has not landed either (`drive.coax` says the clock
"comes with phase 2"), so this is a shared gap, not a new one. But the
native host is where it is cheapest to do right: the host already passes
`dt` into every frame and nothing else reads a clock.

### 3. Pixels per platform as the check

The component spec says: one golden picture per component, skin and
platform. The research points the other way twice:

- Exact compares screens in text, node by node, so an agent need not look
  at a picture;
- Exact checks layout against one oracle (the browser), not against a
  stored picture per host.

Pictures per platform are the most expensive kind of check to keep. The Mac
app has 21 of them, matched pixel for pixel against Zeron, and they cannot
run on this machine at all.

### 4. Layout is still arithmetic

The research's item 4 says the retained layer should use CSS-named flex
layout written in Coax, limited to block and flex, checked against Chrome
by laying out the same tree as HTML. Its reason: agents already know CSS,
and a layout engine is what makes `layout` answerable.

The component spec's layout layer is "sizes and positions from state, a
width and a skin", which is the hand arithmetic the Zeron components
already do. It will work for the chat set, which has one column. It is a
choice made by omission, and the game HUD set and any form-like screen
will pay for it.

### 5. Everything is redrawn every frame

Exact updates only what changed. The research called our immediate mode
"different by design" and fine for worlds at 60 frames a second. A chat
window is not a world: it is still for minutes at a time. The Linux window
presents 60 frames a second while nothing changes (measured with
`UI_HOST_TRACE=1`). I did not measure what that costs in power, and the
Mac host does the same.

The research's `coaxial_quiescent()` (is anything scheduled?) is the
export that fixes this: a host that knows nothing is scheduled can stop
drawing until input arrives. The same export is what `clock settle` needs.

### 6. The retained tree moved forward, without the reason being written

The research's review moved the retained tree to phase 8 (last but one),
because the layout trace already answers `tree` and `layout` for realms.
The component spec puts the element table in `core/`, which is first. For
apps that is right: an app has no layout trace. But the spec should say it
is overriding the review's order, and that the table must answer the
driver's `tree` in the same format the trace does.

### 7. Process: apparatus was added

Exact's rule, which the research admired: agents remove apparatus freely
and add none, and a spec needs an implementer and a date. Today added a
roadmap, a spec, an issue with 24 boxes and a planned check tool
(`components-check`). None of the spec's phases has an implementer or a
date. The owner asked for the roadmap, the spec and the issue, so they
stand; the missing dates are the part to fix.

## What the research wanted that today's work does not touch

| Research item | State today |
| --- | --- |
| Driver on the web (phase 1) | Exists (`coax/web/drive.coax`) |
| Agent clock (phase 2) | Not landed, by `drive.coax`'s own header |
| Drive scripts (phase 3) | Not landed, by `coax/start-here.md` |
| Field-by-field state carry (phase 4) | Not checked today |
| Deeds as agent tools (phase 5) | Not checked today. The session record in `coax/lib/agent/session` is where an app's tools would be declared; nothing declares one |
| The on-ramp (phase 6) | `coax/start-here.md` and `coax vocab` exist |
| Mac and iOS drive hosts (phase 7) | Not started. Linux was added today without one |
| Retained tree with flex (phase 8) | The tree is specified; flex is not |
| Baked first frame (phase 9) | Not started. For the desktop app it matters little: its first picture takes a quarter of a second |

Two things Exact has that neither the research nor today's work plans:

- **Accessibility on native hosts.** Exact gets it from platform controls,
  and vendors AccessKit on Windows. Our Linux and Mac hosts expose
  nothing to a screen reader. The element table in `core/` is the data a
  bridge (AT-SPI on Linux) would read.
- **Checks at the largest text size, in light and dark, at two widths.**
  The skins make light and dark cheap. Nothing plans the text-size check.

## Recommendations

In order. The first two should happen before any more checks are written
against the Linux host.

1. **The shared hosts answer `coax drive`, and `--do` goes away.** Put the
   driver's socket in `apps/shared/host/linux/ui-host.c` once, so every
   app on that host gets it. The operations call Coax exports, as the
   research says, so answers agree across hosts. Then port the Mac host
   and delete both step languages. Add this to the roadmap's Step 1 and
   to #13153.
2. **Every component row has a stable id, and targets are ids.** Build the
   element table in `components/core/` before the second set of
   components, and make it answer `tree` in the layout trace's format.
3. **The host owns an agent clock.** A mode in which frames advance only
   when the driver says, with the pinned seed, locale, zone and epoch the
   research names. On the native hosts this is small: one place passes
   `dt`.
4. **Decide layout now.** Recommended: add the research's flex subset
   (block and flex, CSS names, checked against Chrome) as
   `components/layout/flex.coax` before the game HUD set moves. Keep the
   chat set's arithmetic until then. Whichever way, write the decision
   into the spec.
5. **Compare in text first, pictures second.** One set of pictures for
   every host that uses the Coax rasterizer (Linux and Android draw the
   same glyphs from the same code), a separate set only for hosts that
   rasterize themselves, and node-by-node text comparison as the default
   check.
6. **Draw when something changed.** Add the quiescent export to the
   components' frame contract and have the hosts wait for input when it
   says nothing is scheduled.
7. **Put an implementer and a date on each phase** of
   `components/spec.md` and each step of the roadmap, or cut the phase.

## What was done about it (2026-11-10, later the same day)

- **Recommendation 4, layout: decided and built.** Flex with CSS's names,
  in Coax, with Chrome as the oracle: `components/layout/flex.coax` and
  `components/gallery/flex-chrome.coax` (200 trees, 1,136 boxes, every
  rectangle within 0.05 px of Chrome's). The decision and the subset are in
  `components/spec.md`, "Layout: flex". Nothing uses it yet.
- **Recommendation 6, draw when something changed: done in the Linux
  host.** `apps/shared/host/linux/ui-host.c` compares each frame's vertices
  with the last one it presented and draws only when they differ. An idle
  focused window presents 2 to 4 frames a second (the caret) where it
  presented 60, and an idle demo window used 0.43 s of CPU in 8 s where it
  used 0.73 s in 6 s. This is the host's own comparison; the `quiescent`
  export, which would also let the app's frame be skipped, is not built.
- **Recommendations 1, 2, 3, 5 and 7 are open**: `coax drive` on the native
  hosts, ids on every component row, the agent clock, text comparisons, and
  an implementer and date on each phase.
- **Found on the way:** replacing the Coder Browser with Chrome had broken
  the repository's headless tools on `coderos-4080` (`shot`, `drive`,
  `clip` said "no headless Chromium"). `coax/lib/net/cdp.coax` now finds
  Chrome behind the launcher.
