Files in this folder:

- `README.md`: this narrative and its tables.

Times are UTC; the owner was on US Central time (CDT = UTC-5), shown where it helps. "Owner" is the human; "coordinator" is the main Claude Code thread.

## Lessons

### What slowed things down

- **Disk, not compute, was the binding constraint.** Each worktree agent carried its own checkout plus a Rust target dir; with 10-17 agents running, free space collapsed eight times and twice made agents refuse work. Cleanup was reactive, and one aggressive pass deleted a live agent's worktree.
- **The "no big builds in subagents" rule moved integration onto the coordinator.** It protected disk and CPU, but agents handed back uncompiled commits on branches, so the coordinator spent hours cherry-picking, resolving conflicts (generated route maps, `chat.rs`, sign-in vs. Cloud teardown) and building `openagents-web` serially. Many owner-visible fixes waited in that queue.
- **Staging and production lagged far behind main.** By release morning production was 288 commits behind; the first staging deploy and smoke suite came mid-afternoon, and production went live in the evening. Earlier, routine staging deploys would have surfaced the Vercel credit problem and the account-storage gaps sooner.
- **Leftover background watchers created noise.** About 300 completion notices arrived, many from agents' own wait loops being killed (exit 144) after the real work finished, each needing a "nothing changed" reply.
- **Main-thread context filled twice** (about 967k tokens each time), mostly from long status reports and integration output.

### Repeated owner corrections (paraphrased)

- **Layout details had to be repeated.** The spinner and its label on the same row came up at 05:09 for "Working" and again at 14:11 for "Loading your repositories", with the owner asking not to have to say it again. Vertical centering, duplicate download buttons and breadcrumbs were similar one-off catches.
- **No internal or AI-flavored wording facing users.** "Machine talk", verbose or odd answers, and the "one open agent" contradiction were each flagged, and each led to a sweep or guard test.
- **Every how-to needs an action:** a link or a single command, never bare instructions.
- **Recommend and act, don't offer menus.** At 14:14 the owner quoted a hedged "if you'd like..." suggestion back and asked for a decision.
- **Don't ship what isn't real.** The sample plugins without evals, half-built mobile tabs, the fake API-key sign-in and a separate "microcoder" download were all cut or folded in.
- **Accuracy about the company.** Jev listed as our product, privacy and training claims, and model names in answers all needed correction.
- **Test before claiming fixed.** The audio fix was reported done twice before it was right; the owner had to check it each time.

### Coordination patterns that worked

- Issue-per-agent fan-out with a claim step, a standard prompt (rebase, persistent target dir, lean tests, no deploys, push to main) and NEEDS_OWNER.md for owner-only steps. The first 8 hours closed most of the ENV, BYO, WEB and compute backlogs.
- Large migrations split by a parent agent into forks (UI-10/UI-11 into per-file forks, copy sweeps per surface, Kitchen Sink extraction into eight chunk agents).
- Read-only audit agents in parallel (four release audits in under five minutes; UI stack audits per platform) before committing to a plan.
- A standing "Verse lane" agent relaunched as each one finished, so Verse kept moving without owner attention.
- Board Status synced from issue state (#11108) once drift was noticed.

### Suggestions for the harness and workflow

- Budget disk per agent: a shared, deduplicated build cache (or a fixed pool of N target dirs leased to agents) plus a disk floor that blocks new launches, instead of reactive cleanup.
- Never delete a worktree whose agent is still running: check the task registry before removal.
- Give integration its own lane: one agent (or CI) that owns building and landing `openagents-web` commits from branches, so the coordinator stays available to the owner.
- Kill an agent's background watchers when it hands back, so a finished agent sends one notice, not several.
- Deploy main to staging continuously, with the smoke suite and a provider-credit check, so production readiness is known before launch day.
- Turn repeated corrections into checks: a UI test for spinner/label alignment, the machine-talk guard, and a chat golden that blocks listing outside products as ours.
- For media fixes, measure against an independent reference before reporting done.

## Method

Scripts streamed the main JSONL and every subagent JSONL. Owner messages are `user` entries with human origin plus queued commands that are not task notifications or agent hand-backs. Agent rows join each `Agent` tool call to its result (agentId), its completion notices and hand-back messages, and its transcript file. Commits count only if a short hash in the agent's report, or a range in its `git push` output, resolves to a commit on `origin/main` in the window. Topics were assigned by hand for owner messages and by description patterns (with a few manual fixes) for agents. Secrets, the owner's contact details, private project names and private file contents were left out, and the output was swept for key and token patterns before commit.
