# Aggregate traversal budget

The unmodified fixed-base adapter loads both the actual page and native `#run` tables. With `--run-steps 250000000`, a 0.20.0 stage-zero prototype of the new meter evaluated it in 166,665,133 existing steps and 9,407,001 aggregate visits, using at most 38,376 tracked aggregate slots. The new independent visit cap is 134,217,728 per frontend evaluation or check; it leaves the existing step limits unchanged. The machine-readable timing report is alongside this note. It is a workload measurement, not a wall-time or total-RSS bound.

The resulting checked C has SHA-256 `3ce04066439e4253a59efec814b559c896225c39e3eeae985426baa608570dca`, identical to the previously tested output with the same no-header options. The independent fixed-base oracle test was also run with the bounded prototype before the final literal-initialization and scalar-exclusion accounting was added: checked and release profiles compared every generated table entry (768 total) and all boundary scalars against the pinned libsecp oracle. The later accounting changes produced identical checked C; they did not change emitted arithmetic. Prototype compiler SHA-256 after that change: `6f302ad96eb34799441d63b53c21f4393a57896d577721e526a2e1f389bff1f1`. The oracle library artifact is `8c46f911b6821f9fc0de66a55d50b11325e364cf64afd95ca6ab0b7f2882201b`. This does not approve secret production use or close the separate source-audit task.

A separate 100-by-10,000 copy fixture used 10,915 expression steps on both the 0.20.0 compiler and the prototype, with 1,010,100 visits reported by the new meter. The focused tests exercise real million-element copies without changing their expression-step count; actual frontend and check failures at the full limit and later-check recovery; and ASan/UBSan boundary tests for nested copy, assignment, view detection, struct defaults, array and struct literal writes, partial cleanup and frozen-expression rollback. The meter charges before each aggregate value/field visit, but does not charge independent scalar reads or assignments. Cleanup itself is not metered; live slots, live containers and the weak-storage registry bound a single retained aggregate cleanup, while AST traversal, string comparisons, host allocations and total process resources remain outside this limit.

With the final prototype, the unchanged Nostr JSON graph passed 20 checks, the event team's explicitly frozen `ee3b610f68ecfaf16458e296ed63d8ca50ce32f5b8eb1f6ad7215c369d7e94c3` graph passed 180, the scheduling/reference comparisons passed 10, and the existing owned-string suite passed five. These are consumer compatibility checks, not the event mutation gate or a production-secret assessment.

Both the checked and release C and their generated header were compared byte for byte between the oracle-tested prototype and the final narrowed-meter prototype.
