# Mutation scheduling: comparison and limits

For queue task #4a8a, the complete `coax/lib/crypto/secp_group.coax` mutation run was compared on the same source graph with the original full scheduling and the selective scheduler. All 847 mutants and their first killing check matched; both reported 847 killed. The full runner invoked 12,182 mutant checks; the selective runner invoked 1,486 and skipped 10,696. Observed wall times were 378.31 seconds and 45.79 seconds respectively on a shared, busy machine, not a controlled performance guarantee. The input root SHA-256 was `b80d001e7f03a15c6dd7951c2b2c016305653c7755636b53cbc69b0cc00a1b1c`.

The full reference used the pre-policy-bridge prototype (`9ed563b85bd1f026834613a07378697a130ae878cab55a3696dab13d2fa1fc1e`), whose full runner is unchanged by the subsequent policy move; the selective comparison used `2e3a2570eaa65544d40c45652b066fb11bf991cfde9e998f99dba5017895e12e`. The full and selective stdout both hash to `4116125a8202a1432b3d4647b320e1d81623332f675e86813410ce78001b854a`; each `mutation-outcome` trace line matched. Full and selective stderr hashes, including timing and counters, were `5301c2474d97cf78c40d094ebc753b7447c7dd909e6e8d9381c174248d128830` and `71b85cf45009fca1242b7affa1ede62a464ca0790cb7104ada2d9805169f583f`.

The Nostr hex graph has a string cast: both automatic and forced-reference runs used the full runner, ran 101 checks and produced identical outcomes for all 92 mutants. Tests also compare individual outcomes on synthetic graphs, dead paths, quantifiers, view-containing aggregates, and actual crypto and Nostr inputs. They cover resource exhaustion and the constant evaluation marker's restoration after an interrupted evaluation. The checked Coax scheduling policy has 5 check groups and 41 killed mutants.

Isolation depends on current compiler behavior: constants, defaults and compile-time execution are folded before mutation, checks cannot mutate global state, and tracked storage returns to its starting count. View-containing aggregates, string casts and unknown graph elements trigger full scheduling. It is not a proof about host allocation failure or external memory pressure. The event graph contains string casts and therefore still uses the full runner. Future lazy evaluation, reflection or global state must trigger a fresh isolation review.
