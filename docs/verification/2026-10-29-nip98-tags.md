# Bounded public NIP-98 tag extraction (#db7e)

`coax/lib/nostr/nip98-tags.coax` reads a JSON tag-array string and copies the
selected `u`, `method` and `payload` values to caller buffers. The input is
bounded to 262,144 bytes, 2,000 tags and 16 values per tag, matching the
current event reader. Selected tags must have exactly two string elements.
Duplicates are counted and the last value is retained; the separate
`nip98-observe.coax` observer must reject ambiguous counts. Unknown tags are
ignored. A refused parse can partially modify the output buffers.

This parser accepts an arbitrary caller-supplied tag array. Its `valid` result
is **not** an event ID or signature check, source binding, authorization,
replay protection or proof of whole-event Unicode admission. In particular,
it does not decode unknown tag strings: an escaped lone surrogate in an
unknown name or value can still yield `valid`. A selected value with that
surrogate is refused. The existing Coax event verifier's whole-event
admission refuses the invalid Unicode before its tags can be used. Any future
adapter must derive the tag-array span from the same successfully verified,
unchanged original event, apply all whole-event rules, and use the result
only under its own reviewed authorization and replay policy.

The caller must supply truthful overlap information, physically valid views,
live immutable input throughout parsing and disjoint writable buffers. These
are interface obligations, not guarantees established by a boolean.

## Source-bound wrapper remains incomplete

A separate experimental wrapper attempted to verify the actual original event,
parse its tag span and hash the actual body in Coax. Its valid-signature
`#test`s hit the compiler's fixed **20,000,000-step per-test** limit
(`E0400`), even with `--run-steps 250000000`. The run reported 190 passed
and 2 failed checks; it is not a pass. Its exact
[unmerged source, fixtures and diagnostic log](data/nip98-source-e0400-20261029/)
are retained as evidence, not shipped as executable code. The original
wrapper source SHA-256 was
`f4512dc5303c7f407b81ee928c4e067ce71a8570a87a27a5636a798e25e5aeb9` and
its log SHA-256 was
`570a6aa38e26a3e593d25748ab99c2b3e8fca6d55c240276efecd1e1295d9f65`.

No Coax source-bound NIP-98 API adapter, request-body hashing bridge, live
request comparison, replay protection, session logic or production cutover is
completed by this slice. The project task remains open.
