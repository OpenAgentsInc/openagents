## Rules

- **Challenge frame.** Exactly a two-element array: the string `AUTH` (any
  JSON spelling) and a string challenge. The challenge is 1 to 256 bytes
  after unescaping. The frame is at most 4096 bytes, whitespace included.
  Anything else is `N42_FRAME` and changes nothing. A new challenge replaces
  the old one and records the connection generation it came on.
- **Relay URL.** The scheme is `ws://` or `wss://` in any case. The host is
  `[A-Za-z0-9.-]+`, lowercased. Bracketed IP literals and user info are
  refused. A port is 1 to 5 digits with a value from 1 to 65535. It is
  compared as a number and dropped when it is the default (443 for wss, 80
  for ws). The path is printable ASCII (0x21 to 0x7e) without `?` or `#`. It
  is kept as written, so case and percent escapes are not changed, except
  that trailing slashes are removed. Queries and fragments are refused. The
  input is at most 256 bytes. A relay tag matches when its canonical form
  equals the relay's own. So `wss://relay.example.com/`,
  `WSS://Relay.Example.COM:443` and `wss://relay.example.com` are the same
  relay, and `ws://relay.example.com` is not.
- **Template.** `nip42_template(n, gen, now, buf)` returns event_sign's
  inputs: `created_at = now`, which must be between 0 and 2^53 - 1;
  `kind = 22242`; `tags = [["relay",<canonical url>],["challenge",<challenge>]]`
  as raw JSON written into `buf` with NIP-01 escapes; and `content = ""`. It
  refuses another generation (`N42_STALE`), no challenge, or no URL.
- **Relay-side check.** The event's id and signature must verify through
  `nostr_event_verify_vartime`. Then, in order: the generation is the
  current one, there is a challenge and a URL, the kind is 22242,
  `|created_at - now| <= 600` s (inclusive), there is exactly one `relay`
  tag and exactly one `challenge` tag (each with exactly one value; other
  tags and empty tags are ignored), the relay tag matches, and the challenge
  equals the current one byte for byte after unescaping. The public key is
  returned only on `N42_OK`. Content is not looked at. Admission proves only
  that the connection holds the key. It grants no channel or host-operation
  authority.
- **relay.coax adapter.** `nip42_input(r, n, gen, frame)` records the
  challenge only when relay.coax takes it (`RL_AUTH`), so the two machines
  never disagree. It returns -1 for a frame that isn't a challenge.
  `nip42_send` refuses an event that doesn't read (bad id or JSON), a stale
  generation in either machine, or an event that fails the same check the
  relay applies. Only then does it write the frame and call
  `rl_auth_sent(id)`. relay.coax already resets AUTH on reconnect and
  retries an auth-required subscription once per connection.

## The event_sign interface coded against

From openagents-d7 (not on main; not read from its worktree):

```
nostr_event_sign_step(key:[]u8, aux:[]u8, created_at:int, kind:int, tags:string,
  content:string, work:[]NostrSignWork, scratch:[]u8, out:[]u8, overlap:bool) -> int #export_c
```

It is a resumable step machine. The caller repeats the call with the same
arguments while it returns `EVENT_MORE` (0). It returns -1 when it refuses,
or the length of the signed event JSON in `out`. `tags` is the raw JSON
array, copied verbatim. `Nip42Template` carries exactly `created_at`,
`kind`, `tags` and `content`. The wiring loop is in the header of
`nip42.coax`.

## Checks

- `coax test coax/lib/nostr/nip42.coax`: 48 checks, all passing: 15 of its
  own, plus relay.coax's 13 and json.coax's 20, which it loads. Its own cover the
  spec example; the challenge frame relay.openagents.com really sent
  (`fixtures/coax_relay.coax`); a 24-case URL table, including a check that
  the canonical form is a fixed point; every refusal path; the bounds
  (challenge 256/257, frame 4096/4097, URL 256/257, window ±600/±601, time
  0 and 2^53 - 1); escapes; the adapter against relay.coax through
  challenge, AUTH, OK, retry and reconnect.
- `coax test coax/lib/nostr/nip42-event.coax`: 214 checks, all passing
  (including event.coax's). The template's tags are byte for byte the tags
  of the independently signed fixtures `N42_FX_TEMPLATE` and
  `N42_FX_ESCAPED`. The send path is checked with the signed fixture, a
  tampered id, bad JSON and a wrong kind. Admission refuses a tampered id.
- `coax test coax/tests/nostr/nip42_signed_checks.coax --steps 1000000000`:
  219 checks, all passing (5 of its own, plus everything nip42-event.coax
  loads). Real signatures are admitted: the spec example (with its
  key), another URL spelling with extra tags, the escaped challenge, and an
  empty tag. Validly signed events with a wrong kind, two challenges, two
  relays, no relay tag, or a short or long challenge tag are refused. So are
  an old challenge, another relay, another generation and 601 s of drift.
  One schnorr verification costs about 76M interpreter steps, more than
  the 20M default per check, which is why these checks live outside the
  mutated files. `coax mutate` has no `--steps`.

## Mutation

Run as `coax mutate FILE --jobs 3 --shard I/3`, merged with `--merge`, on
the final file contents, with no `// mutant: equivalent` lines.

- `nip42.coax`: 1940 mutants, 1940 killed, 0 survived.
- `nip42-event.coax`: not finished, so the file is not on main yet. It has
  only a few mutation sites, but `NostrEvent` holds a string view, which
  forces the full runner. Every mutant therefore reruns all 214 checks it
  loads, including event.coax's 184. At host load 70 to 140, one shard
  (`--jobs 3`) and then four shards (`--jobs 1` each) all hit the 900 s cap
  (exit 124) before writing a record. Its checks pass (214/214), and so do
  the signed checks that load it (219/219). It stays committed but unpushed
  in the claude-nip42 worktree until a mutation run finishes with zero
  survivors. That needs a quieter host, or more shards with a longer cap
  per shard on another machine.

Three survivors on the first run were restated rather than exempted. A test
helper's `&&` was inlined into its check. The path loop now iterates bytes,
since path[0] is always `/`, so starting at 1 could not be observed. The
frame's string limit is now the frame limit, since a larger string limit
could not be observed under the 4096-byte frame bound. Equivalences of the
"every refusal path ends the same" kind were avoided by giving `nip42_url`
distinct result codes.

## Addendum: the glue is not `#authority` (main session, 2026-10-29)

`nip42-event.coax` decides nothing: it extracts fields from `nostr_event_read`
and `nostr_event_verify_vartime` and passes them to `nip42_admit_fields` and
`nip42_send_fields`, which make every decision and are mutation-tested in
`nip42.coax` (1,940/1,940). As `#authority` it pulled `event.coax` and the
Schnorr verifier into its mutation run; 16 single-mutant shards and the
earlier 5 attempts all hit the 15-minute limit before writing a record. It is
now an ordinary unit, like `psionic/lib/pylon/host.coax`. Its 214 checks pass
(23 s), and the real-signature checks in `nip42_signed_checks.coax` (219/219,
`--steps 1000000000`) are unchanged.
