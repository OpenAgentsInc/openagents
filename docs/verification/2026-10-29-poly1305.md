# Poly1305 primitive, initial evidence

This is a bounded one-shot Poly1305 authenticator, not an AEAD or a complete
NIP-49 backup. It is not approved for production secrets. The internal ABI
requires a fresh one-time key for each message; callers must never reuse it.
The internal ABI
requires valid views and a truthful overlap observation. Temporary key and
accumulator values are not proven erased. The source's public-loop structure
and masked reduction do not prove machine-code or target side-channel behavior.

The implementation uses five 26-bit limbs with explicit clamping, carry folds
and canonical reduction. For valid normalized inputs, the pre-carry products
are bounded below 2^58; the arithmetic and caller preconditions need ongoing
independent scrutiny. The RFC 8439 section 2.5.2 and appendix A.3 examples,
explicit modulus boundaries and carry propagation checks pass. All 321
mutants in the loaded graph were killed.

An optional source-hash-pinned Z3 check (`poly1305_bounds.py`, Z3 5.3.2)
found no unnormalized limb after three modeled carry rounds for arbitrary
nonnegative products below 2^58. Its two-round negative control found a
counterexample. This checks a hand-authored model, not a mechanical proof
that emitted code or caller assumptions match the model.

The arbitrary-precision reference in `coax/tests/nostr/poly1305.py` checked
1,027 inputs per checked and release native and Wasm profile, including a
1 MiB message; 110 inputs also
matched OpenSSL 4.1.0's Poly1305. Native refusal paths passed ASan/UBSan, and
the generated code compiled for arm64 iOS Simulator. This is not an iOS
execution or physical-device result.
