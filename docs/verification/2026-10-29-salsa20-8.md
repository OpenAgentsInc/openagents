# Salsa20/8 primitive, initial evidence

This is a u32 word core; scrypt must adapt bytes using little-endian order.
It is one component of optional NIP-49 key backup. It does not implement
scrypt, XChaCha20-Poly1305, password normalization or encrypted key import.
It is not approved for production secret use. The internal ABI assumes valid
views and a truthful overlap observation; a public host adapter must establish
those facts. Its value temporaries do not establish secure erasure, and source
checks do not establish machine-code side-channel behavior.

The Coax tests include the pinned RFC 7914 section 8 vector and transactional
refusal at short input, short output and overlapping views. All 181 mutants
were killed. `python3 coax/tests/nostr/salsa20_8.py` runs 2,002 deterministic
inputs per checked and release profile against an independently structured
arithmetic model on native and emitted Wasm. Native boundary cases run with
ASan/UBSan; Wasm also checks short views, reported overlap and output tails.
Both profiles also compile for the arm64 iOS Simulator;
this is a compile check, not an iOS execution or a physical-device result.

This run used coax0 0.22.0 (`9857663bf2c87462d9acdd09b118c9a3e298a3a9caa43ab842dfeabedcce0cd7`),
source `315fc51b00354f48bd45781675e0017bf8564f895b837933cbf27d663e4df816`,
and pinned RFC `df55932f8b6a5d271f36a634d91a25903724e189ba6c120bf7257cd47f10b197`.
The checked and release generated C was identical
(`405e81efb303b95a639c13899120fe7939bc13c955fd3ff5408b966d425539dd`),
as was the Wasm (`2a98521574511edeb54986e463e8b916c98a50036ba0c0f1f8a582927745ad49`).
The host was arm64, with Homebrew clang 23.1.4, Node 26.12.1 and iOS
Simulator SDK 26.5. The independent review covered the word arithmetic and
admission path, not target-side timing, erasure or production deployment.
