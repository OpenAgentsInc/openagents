# Experimental BIP-340 fixed-base point preparation

This Coax slice uses the generated seven-tooth fixed-base table, converts the
projective result to 8×32 limbs, applies the separately reviewed field inverse,
and derives affine x, y, finiteness and y parity. It assumes the point is
canonical and generated by the trusted comb; `sp_affine` is not an arbitrary
point validator. `sp_x` requires disjoint live output and does not assert that
the point is finite. The eventual signer must bind the point's finite/parity
values to its staged result and publication decision.

The explicit point workspace is caller-owned and requires a real wipe. Secret
scalar/point values, inverse implementation arrays, ABI/compiler copies,
stack/register spills, original input/output, crash handling, target timing and
physical devices remain outside that wipe. The fast-field source audit belongs
to a different ECDH root and is not a signing-entry audit. This is not a signer
or production-secret approval.

All 102 loaded Coax checks and 1,799/1,799 full mutations passed without waivers.
The actual compile-time generated table used an explicit 250,000,000 aggregate
step cap; individual checks retained their default bound (the real scalar-three
point check used 9,553,360 steps). Checked/release native and actual Wasm each
passed 1,009 fixed-base inputs against pinned libsecp, including zero, order
boundaries and infinity; the first 32 were also checked with an independent
Python elliptic-curve model. Test-host workspace wipes were observed. Native
ASan/UBSan exercised one case; each iOS 26.5 Simulator profile executed scalar
three and infinity. The vector run preceded an odd-y test and comment-only
clarification; runtime procedures were unchanged. Independent source review of
SHA-256 `98ab2e2ab9f4f90f2ae0333e8f340705b2a99520a717efa7e6139876d5b1f69e`
found no concrete affine-algebra blocker under those premises; it did not rerun
the tests or approve target behavior. The pinned libsecp oracle binary SHA-256
was `8c46f911b6821f9fc0de66a55d50b11325e364cf64afd95ca6ab0b7f2882201b`.
