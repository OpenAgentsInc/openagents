# Resumable NIP-49 scrypt composition, initial evidence

This experimental composition runs one-iteration PBKDF2-HMAC-SHA256, resumable
ROMix with `r=8, p=1`, and PBKDF2-HMAC-SHA256 again to derive 32 bytes. It
accepts a 16-byte salt and `log_n=1..18`, subject to caller-provided memory
up to 256 MiB. The caller supplies NFKC-normalized password bytes; normalization
is not implemented here. The low costs are useful for interoperability tests
and do not constitute password-hardening recommendations.

The caller must provide stable, disjoint, untampered state and scratch and
truthful pointer/overlap observations. Password, intermediate data and ROMix
scratch are not proven erased on success, error or cancellation. There is no
public pointer gate, cancellation, device validation or production-secret
approval. ROMix's password-dependent scratch indexing is deliberate and is
not a constant-time memory-access claim.
The step budget limits iterations rather than wall-clock latency. A refused
start preserves any existing state, and an internal failed step can invalidate
ROMix without erasing state or scratch. Shape checks do not authenticate a
restored state.

The small end-to-end vector matches OpenSSL-backed `hashlib.scrypt`, and all
1,434 mutants in the loaded Coax graph were killed. The
independent test `coax/tests/nostr/scrypt_nip49.py --nip49-native` checked
16 small inputs per checked/release native and Wasm profile, and separately
matched a full `N=65536, r=8` 64 MiB native operation in each profile. Native
ASan/UBSan and arm64 iOS Simulator compilation passed; no iOS execution or
physical-device result is claimed.

The run used coax0 0.22.0 (`9857663bf2c87462d9acdd09b118c9a3e298a3a9caa43ab842dfeabedcce0cd7`)
and wrapper source `a8de301973adae60ca3af1e4bc81b9e57ee06c59c5e68e6fa92c5dcb411dee14`.
Checked C and Wasm SHA-256 values were
`702f02dcf340e89672325041385beb86b3748c9edf1c2d9e2487e3403cf26876` and
`150b34c771fe0d9c1b6ac6d9c2e03c5725253baf3a61d4bf8494ac8a517f75f5`;
release values were `eabbb304a25898657da6c044f828e0688a4822d2fe8e25ae8df354ea5b87cea9`
and `c8b68d256e3865f1274f785759e7cbcd6390c0499011f3c95a3de984fcbe3411`.
The run used arm64 macOS, Homebrew clang 23.1.4, Node 26.12.1, and iOS
Simulator SDK 26.5.
An independent source review found no concrete composition or state-transition
blocker within the documented premises; erasure, target timing and production
use remain unapproved.
