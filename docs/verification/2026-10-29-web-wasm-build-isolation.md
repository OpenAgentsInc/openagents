# Parallel Wasm build isolation

A site release of `3284c9665d` failed to link Everglade before staging promotion. Clang reported tens of thousands of null bytes in its generated `Player.c`, followed by missing player exports. The world build launches Realm, Garden and Everglade concurrently, and each previously wrote and compiled `build/.c/Player.c`, `Player.h` and `Player.o`. The three builds could truncate and replace the same files while another compiler was reading them. Builds to the same output also shared the `.wasm.tmp` path.

`wasm.sh` now uses a fresh per-invocation temporary directory for generated sources, headers, objects and the linked output. The final move remains atomic. A deterministic regression launches three real script invocations with shared libraries and overlapping output names. It failed against the old script (a competing process moved the shared temporary output) and passes with separate intermediate paths. Actual Realm, Garden and Everglade release-mode Wasm builds also passed concurrently using the same source libraries. The normal web build runs this regression before launching parallel worlds; no release smoke or visual gate was weakened.
