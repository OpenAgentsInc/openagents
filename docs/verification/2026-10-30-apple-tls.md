# Apple TLS for native Coax relay clients — 2026-10-30

Apple native relay TLS now uses Network.framework and Security. The reusable
Coax relay connection uses the portable `cxtls_connect` effect, without a
throwaway TCP connection, OpenSSL on Apple, plaintext fallback or verification
bypass. The existing Linux OpenSSL backend remains supported.

## Native contract

`tls-native.c` includes `tls-apple.inc` only on Apple. Network.framework owns
TCP, TLS record processing and TLS 1.2/1.3 negotiation. Security applies
`SecPolicyCreateSSL` for the DNS name and `SecTrustEvaluateWithError` for the
chain, expiry and name. Certificate-controlled network fetches are disabled;
the peer must supply its intermediate certificates. SNI is set explicitly.
The platform APIs' [server-name verification](https://developer.apple.com/documentation/security/sec_protocol_options_set_tls_server_name(_:_:))
and [TLS configuration](https://developer.apple.com/documentation/network/security-options)
remain native effects; Coax owns URL choice, WebSocket framing and relay rules.

`cxtls_connect` consumes a bounded TLS host builder and owns TCP plus TLS under
one deadline. Handles are opaque; Apple has sixteen TLS slots independent of
the plain socket slots. The bridge has one API caller thread per process.
The existing `cxtls_start` descriptor upgrade remains Linux-only; every
portable relay call site now uses connect. No platform-private APIs or
deprecated SecureTransport are used.

Callbacks run through a serial queue with generation-fenced static slots.
A timeout leaves one receive pending; the next poll gets its later bytes,
without duplication or loss. Cancelled callbacks cannot change a reused slot.
Sends use an owned copy, so cancelling a timed-out send cannot borrow freed
caller storage. Failed sends must be closed, never replayed as whole messages.
TLS output is bounded at 1 MiB and each received chunk at 16 KiB.

Network.framework reports both TLS close_notify and an abrupt underlying FIN
as receive completion. This was observed in the new native negative check.
Apple therefore returns **`CXTLS_END_UNVERIFIED` (-12)** for either, retaining
the old meaning of `CXTLS_EOF` instead of inventing authenticated completion.
Ordinary Coax polling refuses -12. During the closing handshake only a complete
authenticated WebSocket close record permits it as stream end. `last_read`
retains the native result for reconnect diagnostics. Linux still distinguishes
close_notify (-1) from a truncated socket (-3).

Test anchors exist only in binaries compiled with `CXTLS_TEST_TRUST`. Tests
import their generated public CA without writing any keychain, and anchor
exclusively to it. Production ignores `CXTLS_TEST_CA`. Every fixture key and
certificate is ephemeral, generated locally and deleted; none is committed.

## Qualification

The [retained observations](data/apple-tls-2026-10-30/manifest.json) bind raw
logs, tool identities and the publication source snapshot. Tests were written
first: the native stream check initially failed because `cxtls_connect` did
not exist. Focused checks only; no full mutation or unrelated library gate.

Apple runtime links platform frameworks only. OpenSSL 4.1.0 on the Mac is
fixture-generation/control tooling. LeakSanitizer is disabled on Apple arm64
where unsupported; AddressSanitizer, UBSan and the separate ThreadSanitizer
run are enabled. Linux retains leak checking.

The initial EOF check deliberately caught Network.framework's ambiguity and
led to the explicit -12 result. A first relay test counted the deliberate
unacknowledged-connection drop as a protocol failure; the fixture driver now
uses `last_read` to recognize that precise connection loss while reconnecting.
The Linux TLS-1.1 control also exposed a CLI-status flake after successful
handshake: the control now requires negotiated TLS 1.1 evidence from both
the OpenSSL output and the fixture server, independently of shutdown status.
No product verification or protocol limit was relaxed to make those pass.

## Reproduce

```shell
COAX=/path/to/qualified/coax coax/tests/net/tls.sh
COAX=/path/to/qualified/coax python3 -I coax/tests/net/relay_e2e.py
```

`tls-env.sh` supplies `-fblocks -framework Network -framework Security
-framework CoreFoundation` on Apple and the Nix OpenSSL flags on Linux.
The public probes publish no events and use no Pylon or owner key.
This work qualifies Apple TLS and the reusable client. iOS runtime and
production-secret signer approval remain separate gates.
