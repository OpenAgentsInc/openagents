# Chapter20: independent fleet interoperability

The compiled Coax fleet passed **37 distinct black-box cases** on this Mac
on October30. The frozen ASan/UBSan executable has SHA-256
`6b7049b1e469cb6930f3ea166e02e55138380bcb4064e90b2ba22c6f17d29e54`.
The exact Coax source hashes, native binary hashes, individual HTTP results
and sanitizer observations are in
[`data/oct30-fleet-e2e/qualification.json`](data/oct30-fleet-e2e/qualification.json).

The harness is [`psionic/tests/fleet/fleet_e2e.ts`](../../psionic/tests/fleet/fleet_e2e.ts).
It calls the real `/v1/systemone` HTTP endpoint. Product decisions and
cryptography execute in the compiled Coax runtime. An independent relay
peer uses the pinned Noble and nostr-effect test dependencies; it is test
tooling, with no shipped TypeScript routing or signing implementation.

The native path uses the actual Coax relay under ASan/UBSan, the qualified
native Pylon and a real release `psionic-serve --toy`. A single request
exercises choice, noul and score answers, and must identify the remote
Pylon and the exact advertised toy identity. An intentional1.5-second
engine delay proves a shorter fleet deadline refuses the late response.
After the Pylon stops, a second request succeeds through the same-identity
local Coax engine and identifies its `psionic` door.

The remaining cases check:

- AUTH and subscriptions before a job; normal remote success, a result
  before positive ACK, refusal when a result precedes a negative ACK,
  provider failover, and a prior provider's late answer during another
  attempt.
- Stale, draining, full, identity-mismatched and generation-superseded
  beacons; publication/subscription refusals; a provider that never answers.
- Invalid signatures and wrong provider, job tag, recipient, request,
  attempt, model, full identity, door, question or probability/confidence.
  None becomes an HTTP200 result.
- Exact-identity local fallback, different-identity refusal, request-model
  admission before either dispatch, and a slow fallback bounded by the
  total deadline.
- Local HTTP status2000, conflicting duplicate Content-Length,
  Transfer-Encoding, absent length, a truncated declared body and an
  unframed trailing body. Each is refused despite carrying an otherwise
  plausible answer.

Qualification used two scoped runs against the **same frozen binary**.
The initial pass completed25 cases before the next case's100ms discovery
window elapsed without AUTH. The HTTP listener being ready does not mean
the relay is ready. The harness now waits for AUTH and both subscriptions
before the HTTP call, then uses the default500ms discovery budget. Only
the failed/remaining12 cases were rerun. The CLOSED refusal case was also
checked once through the changed readiness helper. The initial failed run
is retained alongside the correction; no runtime code or answer-acceptance
expectation changed, and completed checks were reused.

There were no ASan/UBSan reports in the native logs. Fleet and relay were
sanitized; Pylon and engine used qualified plain/release binaries, as the
record explicitly states. This is loopback interoperability evidence. It
does not prove signer side-channel safety, host key wiping, public TLS
deployment, a production identity, payments or arbitrary-model correctness.
The public-relay rehearsal is recorded separately by the demo owner.
