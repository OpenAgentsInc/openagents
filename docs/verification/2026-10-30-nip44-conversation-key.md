# NIP-44 v2 conversation key from two keys (#4878 nip44-v2, ECDH part)

`coax/lib/nostr/nip44-key.coax` (`#authority`) finishes NIP-44 v2's
`get_conversation_key`: HKDF-extract with salt `nip44-v2` over the raw,
unhashed 32-byte shared x, where the x now comes from `ecdh.coax`'s validated
x-only ECDH (task #71e7) instead of from the caller.

```coax
nip44_conversation_key_from_keys_checked :: (secret:[]u8,public_key_x:[]u8,
    work:[]EcdhScratch,out:[]u8,overlap:bool)->u32
```

It follows `nip44.coax`'s style: `NIP44_*` codes, a truthful `overlap` fact for
any two of the four views, and out written only on success. Refusals, in
order:

| Code | When | work | out |
| --- | --- | --- | --- |
| `NIP44_KEY` (8) | secret or public key x is not 32 bytes | untouched | untouched |
| `NIP44_OUTPUT` (9) | work is not exactly one `EcdhScratch`, or out is below 32 bytes | untouched | untouched |
| `NIP44_ALIAS` (10) | `overlap` | untouched | untouched |
| `NIP44_PEER` (13, new) | public key x is not a curve point (no square root, or not below p) | zero | untouched |
| `NIP44_SECRET` (14, new) | secret is 0 or not below n | zero | untouched |
| `NIP44_OK` | | zero | 32-byte conversation key |

`NIP44_PEER` and `NIP44_SECRET` extend `nip44.coax`'s 0..12 and are declared
in the new unit. The peer is checked before the secret because `ecdh_stage`
checks them in that order. After the public lengths and the alias fact are
admitted, every return clears all of `work` (scalar, shared point, affine
point and staged x) with a plain store. Erasure that the target compiler
can't drop is still the host's platform contract (`zeroize.coax`), as in
`nip44.coax` and `ecdh.coax`. This record claims no side-channel or erasure
guarantee.

The function is in its own unit so that its in-file checks stay few. Mutation
mutates the whole reachable graph (nip44.coax's, HKDF/HMAC/SHA/ChaCha/base64,
and ECDH's), and each mutant reruns every check that entered its procedure.
The 35 + 8 + 10 vector rows (about 1.4 billion interpreter steps) are in a
plain test file, `coax/tests/nostr/nip44_key_vectors.coax`, so they don't run
once per ECDH or SHA mutant.

## Vectors

`coax/tests/nostr/nip44_key_vectors.coax` is generated by
`coax/tests/nostr/nip44_key_fixtures.py` (stdlib only, tooling) from the same
pinned `coax/tests/vectors/upstream/nip44/nip44.vectors.json` (sha256
`269ed0f6…`, checked by the generator) that `nip44_vectors.coax` uses.
Regenerating gives the same bytes.

- `valid.get_conversation_key` **35/35** from `sec1`/`pub2` through our ECDH.
  The work starts dirty and ends zero, and out is exact.
- `invalid.get_conversation_key` **8/8** refuse, out unchanged and work
  wiped. All 8 refuse as `NIP44_PEER`. The three rows that mean an invalid
  secret (`sec1` 0, n, above n) pair it with the public x `1234…cdef`, which
  is not on the curve, so ECDH refuses the peer first. The generator derives
  each row's expected code independently (Euler's criterion, then the scalar
  range). The secret refusal itself is covered by the unit's own checks:
  secrets 0 and n against the generator's x refuse as `NIP44_SECRET`.
- `valid.encrypt_decrypt` **10/10** end to end from the two keys: conv(sec1,
  pub2) and conv(sec2, pub1) both equal the row's conversation key
  (**symmetry**, 10 pairs), encrypt with the row's nonce under the first key
  equals the upstream payload byte for byte, and decrypt under the second key
  returns the plaintext. The generator computes pub1 and pub2 from sec1 and
  sec2 with a small affine multiply; the matching conversation keys check
  them.

Unit checks in `nip44-key.coax` (6): metadata refusals (lengths, work count
0 and 2, out 31, alias) leave a dirty work and out untouched; invalid peers
(all-ff, and x = 0, the twist's order-3 point) refuse with work wiped; secret
0 and secret n refuse with work wiped; upstream row 0 succeeds into an
exactly 32-byte out with work wiped.

## Signed-event round trip (added after event_sign landed)

`coax/tests/nostr/nip44_event_roundtrip.coax` (`coax test ... --steps
2000000000 --run-steps 250000000`, 392 of 392 checks including the loaded
suites, 30 s), with test keys from BIP-340 vectors 0 and 1:

- Alice's and Bob's conversation keys from the two keys agree.
- Alice encrypts with NIP-44 and signs a kind 4 event with `event_sign.coax`.
  Bob reads it with `nostr_event_read`, verifies the id and signature with
  the fast verifier, checks the sender and decrypts the content.
- The wrong sender, the wrong conversation key and a changed content byte
  are each refused.

It's a plain test file, not `#authority`: every piece it joins has its own
zero-survivor gate.

## Payload limits and interoperability (2026-10-30)

- **The limit closes end to end** (`nip44_event_roundtrip.coax`, 415 checks
  including the loaded suites, `--steps 8000000000`):
  - An event's content is one JSON string of at most 65,536 raw bytes
    (`ja_policy`). So the largest NIP-44 message an event carries is 40,960
    bytes, a 54,704-character payload. It encrypts, signs, reads, verifies
    and decrypts.
  - At 40,961 bytes the payload pads to 65,628 characters. `event_sign`
    refuses before writing anything (`out` is left all zero), because its
    own reader would not admit the event. Every larger message, up to the
    65,535-byte COMPAT maximum, takes the same path.
- **Interoperability both ways:** Psionic chapter 24's buyer
  (`psionic/tests/pylon/buyer.ts`) uses `nostr-effect`'s NIP-44, an
  independent implementation. It encrypts jobs that the Coax Pylon
  decrypts, and decrypts the Coax Pylon's encrypted answers.
  `pylon_e2e.py` passes over ws:// (52/52) and wss:// (53/53) at
  `fed0a442b2`. All keys are test keys.

## Not done

- **No `#export_c` wrapper:** the public ECDH build goes through the owned
  `coax_ecdh_owned_*` ABI and its lifecycle (`ecdh_lifecycle.coax`). A raw
  export of this function would bypass that contract, so the native and Wasm
  paths for the two-key derivation are left to that ABI's owner.
- **Targets and erasure:** checked in the interpreter only. No native,
  Wasm or iOS run of the two-key path, no target-timing claim, no erasure
  guarantee for `work`, `out` or derived keys.
