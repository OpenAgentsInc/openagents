# NIP-01 feed, iOS 1092

Issue [#13627](https://github.com/OpenAgentsInc/openagents/issues/13627), stage
three of the [Arcade port](../arcade/08-delivery.md). This is the first feed
binary: iOS installs the new read-only operation 20. Older runtimes keep their
existing service inventory and signed update feeds. The browser mounts the
same controller at `/feed` inside the existing site shell.

## Verified behavior

The feed uses saved account relays with explicit selection, verified kind-1
notes, cross-relay deduplication, deterministic ordering, author/hashtag/time
filters, bounded inclusive history and verified author metadata. New live
notes stay behind an indicator while the reader's current list remains still.
No refresh button, signer, public publishing or encrypted messaging capability
is installed by this release. The [contract](../protocol/nostr-app-services-v1.md)
records the precise memory, pagination, custody and SDK limits.

- The portable iOS root passed 983 checks on the build host. The browser root
  passed 676 checks; the subsequently added signed-vector author/time/hashtag
  query check passed separately. Passing unchanged slices were retained.
- The new authority queue passed 137 mutants: 128 killed, zero survivors,
  nine documented equivalent mutations. Explicit tests cover terminal capacity,
  exact byte limits, stale generations, ACKs beyond delivered records, replay,
  serial exhaustion and circular wrap with multiple pending records.
- The existing JavaScript/WebAssembly runtime oracle passed for app/extras.
  Binaryen size optimization keeps the app script inside the existing 8 MiB
  artifact bound. The 32 MiB JavaScriptCore memory bound is unchanged. A real
  fresh-login regression exposed an oversized reset stack frame; clearing
  bounded feed records individually repaired it, and the failed case passed.
- On Christopher's physical iPhone 17 Pro Max, the actual NativeProgram and
  NativeHost read from both `wss://relay.primal.net` and `wss://nos.lol`, observed
  kind-1 originals from both, and displayed verified notes. The independent
  HTTP fixture supplies only the account/settings snapshot; the notes come
  from the real selected relays, and no fixture note is published. The fixture
  uses isolated in-memory credentials and does not change production settings.
- Four distinct physical-phone checks passed: read-only service refusal/clock,
  actual live relay/controller integration, native image-view continuity and
  fresh-login controls. A fifth check passed for stable native reading anchors
  after insertion and explicit scope changes resetting to the top. The live
  test was repeated only after correcting its screenshot to use the actual
  NativeWorkspace projection; both selected cases passed.
- The corresponding simulator slice also passed, retaining the earlier passing
  account/navigation/Markdown cases. An initial live test used Damus, which
  failed TLS on this network; the fixture was changed to the two reachable
  relays above. The product never substitutes fixture relays for saved ones.
- Headless hardware-WebGPU Chrome opened `/feed` through the site shell and
  showed `2/2 relays` and live notes. Invalid author input was actionable.
  Selecting one relay, a 24-hour window and `#bitcoin` showed `1/1 relays` and
  twelve results; selecting an author then showed seven notes from that author.
  Exact filter semantics, forged events, duplicate originals, stale owners,
  equal-time pagination and pending new arrivals have deterministic Coax checks.

Local evidence is under this worktree's `build/feed-*` and
`apps/openagents-ios/build/feed-device*.xcresult`. Attachments include the real
relay receipt and a native UIKit text/layout capture; that capture does not
include the composited Metal chrome and is not claimed as full GPU visual
parity. The Arcade motion catalog and Android qualification remain later
issues, rather than inferred from this feature test.

## Release

Build 1092 is being frozen from the tested source. Archive, IPA, runtime,
signed generation-1 resources and upload receipt are retained under
`~/.openagents/releases/openagents-ios-1092/`. Upload acceptance, processing
and existing Owner-group assignment are recorded separately. Work proceeds
to #13628 as soon as the upload has begun; it does not wait for Apple.
