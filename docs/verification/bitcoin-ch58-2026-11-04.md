# Bitcoin chapter 58 qualification, 2026-11-04

`chainstate.coax` and `chainstate-store.coax` add a distinct validated-v1
profile. Initialization accepts
only the empty state at the actual network genesis. It refuses light metadata;
there is no light-to-validated migration. Chapter 57 checks every block and
script before an immutable replay constructs coins, complete inverses, exact
Core undo chunks, parent-bound receipts and the tip in one atomic KV batch.
No tip or block-index validity is published by preparation.

`blockundo.coax` implements Core's input-undo formatter, including the legacy
version dummy. All 115 root mutations are killed with zero survivors. The
reader handles nonzero old version dummies but does not invent missing
height-zero metadata. The validated writer always retains complete metadata.

Compiler and Core reference provenance are the same as
[chapter 57](bitcoin-ch57-2026-11-04.md). Qualification is native C on arm64
Darwin; no Wasm result is claimed. The full import closure has 701 checks,
including eleven connector models, six storage models and four undo codec
checks. The current source's full authority compilation passes.

`chainstate.py` independently replays a 102-block regtest journey against
actual Bitcoin Core 32.1.0, starting from genesis with no wallet or peers.
The entire UTXO set's MuHash agrees at heights 100, 101 and 102 and after both
disconnects. All 102 actual XOR-masked Core rev bodies match byte for byte.
Both packed and indexed tables pass this journey. Every one of the mature
frame's 1,335 physical cuts exposes precisely the old or complete new table.
The Python oracle's first draft had an incomplete KvOpen ABI declaration;
it was corrected before recording these passing comparisons.

The real Coax file tool independently connects the complete regtest prefix,
refuses a consensus-invalid child without appending, connects its two valid
children, disconnects twice, reopens and restores a torn tail. A well-formed
light snapshot is refused. Each block is a separate durable file commit.
The teaching file tool's fixed buffers are not a full-chain storage policy.

The contiguous mainnet range 170,060–170,063 validates all 50 transactions,
compares exact Core undo and poststates, then restores the exact original
canonical table and MuHash. Its pre-state is the independently supplied
archival context and all touched coins, not a global mainnet UTXO snapshot.
The production API has no corresponding snapshot-import path.

ASan/UBSan checks cover the 35 pinned Core verdicts and 16 historical blocks
(9,523 transactions), checking exact coins, Core undo and full disconnects on
success, and unchanged published state on refusal. The initial binary input
adapter capped raw bodies at four million bytes and therefore locally refused
the intentionally overweight fixture; its I/O cap was raised to eight million
and the six remaining cases were run separately. Passing cases were retained
at that checkpoint. Subsequent pipeline/hash changes were qualified with the
full corpus. No consensus bound was changed.

The historical BIP-30 repeats restore overwritten old coinbases through the
complete inverses. Core-compatible CBlockUndo alone does not carry those
coins; no clean Core reorg across its historical overwrite bug is claimed.

The source, profile, fixture hashes and live Core states are retained in
`bitcoin/fixtures/chainstate/SOURCES.md`. The worked example's debug and
release output matches `bitcoin/fixtures/validated-chain.out` exactly.

The independent storage unit kills all 195 root mutations, with zero
survivors. No equivalent annotations were added. An initial combined shard
reached its automatic 840-second cutoff and was stopped; storage was then
separated from block/script traversal so its gate runs in minutes without
removing the full pipeline's imported baseline checks.

A diagnostic pipeline shard found six survivors, prompting exact maximum
output-script and empty-script spend models, an independent missing-parent
case, and reuse of the already qualified index-extent predicate. Earlier
source snapshots are diagnostic only, never merged into the final proof.

The next first-shard report killed 104 of 105 mutations; its sole survivor
disabled witness decoding in replay. A new pinned signet block-1 model now
checks the full admitted-header, challenge, witness replay and exact
disconnect path. The complete 1/1 pipeline gate against this updated closure
kills all 210 mutations, with zero survivors. No old receipt is presented as
the final result.

All three final receipts merge successfully on the Mac against the exact
current source: 115 codec, 195 storage and 210 pipeline mutations, all 520
killed and zero survivors. The final pipeline run used the verified Linux
compiler from chapter 57, 128 workers and an automatic 840-second cutoff;
it completed within the cutoff. Local diagnostic work was stopped before
15 minutes.

After promotion, targeted checks pass for the registry, chapter headings,
contents/plan, 103-example inventory, 863 exact source listings, local links
and counts (98 implemented, four partly implemented, 23 planned). The full
book gate still stops at the pre-existing `coax.wgsl.current` evidence mismatch
for `verse/everglade/gpu.bindings`; it is not weakened or claimed passing.
The unchanged light path retains its earlier qualification; it is not rerun
or upgraded by this work. Full-node money admission waits for 80, 93 and 118.

Tools-check reports 17 unrelated missing Firm reason headers on the rebased
checkout (15 at the original base, plus `test_room_chat.py` and `raid-cost.ts`).
All new oracle tools carry the independent-oracle reason.
