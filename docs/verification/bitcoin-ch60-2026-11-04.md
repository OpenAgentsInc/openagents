# Bitcoin chapter 60 qualification, 2026-11-04

`chainreorg.coax` integrates the complete block validator, validated coins and
Core undo with the admitted header index. A whole detach/attach path produces
one unsealed KV body. The caller seals, appends and syncs it before publishing
coins and moving the active index to the exact validated cursor. Preparation
may cache completed script checks or stable consensus invalidity; it never
moves the active index. Context, storage, damaged undo and transport/mutation
failures remain retryable. Preferred prefixes permit bounded download work;
they do not grant caught-up or money-admission status.

The concatenator checks both input bodies and their zero sequences, operation
counts and extents before writing anything. Its final portable receipt kills
all 31 root mutations with zero survivors. Chapter 58's unchanged validator,
undo codec and storage gates retain their earlier qualification at
`b05a6eb8b4821125036200feed5f37b62c58ae6c`; those passing gates are not rerun.

Compiler and Core provenance are the same as
[chapter 57](bitcoin-ch57-2026-11-04.md): verified Coax0 0.48.0 on arm64 Darwin
and Linux, and official Bitcoin Core 32.1.0. The Core node uses isolated temp
storage with networking and wallets disabled. No mainnet sync, Wasm result,
physical archive ownership, serving policy or money admission is claimed.

Thirteen new Coax models cover stable failure classification, exact-size extension,
late invalid child and descendant fallback, both fork directions and exact

717 checks. The final mutation baseline checks the complete closure; the
native Core library was built against the earlier 714-check closure, with
identical product source. Three added boundary models strengthen tests only.

and hashes. It runs a complete genesis-to-prefix journey, A102, failed B105
through missing-input B104, fallback B103, damaged A103 and corrected A104.

and the final mutation counts are retained with the receipts below.
