# Coax IETF ChaCha20

Task `crypto-chacha20` (#5fc9), worker `codex-nostr-codecs`, 2026-10-28.

## Contract

`coax/lib/crypto/chacha20.coax` owns the RFC 8439 quarter round, block function,
stream XOR and admission policy. All word addition and rotation use Coax's
explicit `add_wrap` and `rotl`, so checked and wrapping profiles have the same
defined cipher arithmetic. It uses the shared byte helpers and no host RNG,
allocation, I/O, persistent state or foreign crypto implementation.

Public memory-observing wrappers live in `chacha20-memory.coax`:

- `chacha20_block(key, nonce, counter, out)` emits exactly 64 bytes.
- `chacha20_xor(key, nonce, counter, input, out)` emits exactly `input.count`
  bytes. Encryption and decryption are the same XOR operation.
- Both return `ChaChaResult { written, error }`. Errors are `CC_KEY` (1),
  `CC_NONCE` (2), `CC_INPUT` (3), `CC_OUTPUT` (4), `CC_COUNTER` (5) and
  `CC_ALIAS` (6); zero is success.

Keys are exactly 32 bytes, nonces exactly 12 bytes, and the initial counter is
an unsigned 32-bit word. Inputs/output capacities use the shared 1 MiB bound.
All sizes/capacities, the entire required counter range and output overlap are
admitted before writing. The final counter 0xffffffff can process one 64-byte
block; a 65-byte request at that counter refuses. A maximum-size request can
start at 0xffffc000, while 0xffffc001 refuses. This is the IETF counter profile;
counter rollover must never carry into a nonce word.

On every refusal `written` is zero and output is unchanged. Output must be
disjoint from all key, nonce and input views; exact and partial in-place XOR
are intentionally refused by this caller-buffer profile. Zero-length input
still validates key/nonce/capacity but writes no bytes and tolerates overlap.
Successful operations preserve every output byte beyond the requested prefix.
Native callers lend truthful allocated spans; count/overlap checks do not prove
ownership or make fabricated positive pointer spans safe.

This is a stateless one-shot primitive, not an authenticated message format or a
stateful partial-block cursor. Callers own nonce uniqueness and nonoverlapping
counter ranges. It makes no key-storage, secure-erasure or constant-time
qualification claim: local round state contains temporary key-derived copies,
and the later secret-lifecycle, generated-artifact review and integration gates
still apply. No app feature or production key was added.

## Verification

Checks preceded implementation. Surviving mutations led to exact-capacity
coverage and simpler block iteration; no mutation exemptions were used.

```sh
coax/bin/coax test coax/lib/crypto/chacha20.coax
coax/bin/coax mutate coax/lib/crypto/chacha20.coax
python3 coax/tests/nostr/chacha20.py --evidence /tmp/chacha20.json
```

- Pure authority closure: **15 check groups; 351/351 mutants killed**. The
  closure includes the shared byte checks; these are not disjoint mutation
  totals. Checks exercise the published quarter round, complete block bytes,
  stream/block agreement, every short block length, exact/short capacities,
  invalid metadata, aliases and the counter endpoints.
- All **10** published block/cipher expected outputs from RFC 8439 §2.3.2,
  §2.4.2, A.1 and A.2 are mechanically read from the pinned original RFC text,
  along with appendix input rows. The first two examples' key/nonce/counter
  parameters are specified directly in the reader. It verifies the RFC's
  SHA-256 before extraction. Source hash:
  `25bef70fbf7a07ff45c2fe4cb7c6ce954eac687413d8610603268b4e4415324c`.
- **269** independent records comprise those 10 examples, 3 explicit final
  counter/max-request cases and 256 seeded test cases (seed 8439). All outputs
  agree with Node 26.12.1's OpenSSL 4.1.0 implementation. The oracle first checks
  its agreement with every original RFC output; it does not derive expected
  ciphertext from Coax. Only public/throwaway fixtures are used.
- Native checked and release C each pass all 269 records under clang ASan/UBSan,
  plus 15 invalid-count/capacity/counter and physical-alias cases. Guard bytes,
  key/nonce/source preservation on refusal and zero written counts are checked.
  Unsupported macOS leak detection is disabled; no leak-check claim is made.
- Actual scalar Wasm under Node/V8 passes the same 269 records in each profile,
  plus 11 refusal cases and decrypt round trips. No SIMD flag or foreign cipher
  is used by the candidate. Algorithm/policy remains Coax; C faces only carry
  scalar calls, pointer spans and test results.

OpenSSL's raw ChaCha20 interface uses a little-endian 64-bit counter and an
8-byte nonce. The test oracle initializes its 16-byte IV as `LE32(counter) ||
nonce12`, giving the same initial words as IETF ChaCha20. Comparisons stay
within the admitted 32-bit counter range, so the different overflow policy
never participates. Refusal checks separately prove the IETF bounds. See
[OpenSSL's interface description](https://docs.openssl.org/3.5/man3/EVP_chacha20/)
and the [Node Cipheriv API](https://nodejs.org/api/crypto.html#cryptocreatecipherivalgorithm-key-iv-options).
