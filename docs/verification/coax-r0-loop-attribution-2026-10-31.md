# R0: the whole clean and warm iOS development loop, attributed

Measured with [`verse/benchmarks/loop.py`](../../verse/benchmarks/loop.py) on
Apple M5 Max, compiler coax0 0.33.0, source `6da88715c0`, for the
15 Coax units and 2 shader units of
`apps/openagents-ios/generate.sh`. Other sessions were building on this Mac
(load average about 30-60 at the start), so absolute times are noisy; the
ranking is the result. Xcode's rows are its own task sums across parallel
workers, not additive with each other or with the standalone rows.

## Warm, and the bottleneck

**Largest bottleneck: Swift compilation** (30.5 s of summed tasks in a clean
build). Coax itself is under a second for all units and is not the problem;
the C backend does not need replacing for loop time.

The warm loop had a worse, fixable cost: a rebuild with **no change at all**
took 7.3 s and recompiled 11.2 s of Swift and 5.0 s of C, because
`generate.sh` (run on every build) rewrote every generated file, giving each
a new timestamp. It now generates into a scratch directory and replaces a
file only when its bytes changed. After the fix (same machine, higher load):

| Warm build | Before | After |
| --- | --- | --- |
| Nothing changed | 7.3 s (Swift 11.2 s, C 5.0 s) | 4.3 s (generate script 2.6 s only) |
| `verse/cast.coax` touched, same generated bytes | 8.9 s | 3.2 s |

What remains in a no-op warm build is the generate script: Coax has no
incremental cache, so it recompiles every unit each time (about 1 s) plus its
compiler-freshness and release drift checks. A real edit to one unit
recompiles that unit's C and the Swift that includes its header.

GPU preparation measures the same Metal call the app makes at start, on the
Mac's GPU; a phone's shader compile is not measured here, nor first-frame
time (launch is timed to process start).
