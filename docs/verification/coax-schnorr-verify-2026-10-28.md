# Public BIP-340 verification

`schnorr-verify` (#41bd) adds the complete byte-view verification entry in
`coax/lib/crypto/schnorr.coax` and a strict Nostr event-ID wrapper. This is a
read-only public-input implementation. It does not sign, generate keys, derive
ECDH keys, erase secrets or approve production secret use.

## Public contract

```coax
schnorr_verify_vartime(message, public_key, signature) -> bool
nostr_verify_vartime(event_id, public_key, signature) -> bool
```

The public key is exactly 32 raw x-only bytes; the signature is exactly 64 raw
bytes. General messages may have any length from zero through 1,048,576 bytes.
The Nostr wrapper accepts exactly 32 raw event-ID bytes. Hex text is decoded by
the caller. Malformed lengths/counts, noncanonical r or s, invalid public-key
lifts, infinity, odd R.y and an unequal R.x all return false.

Views are borrowed synchronously and are never retained or modified. Aliasing
read-only inputs is supported. The native caller must supply readable buffers
for admitted counts and retain them for the call; metadata checks are not a
proof that an arbitrary foreign pointer is valid. There is no input-sized
allocation or padding buffer. Hashing uses a local 112-byte state and fixed
32-byte tag/output buffers, so a large message does not create a large stack
array.

Every new procedure ends `_vartime`. Names document the public-input boundary;
they do not establish general taint enforcement or target constant-time behavior.
Only the two complete byte-view entrypoints are newly exported through the C ABI.

## Algorithm and internal boundary

Preparation first admits the exact lengths, r<p and s<n, and lifts the x-only
public key to the even-y point P. It streams
`tag_hash || tag_hash || r_bytes || public_key || message` through SHA-256,
reduces the challenge modulo n, and stores the coefficient -e. The existing
public multiplier computes `R = s·G + (-e)·P`. Canonical affine conversion and
the final comparison reject infinity and require an even y and x=r.

The fixed `BIP0340/challenge` tag hash is generated by `#run` from a literal
under the unchanged aggregate 100k step budget. Runtime hashing uses the
streaming SHA API. That API still shares its compression implementation with
the compiler-fingerprint module; this does not newly qualify the old general
fingerprint API or secret paths. Independent preparation digests and complete
signature vectors check the actual domain separation and chunk order.

`SvPrepared.ready` means preparation succeeded. It does **not** mean a signature
is verified. The equation/comparison helpers are not C exports. Coax `#load`
composition is not a capability boundary: trusted source consumers must use the
complete public entrypoints and must never turn a constructed prepared record
or a mathematical helper result into verified authority. The helpers permit
real small-coefficient equations to be checked independently; they are not
mocked verification or a replacement for hashing the original inputs.

The group APIs return canonical infinity for every refusal. Affine conversion
preserves a nonzero infinity flag for infinity and refusals; the final
comparison requires flag zero. The verifier uses that explicit data contract
instead of redundant status guards that cannot change the result.

## Interpreter checks and their practical limit

The loaded `#authority` closure passes 124 checks with the default
20M interpreter steps per check. It includes actual preparation against all 19
pinned upstream rows (including decoded key point, r, s and independent -e),
real small-coefficient equations, readiness refusal, infinity/odd-y/x/parity
cases, input boundaries, and the complete imported crypto checks.

There is no full positive signature check in that loaded interpreter closure.
A direct official-row-0 positive probe reaches `E0400` at the unchanged 20M
budget. The focused native test records this observation explicitly. No budget
is raised or bypassed. Full emitted native/Wasm official vectors, seeded faults
and the actual hour differential fill this practical end-to-end testing gap;
they are evidence, not a formal proof.

The component fixture generator is explicit test tooling only. It preserves the
upstream CSV bytes, binds SHA-256
`34c9d1d9c3a88d524bc80778540dc43f8306ec249a7485293063c376db851c2d`,
labels the fixtures as preparation checks, and copies no private-key columns.
Normal library/app builds remain Python-free.

## Focused emitted-artifact evidence

The focused report is retained at
`coax/tests/nostr/data/schnorr-focused-2026-10-28.json`. It records compiler,
source, oracle, generated C and actual native/Wasm artifact hashes.

Current focused validation includes:

- All 19 official verification rows in both native profiles and both public
  entrypoints: 76 comparisons, with exact message lengths 0, 1, 17, 32 and 100.
- All 19 rows also match the independent unbounded-integer affine reference.
- 2,052 seeded native comparisons, including a valid 1 MiB message and refusal
  above that cap.
- 44 malformed-count/length and positive read-only alias cases.
- 174 actual wasm32 cases per profile, including every official row, generated
  valid/changed signatures, size boundaries, immutable inputs and guard bytes.
- Native ASan/UBSan over positive verification and malformed metadata.
- Four faults in the actual emitted C: omit the challenge public-key chunk,
  change the challenge sign, remove the even-y constraint, and bypass the
  strict Nostr message length. Official end-to-end vectors detect each fault.

Native observations are on `arm64-apple-darwin25.4.0` with Apple clang `-O2`.
Wasm uses clang 23.1.4 and Node 26.12.1/V8 14.6. Native timings isolate the ctypes
C call plus FFI; Wasm timings isolate the exported C/Wasm call. They exclude
buffer writes and input-preservation comparisons. These observations do not
waive correctness or constitute timing-security measurements.

## Sustained run and source provenance

The full loaded reachable mutation closure kills all 1,907 of 1,907 mutants,
with zero survivors and no exemptions or filters. The actual sustained run
passes after 3600.002915 real monotonic seconds: 1,743,107 cases (504,586 valid,
1,238,521 invalid) in each native profile. It also checks 102,536 strict Nostr
cases per profile. There are zero mismatches; the retained regression corpus
is empty. This is 3,486,214 general and 205,072 Nostr comparisons, excluding the
official preflight.

The sustained report is `coax/tests/nostr/data/schnorr-hour-2026-10-28.json`.
It retains the seed, corpus hash, source/artifact fingerprints, exact observed
duration and counts. The regression corpus is retained alongside it. Both the
runtime sources and all loaded check inputs remained byte-identical through
the completed hour.

The hour runner builds both profiles, checks every official row first, and then
compares general verification against the pinned public libsecp256k1 oracle.
It periodically exercises the Nostr wrapper too. Inputs mix fresh throwaway
signed public fixtures, changed messages/signatures/keys, r/s boundaries,
malformed lengths and official rows. The deterministic seed and case indices
reproduce the corpus; a rolling corpus hash, category counts and periodic
checkpoints are retained. A mismatch writes its public input and index before
failing. Test signing keys are deterministic throwaway data, never user identity.

The timer starts after building/preflight and requires at least 3600 real
monotonic seconds of differential work. `--preflight-seconds` is separately
labelled `acceptance_hour=false` and cannot satisfy acceptance. The runner uses
no simulated elapsed time or sleeping substitute. Bounds are four million
cases, at most 4097 generated message bytes, 32 MiB of temporary artifacts and
4096 timing samples per profile. No network dependency is used in this gate.

## Reproduction and remaining scope

```sh
coax/bin/coax test coax/lib/crypto/schnorr.coax
coax/bin/coax mutate coax/lib/crypto/schnorr.coax
python3 coax/tests/nostr/make_schnorr_fixtures.py
COAX_SCHNORR_REPORT=/tmp/schnorr-focused.json python3 coax/tests/nostr/schnorr.py
python3 coax/tests/nostr/schnorr_hour.py --report /tmp/schnorr-hour.json --regressions /tmp/schnorr-regressions.jsonl
```

Use fresh regression output paths; the hour runner refuses to overwrite an
existing corpus. No whole compiler, app or unrelated suite is repeated for
unrelated main commits. Nostr event admission, profile/domain authority wiring,
independent security review, physical iOS and broader target evidence retain
their separate gates. A valid BIP-340 signature alone grants no project role or
host admission.
