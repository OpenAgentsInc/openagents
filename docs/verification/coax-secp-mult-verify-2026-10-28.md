# Public secp256k1 verification multiplication

Task `secp-mult-verify` (#ff0f) adds `coax/lib/crypto/secp_mult.coax`.
It computes `a·G + b·P` for public verification inputs. It does not sign,
produce a public key from a private key, or derive ECDH secrets. Every new
procedure ends `_vartime`. Names document the boundary; they are not a general
secret-taint checker or approval to call this module with secrets.

## Representation and admission

`ecmult_vartime(a, point, b) -> SgResult` takes the existing eight-u32 scalar
values and bounded ten-limb field coordinates in `SgPoint`. As with the group
module, every input field must satisfy its magnitude ≤ 8 precondition before
calling this API. The public curve check rejects invalid bounded points,
including noncanonical infinity sentinels, even when both coefficients are
zero. Refusal returns `ok=false` and the canonical `(1,1,0)` infinity.
A valid infinity is accepted for general group arithmetic. Nostr public-key
admission must independently require a finite point.

Finite inputs and field aliases are admitted by the existing group rules.
All successful outputs have canonical magnitude 1 field coordinates and
canonical infinity. The module uses no allocation, host effects or retained
state. Public point validation and wNAF digit selection branch on public data.
The caller owns the by-value inputs and outputs.

`sm_wnaf_vartime` recodes the **exact unsigned 256-bit integer** in the scalar
limbs, without first reducing modulo n. Group multiplication produces the same
point as reduction because the admitted secp256k1 group has order n and
cofactor 1. This also makes the carry into an extra word observable for the
all-ones256-bit input. This helper is not a canonical-scalar admission API;
its supported public window metadata is 2..5, otherwise `ok=false`, length 0
and all-zero digits.

## Recoding and group algorithm

For an odd remaining integer k, choose the signed residue d modulo 2^w with
`−2^(w−1)<d<2^(w−1)`. For even k, choose d=0. Store d and replace k with
`(k−d)/2`. A nonzero digit is odd and the next w−1 digits are zero. Thus
`k_original = Σ d[i]·2^i`. The maximum positive input 2^256−1 becomes
`−1 + 2^256`, so the digit array has 257 entries.

The temporary integer has nine little-endian u32 words. Positive digits do
not exceed the low word, so subtraction needs no borrow. For negative digits,
the first u64 addition is at most 2^32+14 and each propagated carry is at
most 1. A ninth word retains bit 256 before the right shift. Shift loops visit
words from low to high, reading the next word before that word is changed.
Every invocation runs 257 recoding rounds; digit-dependent branches and
access patterns remain deliberately variable-time.

P uses window 5 and the eight positive odd multiples
`[P,3P,5P,...,15P]`. They are built with one doubling and seven group additions.
A negative digit negates y, then canonicalizes infinity. The signed digit
bounds prove `(abs(d)−1)/2` lies in 0..7.

G uses window 2 and a **two-entry signed `[G,−G]` table actually generated by
`#run sm_generator_table_vartime()`**. Both compiler profiles execute it
within the unchanged aggregate 100k compile-time step limit. This small table
makes the first bootstrap slice honest about that limit. It costs more online
additions than a larger precomputed generator table; no speed or optimal-window
claim is made. The existing field exponent/bound certificates share that same
aggregate budget; it is not reset for each `#run`.

The highest occupied index in the union of both public digit arrays sets the
loop length; a direct Coax check pins zero, single-term and bit 256 lengths.
The public high-to-low loop doubles the accumulator, adds the selected signed
G entry if present, and adds the selected signed P multiple if present. Existing
complete group kernels handle equal/opposite points and infinity. The number
of rounds is at most 257. There are at most 257 point doublings, 129 G additions,
52 P additions, and the public odd-table preparation per call. Those addition
bounds follow the wNAF separation rules; they are not a wall-clock guarantee.

## Focused correctness evidence

The retained machine-readable report is
`coax/tests/nostr/data/secp-mult-verify-2026-10-28.json`. It binds source files,
the compiler binary, generated C and compiled artifacts to their hashes. The
build uses the same trusted coax0 0.15.0 binary throughout this slice. Newer
unrelated main commits do not trigger repetition of passed checks.

The final source passes 71 Coax checks. Mutation over the complete loaded
reachable closure kills all 1,224 of 1,224 mutants, with zero survivors and no
exemptions or filters.

The final focused native/Wasm suite passes all six tests in 209.6 seconds:

- 100,000 random triples in each native profile; both produce output hash
  `ef4c9adea459897a24e9821d9e80c6ea072163608c20dc4ce14dfbd4f8c444df`.
- 32 independent affine cross-checks and 153 additional edge/refusal triples
  per native profile.
- 10,376 independent recoding comparisons, including a carry that stops at
  each non-maximal next word; plus 12 invalid-window refusals.
- 72 real Wasm multiply cases and 54 recoding cases per profile, including
  canonical coordinates, infinity and output guards.
- 24 dense-scalar ASan/UBSan cases, two truncated-stream refusals, and all
  four injected generated-C faults detected (including stale carry).

Native target is `arm64-apple-darwin25.4.0`, Apple clang at `-O2`; Wasm uses
Homebrew clang 23.1.4 and Node 26.12.1/V8 14.6. The temporary corpus/artifacts
occupy 43,741,056 bytes, below the 96 MiB cap. Native streamed profiles finish
in 195.1 seconds checked and 104.7 seconds release while running concurrently;
these are observations on this target, not a performance guarantee.

The native differential driver streams fixed 160-byte public input records and
97-byte output records through the actual emitted C. Expected points come from
the pinned libsecp256k1 v0.8.0 public parse, public-key tweak multiplication and
combination APIs. The test verifies the source/artifact pins before loading the
oracle; it does not download, configure or run upstream scripts. A separate
Python unbounded-integer affine implementation cross-checks the first 32 random
results, and independently checks all wNAF recodings. Python is explicit test
tooling only, never a build or product dependency.

Random P values are valid libsecp generator multiples with independent random
nonzero Jacobian scale factors. Output comparison uses
`X == expected_x·Z²` and `Y == expected_y·Z³` modulo p; it does not reproduce
the production Jacobian formulas or rely on production affine conversion.

Native edge checks cover zero, powers of two, group-order boundaries,
all-ones scalars, opposite terms, infinity, raw field aliases and invalid
bounded points. Real wasm32 execution checks multiply results, wNAF output,
canonical limbs and output guards in Node/V8 against independent BigInt math.
Native ASan/UBSan checks dense scalars and malformed bounded points. Seeded
faults remove each term separately, lose a cross-word recoding bit, or retain
a stale carry after propagation should stop; all must be detected by the same real generated-code oracle tests.

The test suite declares at most 100,000 random triples per profile, a 1200-second
timeout per streamed profile, and at most 96 MiB of temporary artifacts and
fixtures. It uses two independent streamed native processes in parallel,
without spawning a process for every triple. The source checks use the default
20M interpreter steps per check and the aggregate 100k `#run` limit. The
unmodified mutator uses its standard adaptive per-check budget, without an
option override or an exemption.

## Scope limits and reproduction

This is a correctness slice for verification arithmetic. It supplies neither
BIP-340 challenge hashing/signature admission nor an event-validation pipeline.
It does not establish target-level constant-time behavior, secret erasure,
physical iOS execution, production key handling or independent security review.
Future secret fixed/variable-base multipliers must not call this API.

From the repository root:

```sh
coax/bin/coax test coax/lib/crypto/secp_mult.coax
coax/bin/coax mutate coax/lib/crypto/secp_mult.coax
COAX_MULT_REPORT=/tmp/coax-secp-mult.json python3 coax/tests/nostr/secp_mult.py
```

`COAX_MULT_COUNT` allows a bounded 1..100000 development subset. A reduced run
is preflight evidence only; it does not satisfy the 100,000-triple acceptance
check. No whole compiler, app or unrelated crypto suite was rerun for this
module.
