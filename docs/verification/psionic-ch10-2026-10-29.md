# Chapter 10: Elephant CPU verification, 2026-10-29

The original-weight experiment used coax0 0.16.0. We also checked the refined
components with a Coax 0.22.0 stage-zero compiler from a private source snapshot
(SHA-256 `2709fec830e72816b0587b93892aaf17f318c00a47b5dec8f4270ca9b12e3a4d`);
that stage has no protobuf importer. The same private snapshot fully
bootstrapped coax0 0.22.0 (SHA-256
`c5acf492faaef7ea8450245c44b454e69b208f83d9594e874be4d06eb3d3ae1a`);
its release-mode component and book checks also passed. The reference target
is the pinned
`baselabs/elephant-1` revision
`b3f8a93462fb1051a9de031e94a7ff380e254072`. The original 18,819,722,392-byte
checkpoint and its sidecars were authenticated against the committed pins;
all 760 tensors were inventoried, including the rank-five vision projection.
The text stack has 24 linear and 8 full-attention layers. Weights are not
committed. The complete artifact identities and admission results are in the
[original-bundle record](psionic-original-bundles-2026-10-29.md).

An independent PyTorch 2.10.0+cpu / Transformers 5.3.0 run on CoderOS used the
original BF16 weights converted to float32 and eager attention. The independent
reference applies an explicit additive two-block mask matching the visibility
specified by the pinned upstream serving patch. Psionic uses its own wide CPU
arithmetic and no Transformers runtime dependency.

The independently captured first-layer outputs agree over all 4,096 elements
with maximum absolute difference 0.000001431; the small checked-in vectors and
[fixture checker](../../psionic/tests/elephant_layer0_fixture.py) preserve that
comparison. The full one-token Coax run reproduced the shown values on the
Mac and CoderOS. These numbers are numerical comparisons, not a claim of bitwise
identity or general model accuracy.

For the typed choice `Water is wet.`, `Is the water wet?`, options `yes` and
`no`, Coax rendered and encoded 86 tokens, split into a 49-token shared prefix
and 37-token suffix. The independent reference used those exact token IDs and
the two-block mask. The harness allocates 14,581,760 state floats and
86,751,680 workspace floats (about 386.6 MiB together), in addition to the checkpoint mapping,
tokenizer, metadata and layer vectors. These figures describe this one
86-token harness, not a general process memory bound. The harness relies on
the caller and allocator for available memory; it does not implement a
resource scheduler.

The original-weight public session, preparation and answer path returned `yes`,
with probabilities 0.757196285 and 0.242803715, slot mass 0.228232722 and confidence 0.514392571.
The independent reference returned probabilities 0.757196248 and 0.242803693,
with slot mass 0.228232533. The largest absolute difference among these three
values is below 0.0000002. A separately authenticated direct request returned
the same displayed result. The pinned sample's complete token IDs and captured
reference are checked in; the opt-in original-file harness checks that token
stream and enforces a 0.0005 absolute tolerance on the decision statistics.
This experiment covers one text request at temperature one, not every input.

The Coax debug/release tests and native debug/release plus ASan/UBSan passed for
layer mapping, complete model mapping, request execution, preparation, session
and answer; the native release checks also passed on CoderOS. The final
mutation runs for preparation, session and answer were still running when
this chapter was pushed; none had reported a survivor at that point. The
separately recorded token, layer, model-mapping and request mutation runs
finished with zero survivors.

## Timing on coderos-4080, 2026-10-29

Machine: Intel Core i7-14700K (20 cores, 28 threads), 125 GiB memory, NVMe,
Linux x86_64; coax0 0.22.0; the harness's `-O2 -ffp-contract=off
-fno-fast-math` C build. The original files were downloaded at the pinned
revision and their SHA-256 values matched the committed pins before use.
Other agents shared the processor during these runs, so these are upper
bounds for this machine, not best cases.

| Run | Result |
| --- | --- |
| `psionic/tests/run_elephant.sh` (compile, authenticate, decide, check) | Passed; 29 min 17.07 s wall; peak RSS 18,651,220 KiB; same probabilities as above |
| `psionic/tests/bench_elephant.sh DIR 1 2`, preparation | 0.000630 s for 86 tokens (49 prefix, 37 suffix) |
| Same, session open (Coax SHA-256 of all files, inventory, binding) | 83.526 s; peak RSS 17,980 MiB |
| Same, first decision | 2,092.119 s (0.04 prompt tokens/s); p_yes 0.757196285, p_no 0.242803715; peak RSS 18,206 MiB |

The load average was 8.5 when the benchmark started and 35.2 when its second
decision on the same session was stopped unfinished; that second decision and
a longer-prompt run were abandoned to free the processor, and no figure is
reported for them. GNU `sha256sum` read the same checkpoint in 42.2 s.

Host measurements from a separate C probe on the same machine: sequential
BF16 reads at 13.8 GB/s on one core and 30.4 GB/s on 20 threads; a
BF16-times-f32 dot product accumulated in compensated binary64 at 0.52 G
multiply-adds/s on one core, and 1.14 G/s uncompensated. About 730 G
multiply-adds per decision at the compensated rate predicts the measured
decision time, so this profile is compute-bound on one core rather than
memory-bound.
