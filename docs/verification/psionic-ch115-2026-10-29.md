# Chapter 170: benchmark a service, not a kernel, 2026-10-29

Verified on Linux 6.18.49 x86_64 (28 cores, one RTX 4080) with gcc 15.2.0
(Nix), Python 3.13.15 and coax0 0.23.0. The compiler binary was the main
checkout's `coax/bin/coax` (sha256 `03498a6c…76ab93`): the worktree's own
`coax/build.sh` hit its 15-minute limit under the host's load and was not
retried. **The host's load average was 133 to 167 from other work during
every measured run.** The figures below measure that loaded host, not the
service; qualified figures wait for a quiet host.

## What was built

- `psionic/lib/bench.coax` (`#authority`), profile `bench-us-v1`: integer
  microseconds and milli-tokens per second, no floating point.
  - The schedule: SplitMix64 at a counter (`splitmix64-counter-v1`, chapter
    103's words), request i on counters 8i..8i+4 for its gap, input length,
    output limit, content and sampling choice; gaps uniformly jittered by up
    to `jitter_pct` of the mean; lengths drawn from integer-weighted
    histograms of up to 16 lengths; up to 4,096 requests.
  - Shadow replay of recorded arrivals at a scale in percent.
  - Nearest-rank percentiles: rank ceil(P·n/100), P50/P90/P95/P99.
  - Summaries: time to first token, inter-token gaps, end to end, the
    server's own inference time, end to end less inference, per-user tokens
    per second (an answer's tokens over its end-to-end time) and total tokens
    per second over the run's span; 200 answered, 429/503 refused busy,
    anything else failed; impossible timings refused.
  - Comparison: refused unless the repeat matches the baseline in all eight
    identity words and the candidate differs in at most one; zero changes is
    a repeat; otherwise better/worse only beyond both the baseline and the
    repeat by more than the margin, else within.
- `psionic/lib/bench-wire.coax` (`#authority`): the two built-in workloads,
  request bodies (gpt-oss Responses SSE, NIP-DEC decisions), SSE token-event
  classification and `latency_ms` extraction.
- `psionic/platform/bench-drive.c`: host effects only (sockets, threads,
  monotonic clock, run files). `psionic/platform/bench-build.sh` builds it;
  `psionic/platform/bench-run.sh` reads a same-user local server's key from
  `/proc` without printing it.
- `psionic/examples/bench-service.coax` and its fixture; chapter
  `psionic/book/ch170-benchmark-a-service-not-a-kernel.md`; `bench` and
  `bench-wire` added to `psionic/check.sh`'s Coax units.

## Measured runs (loaded host; not qualified)

Raw run files, schedules and logs: `psionic/fixtures/bench/2026-10-29/`.

gpt-oss-20b Responses server, 127.0.0.1:8080, shared with other agents. 8
requests, seed 115, jitter 50 percent, built-in responses workload:

| Metric | Baseline, gap 4 s | Repeat | Candidate, gap 2 s |
| --- | --- | --- | --- |
| answered / refused busy / failed | 6 / 2 / 0 | 8 / 0 / 0 | 8 / 0 / 0 |
| TTFT P50 / P90 | 362.7 / 657.8 ms | 369.0 / 665.0 ms | 322.0 / 644.0 ms |
| ITL P50 / P90 / P95 / P99 | 15.8 / 18.0 / 41.6 / 150.8 ms | 15.7 / 22.0 / 46.9 / 105.0 ms | 15.6 / 21.0 / 66.8 / 123.0 ms |
| end to end P50 / P90 | 727.5 / 851.3 ms | 725.1 / 858.9 ms | 734.8 / 849.0 ms |
| per-user tokens/s P50 | 26.9 | 26.0 | 26.5 |
| total tokens/s | 5.17 | 6.89 | 13.38 |

Comparison at a 2 percent margin: TTFT better at every percentile, ITL P95
worse, everything else within; inference unmeasured (the server reports no
timing). On this host that TTFT verdict is noise, not a rate effect. With 6
to 8 answers, P90 and above are the maximum.

Decision target: Elephant `/v1/systemone` at 127.0.0.1:8797 was down when
the run started: all 6 requests (about 22:04 CDT) failed to connect. The
coordinator reported that something was sending it SIGTERM; it later ran
under a restart loop. This session sent it only three `GET /healthz` probes
by hand (404) and one POST that could not connect, and stopped no process
other than its own toy server. The deterministic stand-in was the
chapter 20 toy, `psionic-serve --toy --fixture-delay-ms N` on port 8915, 12
requests, seed 115, gap 1.5 s, jitter 50:

| Metric | Delay 50 ms | Repeat | Delay 250 ms |
| --- | --- | --- | --- |
| answered / refused busy | 11 / 1 | 12 / 0 | 10 / 2 |
| end to end P50 / P90 | 436.6 / 1022.1 ms | 637.6 / 931.3 ms | 536.2 / 1205.9 ms |
| inference P50 / P90 | 433 / 990 ms | 625 / 930 ms | 536 / 2372 ms |
| end to end less inference P50 / P90 | 4.2 / 25.1 ms | 4.5 / 13.7 ms | 5.5 / 20.5 ms |

The 200 ms of added delay was `within` at P50 because the repeat alone moved
P50 by 46 percent. In the delay-250 run one answered decision gave no usable
`latency_ms` (n 9 against 10). A shadow replay of the baseline's recorded
schedule at real time ran too (11 answered, 1 busy). A run that changed both
the label and the seed was refused, and a repeat compared with its baseline
was reported as a repeat.

## What is missing

- Qualified figures on a quiet host, with enough requests (well over 100
  answers) for P99 to differ from the maximum, and a margin set from
  chapter 238's noise floor over several repeats instead of a written 2
  percent.
- Elephant over `/v1/systemone`: not measured (server down).
- `bench-drive.c` has no automated check in `psionic/check.sh`; it was built
  and run by hand, including under ASan/UBSan.
- Closed-loop users, Poisson or bursty arrivals, and prefill/decode
  separation (chapter 18) are not built. Token events are SSE `.delta`
  events, which include reasoning IDs.
- The full `psionic/check.sh` and `book.py --coax` over every example were
  not run; only the units and example above.
