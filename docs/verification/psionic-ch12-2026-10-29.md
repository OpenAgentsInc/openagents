# Chapter 12: decision quality verification, 2026-10-29

This record covers [chapter 12](../../psionic/book/ch012-are-the-probabilities-any-good.md):
the calibration the pinned bundles supply, the published answer serialization
and a small held-out quality run on the original Elephant. It does not cover
numerical conformance; that is chapter 10's record, and chapter 13 holds the
qualification rules.

## Implementation and checks

| Unit | Checks | Mutation (coax0 0.22.0) |
| --- | --- | --- |
| `psionic/lib/decision-calibration.coax` | 44 debug and release | 425 mutants, 425 killed |
| `psionic/lib/decision-json.coax` | 206 debug and release, including 90 generated answers | 2,527 mutants, 2,527 killed |
| `psionic/lib/decision-quality.coax` | 47 debug and release, including a 40-item generated case | 545 mutants, 545 killed |

All three files are `#authority`; no line is marked equivalent. The check
counts include the checks of the units each file loads. The answer fixtures
come from [`answer_oracle.py`](../../psionic/tests/answer_oracle.py), which
uses Python 3.13.15's `round` and `json.dumps` for every byte and a
transcription of `calibrate.py` for the metrics. Midpoint cases include doubles
next to `(n + 0.5) / 10^6`, products that round to exactly `n + 0.5` with
errors of either sign, exact binary ties such as 1/128 and 9/128, and
values printed in exponent form.

Native adapters and harnesses for the three units passed in debug (`-O0`) and
release (`-O2`), both plain and with ASan/UBSan, using GCC 15.2.0 with
`-Wno-unknown-pragmas`. They test 255 choice options, NaN and infinity
refusals, capacity, observed overlaps and extreme item offsets.

`psionic/check.sh` cannot run on this host: `text_fixtures.py` and
`text_oracle.py` require Unicode 17.0.0, and the host's Python 3.13.15 has an
older Unicode database. The default `cc` (GCC 15.2.0) also rejects the
generated `#pragma STDC FP_CONTRACT` under `-Werror`. Neither limit comes from
this chapter. The checks above were run unit by unit with the same flags that
`check.sh` uses, together with `python3 -I psionic/tests/book.py --coax
coax/bin/coax`. The full `check.sh` run is still open for a host with
Unicode 17.

- Freeze commit: `4e72622ffed9e9170b647205f7473c0bb0a2731d`, authored 2026-10-29 11:36:46 -0500.
  This is the commit's hash after rebasing onto `origin/main`; its tree is the
  same as the local commit `e51bdc170a1f28043b28c150577cd28c1d3b9f50` made before the run.
  The run started at 11:38:54.
- Attempt 1 (11:36:50) refused all 12 decisions with status `capacity` before
  any forward pass. The harness had sized the state for each request's token
  count, but the session was opened with capacity 192. The harness was
  changed to size state and workspace to the session capacity. No
  probabilities were computed, and the set, labels and metrics did not change.
- Attempt 2: `psionic/tests/run_elephant_quality.sh ~/models/elephant-1-b3f8a934 12`
  with coax0 0.22.0 (binary SHA-256
  `4afaf042d216158deb4bda4b605541b43816b301d9776b480e6eb004df858027`), GCC
  15.2.0 `-O2`, Linux 6.18.49 on an Intel i7-14700K with 125 GB of RAM. The
  original files were authenticated against the target pins (91 s). Requests
  had 106 to 130 tokens. Each decision ran in its own process, shared with
  other agents' jobs (load average about 30 on 28 threads), and took 4,162 to
  4,850 s. The whole run took 82 min 40 s.
- Backend: Psionic's CPU reference path. No GPU, quantized or upstream runtime
  was used.

The [output](../../psionic/fixtures/quality/heldout-v1-elephant-cpu.txt)
records every probability vector and answer. The answers were serialized by
the `decision-json.coax` in the freeze commit. The later revision restructures
the rounding code, loads fewer units and adds checks. The independent oracle,
applied to the logged nine-digit probabilities, reproduces all 12 logged
answers.

| Measure | Result |
| --- | --- |
| Accuracy | 12/12 (choice 5/5, noul 4/4, score 3/3) |
| Brier | 0.000056 overall; choice 0.000053, noul 0.000065, score 0.000050 |
| Top-label calibration error, 15 bins | 0.003476 |
| Score mean absolute error | 0.003154 |
| Abstention | offered 2, abstained 1 (correctly); answered 11, correct 11 |

Limits: 12 easy items written by us. Every top probability exceeds 0.988, so
all items share the last bin and the calibration error cannot describe
calibration at lower confidence. There were no errors to test overconfidence.
With 12/12 correct, the one-sided 95% lower bound on accuracy is about 0.78. No
reference runtime ran these requests, so the run measures decision quality
only, not numerical agreement. A larger corpus needs a faster backend.
