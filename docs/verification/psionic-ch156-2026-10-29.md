# Chapter 213: fit our own calibration, and refuse a stale one, 2026-10-29

Verified on macOS 26.4 arm64 (Apple M5 Max) with Apple clang 21.0.0, Python
3.15.1 and coax0 0.24.0. No model weights, GPU, network or upstream code were
used.

`psionic/lib/calibrate.coax` implements profile `cpu-f64-calibrate-v1`:
- binary64, chapter 4's compensated accumulator for every sum;
- per-question maps of three kinds: a temperature (log-loss slope within
  [0.05, 20], found by halving to adjacent doubles), ten equal-count bins, and
  isotonic steps (pool-adjacent-violators with integer rate comparisons, at
  most 256 steps), each fitted on at least 200 rows;
- maps bound to a model identity and a question set, refused as `stale` for
  any other;
- calibration error (15 bins of the top label), Brier, log loss, confident
  errors, and reliability in ten bins with a 20-row floor;
- a frozen gate: lower calibration error and lower log loss than raw on the
  gate split; the lowest gate log loss among passing maps is kept;
- the synthetic set `calibrate-sim-v1`.

## What mutation testing changed

- **Checks that could not fail** were removed: a question index outside
  [0, 8) has no rows, and the 200-row floor already refuses it; an empty call
  is refused by the same floor.
- **Calibration bins:** the top label is at least 1/2, so the bin search and
  the sum start at bin 7, and a check covers four neighboring bins.
- **Clamping** became a range test and a rounding to the nearer end.
- **New checks:** rows given in falling order (fitting must sort them), a
  derivative of exactly zero, one-row apply and simulate calls, a bad first
  row, and the simulator's label counter on a second row.

## Not claimed

- **Synthetic data,** one draw per split, point estimates at the gate.
- **Identity by number,** not by a hash of weights and question text.
- **Yes-or-no questions only.**
- **Process:** checks were written alongside the code, not run against stubs
  first.
