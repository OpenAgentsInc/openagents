# Psionic chapter 16: `/v1/systemone`, 2026-10-29

Verified on `coderos-4080` (Linux x86-64, Intel Core i7-14700K, 125 GB) with
GCC 15.2.0 and coax0 0.23.0 built from this tree, SHA-256
`041edee7bc9954ce27813e560018e421a9ec9113f7402a43a0d405ca022b86ab`. Other
agents' builds and mutation runs shared the machine throughout, so every
duration below is an observation under load.

## What was built

- `psionic/lib/serve-request.coax` (`#authority`): HTTP/1.1 head framing
  (8 KiB head, 256 KiB body, `Content-Length` only, `Expect: 100-continue`),
  the NIP-DEC body decoder with every NIP-DEC bound, the refusal codes, their
  statuses and fixed messages.
- `psionic/lib/serve-engine.coax` (`#authority`): the served engine and its
  identity (`name@sha256:<authenticated checkpoint digest>`), the owned toy
  engine, the workspace plan, admission, the per-question fit, the NIP-DEC
  answer body, and the one-slot state machine (accept, bytes, tick, closed,
  done) with its read and decision deadlines, busy refusal and epochs.
- `psionic/lib/serve-run.coax`: the loop that runs each question through
  `ps_prepare` and `ps_answer`. It has no `#authority` marker: every decision
  it uses is in the two files above, and a complete toy decision exceeds the
  compile-time evaluator's aggregate and step budgets, so its success path is
  checked natively.
- `psionic/platform/serve-host.c`: the host. It binds 127.0.0.1 only, reads
  and writes bounded bytes, reads `CLOCK_MONOTONIC`, maps files and forks one
  child per decision, which it kills on `cancel_refuse` or `cancel_close`. It
  logs a status, a code name and a duration per request.
- The toy model, `psionic/fixtures/models/serve/toy.coax`, written by
  `psionic/tests/serve_fixture.py`: 56 BF16 tensors, 10,194 bytes, SHA-256
  `b6680707750842c489bad8a5524bb1b1393ff04f6917b72cf49c2cf87d633573`.

`proto/` was not changed. The protocol specification (section 16.1) defines
`decision.v1.SystemOneRequest`, whose HTTP carriage is the NIP-DEC JSON body,
but `proto/` has no file for that package yet; the decoder follows NIP-DEC.

## Native checks

`psionic/tests/serve.sh` builds the server and `psionic/tests/serve.c` in
debug and release, plain and with ASan and UBSan, and runs all four. Each run
starts three toy servers on ephemeral loopback ports and checks:

- a three-question request (noul, choice, score) returns 200 with the served
  identity, and its seven reported values agree within 1e-9 with direct calls
  to the chapter-10 adapters `psionic_prepare` and `psionic_answer` on a
  separately opened session, with inputs built in C rather than decoded;
- the same request written in 97-byte pieces, and with
  `Expect: 100-continue`, returns the same answer;
- `malformed`, `invalid_request`, `too_many_questions` (65),
  `too_many_options` (256), `unsupported_input` (27 options on the toy, and a
  fractional number in the state), `not_admitted`, `not_found`,
  `method_not_allowed`, chunked bodies, non-HTTP bytes, a declared body over
  256 KiB (refused in under a second, before any body), a head over 8 KiB and
  a state over 128 KiB;
- half a request and a silent connection get 408 `request_timeout` at the
  400 ms read deadline; an abandoned request frees the slot;
- with each decision held 700 ms, a second client gets 503 `busy` with
  `Retry-After: 1` in under 600 ms while the first is answered; a client that
  disconnects during its decision has it cancelled, and the next request is
  answered fresh rather than refused as busy;
- with a 300 ms deadline and a 3 s hold, the decision is stopped and refused
  with 524 `timeout`, twice;
- every server exits 0 on SIGTERM, and no log line contains request or answer
  content (marker strings in the state, question IDs and option IDs).

All four variants passed, in 1 minute 51 seconds together, while other jobs
loaded the machine. Under that load a debug ASan toy decision can take more
than 20 seconds, so the test servers allow 120 seconds per decision.

finished before the owner directed that no more original-weight decisions run

its real requests will be measured on the GPU path once that lands.

## Limits

One connection at a time: a slow client holds the slot until the read
deadline. No TLS, no `Idempotency-Key` or `X-Attempt` handling, no usage
records (`usage` is `null`), no calibration (temperature 1). The identity is
the loaded file's digest, not a digest over tensor payloads alone. Only
Linux was tested; the host uses POSIX calls that macOS also has, but it was
not built there. Running the server for other people is chapter 17.
