# Chapter 219: write a bounded ONNX graph, 2026-10-30

**Environment:** macOS 26.4 arm64 (Apple M5 Max), coax0 built from this tree, Python 3.15.1. The `onnx` check used onnx 1.17.0 and numpy in a scratch virtual environment. No GPU or network.

**What landed**
- `psionic/lib/onnx-write.coax` (`#authority`), profile onnx-17-write-v1:
  - a protobuf writer that writes every length as the shortest varint;
  - an ONNX writer for chains of Gemm, Relu and Softmax over one float input, using IR 8, opset 17 and raw binary32 initializers;
  - every file read back by chapter 218 before it is returned, with 218's refusals passed on as `reread`;
  - chapter 103's affine models folded into raw-feature weights, with the logistic model as Gemm plus Softmax over [0, z];
  - the hidden-layer (tanh) model refused as `op`.
- `psionic/examples/onnx-write.coax` and `psionic/fixtures/onnx-write.out`.
- `psionic/tests/onnx_write_check.py`, which needs onnx:
  - it writes the test networks' bytes, built by onnx's own helpers, to `psionic/fixtures/onnx/write.coax`;
  - with `--example`, it checks the example's two files.
- `psionic/tests/onnx_write_oracle.py`: a standard-library oracle.
- Chapter 8's table and its rows in README and PLAN no longer call the ONNX reader and exporter planned.

**What the example shows**
- Chapter 103's logistic model, exported with its scaling folded in, gives P(on time) within 5.82e-07 of the binary64 model on all 480 test rows. Every decision at 0.5 is the same.
- The latency line is within 1.456e-06 s.
- The MLP is refused as `op`.

**Mutation history**
- **First run, 38 survivors in the writer:**
  - The writer re-checked each weight's name after reading it back. Chapter 218 maps a stem's slashes to dots one for one, so that check could never fail. It was replaced by a stem check before writing (`name`).
  - A count of written weights was unused, and so was the node in a successful check. Both were removed.
  - Literal zero dimensions in tests became shape helpers.
  - New tests:
    - a 16-node chain compared byte for byte with onnx's file, which covers the names `t10` to `t15`;
    - a transposed last Gemm;
    - a buffer exactly one message long;
    - node and weight counts at their limits;
    - chapter 103's widest model;
    - negative cases for the test helpers.
- **Coax's compile-time tests can't hold a non-finite float.** So the writer doesn't claim a finiteness check: it writes values as given, as chapter 218 reads them. The fold checks binary32's range in binary64 before rounding.
- **Second run, 1 survivor in the writer:** an unused dimension in a rank-1 test shape, now its own helper.
- **Third run:** see the table above.

**Not run:** the full `check.sh`, at the owner's request. `onnx-write` is added to its Coax units. The onnx check needs onnx and numpy, so it is run by hand.
