# Chapter 164: shadow a new model, then promote it, 2026-10-30

**Environment:** macOS 26.4 arm64 (Apple M5 Max), coax0 built from this tree, Python 3.15.1. No model weights, GPU or network.

**What landed**
- `psionic/lib/shadow.coax` (`#authority`), profile shadow-sim-v1:
  - a simulated three-way decision with label outcomes, 80 in 100 of which arrive;
  - models whose errors mix the request's difficulty with their own draws;
  - immutable identities: the SHA-256 of a model's bytes;
  - a registry of up to 16 models that refuses other bytes under a known name;
  - a shadow log of both answers and the joined outcome;
  - a report that waits for enough joined outcomes, then judges disagreement and paired extra error, each plus two standard errors;
  - a report digest;
  - activation as one compare-and-swap: version first, then the digest, then a promoting report against the model active now, named by the approval. Any refusal returns the active record unchanged.
- `psionic/examples/shadow.coax` and `psionic/fixtures/shadow.out`.
- `psionic/tests/shadow_oracle.py`: an independent reimplementation using `hashlib`. With `--tests`, it prints the values the Coax checks pin.

**What the example shows**
- Over 4,000 shadowed requests, 3,193 outcomes joined.
- `router-v4` disagrees on 0.0773 of requests (bound 0.0857, limit 0.12). Its extra error is −0.0254 (bound −0.0165, margin 0.005), so it is promoted.
- `router-small` disagrees within the limit, but its extra error bound is 0.0352, so it is held for regression.
- `router-other` has the active model's error count (204 against 202), but its disagreement bound is 0.1287, so it is held for disagreement.
- After 1,000 requests only 801 outcomes have joined, so the report waits.
- After approval, router-v4 becomes active at version 2. Four refusals then leave it unchanged:
  - an approval of a holding report;
  - a stale version;
  - bytes changed after approval;
  - a report shadowed against the previous model.
- Re-registering router-v4 with other bytes is refused as `immutable`.

**Mutation history**
- **First run, 13 survivors.** These led to:
  - a model with an empty name, now refused by the registry;
  - a report digest pinned with counts past one byte;
  - activation of an unregistered model whose digest the approval names;
  - activation of the registry's first entry;
  - test data that can be told apart from defaults;
  - negative cases for the test helpers.
- **Second run, 1 survivor:** zeroing past the name was masked by the words written after it. The words are now written first.
