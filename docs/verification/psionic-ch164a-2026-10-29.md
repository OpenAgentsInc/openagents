# Chapter 164a: learn which model to call, 2026-10-29

Verified on macOS 26.4 arm64 (Apple M5 Max) with Apple clang 21.0.0, Python
3.15.1 and coax0 0.24.0. No model weights, GPU, network or upstream code were
used.

`psionic/lib/route.coax` implements profile `cpu-f64-route-v1`:
- binary64, chapter 3's compensated accumulator for every sum;
- the task simulator `route-sim-v1`: 1 to 4,096 tasks of four features, three
  models whose logistic success weights (within ±64) only the simulator reads;
- published prices: dollars per call plus 0.02 per second of latency;
- a router that picks the largest success probability minus price, ties to
  the cheaper model;
- an old rule with exploration, logging that draws one action per task from
  propensities that sum to exactly 1;
- naive, direct, inverse-propensity and doubly robust estimates of a
  deterministic policy's value, refused as `support` when the policy chooses
  an action the logs could not have taken, or no logged row matches it.

The learners are chapter 70's logistic regression and `tb_train`, unchanged.

## What mutation testing changed

The first run left 24 survivors, fixed in code and checks, not by exemption:
- **Comparisons whose equal case no check reached:** a check finds a logit
  whose sigmoid equals the outcome draw exactly, and another builds
  propensities from the logging draw. The code feature became an integer draw
  (`bits % 5 < 2`), whose boundary occurs.
- **Pre-zeroed buffers:** the simulator's checks now start from −7.
- **Dead code removed:** an unused `logistic` flag, two `n == −1` tests a count
  comparison already implied, and a byte bound that could never be reached,
  restated on the row count.
- **Missing edges:** 1 and 4,096 tasks, the first task of each loop, and a
  choice decided by the incumbent's price.

## Not claimed

- **Simulated tasks and models,** and a learner fitted to the true family.
- **Twenty logs** separate naive and direct-with-averages from zero by more
  than 20 standard errors, but not direct, inverse propensity and doubly
  robust from each other.
- **No confidence intervals,** one exploration rate, deterministic target
  policies only.
- **Process:** checks were written alongside the code, not run against stubs
  first.
