# Chapters 165 and 166: a trace machine and attention as exact memory, 2026-10-29

Verified on Linux 6.18.49 x86_64 (coderos-4080) with GCC 15.2.0, Python
3.13.15 and coax0 0.23.0, compiler SHA-256
`3e0c94704693177b609114c9370531cbed43428c0cb2605527248a0387e2302e`.
The starting repository revision was `dae3b055cb`. No model weights, GPU,
network or upstream code were used.

`psionic/lib/trace-machine.coax` is a bounded integer stack machine: up to 256
instructions, 32 stack values, 8 locals, 64 memory cells, 64 outputs and 65,536
steps. Values are signed 32-bit integers. Each step writes `(ip, code, x, y)` to
the trace, and the digest is SHA-256 over those tokens as little-endian 32-bit
words. `psionic/lib/exact-memory.coax` scores key `k` against query `q` as
`2kq − k²`. Its hard-max read takes the later write on a tie and refuses
when the winning key isn't the query. `em_run` executes the same machine with no
memory except a view rebuilt from those reads before every step.

## What mutation testing changed

The first runs left 46 and 54 survivors. They were fixed by changing code and
checks, never by exemption:

- **Fixtures for every boundary.** The checks saw too little of each trace.
  `trace_oracle.py --coax` and `--memory` now generate 49 self-contained
  fixtures per unit. Each asserts every token, the digest, and refusals at
  exact capacity and one step short. They have no shared helper, so mutation
  can't weaken an assertion in one place.
- **One source of memory.** `em_run` still kept the ordinary memory beside the
  attention view, so a broken read could have gone unseen. Memory became a
  parameter of each step, and the attention machine has no other source.
- **A tie rule that can be tested.** The recency-weighted score could never
  tie, so the comparison's direction couldn't be tested. The read now states
  "the later write wins a tie" directly. The chapter explains the
  recency-weighted form a transformer would use.
- **No conditions that can't be observed.** A second output-capacity
  condition that matched the 64-output limit was removed. So was a publish
  condition on outputs that had no observable effect.

## Not claimed

- **Process.** The checks and the code were written together in one sitting,
  not run against stubs first.
- **Reference only.** This is a reference interpreter with integer scores. No
  transformer weights are constructed yet (chapters 167–170), and there is
  no statement about floating-point softmax exactness (chapter 172).
- **Speed.** The attention read scans every write; logarithmic reads are
  chapter 170.
