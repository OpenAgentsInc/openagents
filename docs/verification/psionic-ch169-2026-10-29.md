# Chapter 228: a harness that catches the compiler, 2026-10-29

Verified on Linux 6.18.49 x86_64 (coderos-4080) with GCC 15.2.0, Python
3.13.15 and coax0 0.24.0. No model weights, GPU, network or upstream code were
used.

`psionic/lib/compiler-harness.coax` runs every case three ways:
1. chapter 227's evaluator;
2. a plan interpreter, which executes the compiler's recorded layers, slots and
   clears in integers with chapter 226's gadget identities;
3. the compiled binary64 weights.

Evaluator against interpreter blames the schedule. Interpreter against weights
blames the emission. Each case is a seeded graph of up to 16 nodes, with
inputs from −100 to 100 and two outputs. Chapter 227's compiler takes a fault
argument (none, early reuse, same layer, no clear, clear sign) that only the
harness passes.

## Found while building it

- **A real compiler bug.** The honest compiler failed an internal assertion on
  seed 3, graph 694: a select's `a − b` needed nine terms after the graph had
  been accepted, because forms never merged like terms. Chapter 226's
  `ra_plus` now merges like terms and drops cancelled ones. Chapter 168 checks
  each gadget's own forms and refuses with `terms`. The oracle predicts that
  refusal, and seed 3, graph 694 is a pinned case.
- **A probe that hid the bugs.** Making every node an output kept every slot
  alive, so three of four planted bugs never happened. The harness now
  compares every node through the evaluator and the interpreter, and only real
  outputs through the weights.
- **Misattribution.** About 1 in 100 schedule bugs was blamed on the weights,
  because a stale select condition differs between ideal semantics and gadget
  arithmetic. The interpreter computes the arithmetic.

## Not claimed

- **Coverage.** The planted faults are chosen ones. Bugs that only show beyond
  16 nodes, past ±100 inputs, or in binary32 need cases that reach them.
- **Process.** Checks were written alongside the code, not run against stubs
  first.
