# Chapter 16b: the protobuf wire, 2026-10-29

Verified on Linux 6.18.49 x86_64 (coderos-4080) with GCC 15.2.0, coax0 0.24.0,
protoc 29.3 and Python protobuf 5.29.3, the versions pinned in
`proto/toolchain.json`. They were installed in a scratch virtual environment
as proto/README.md describes. No model weights, GPU or network were used by
the checks.

**Schema.** `proto/openagents/decision/v1alpha1/systemone.proto` is
registered as profile `systemone` in `proto/modules.json`.
`scripts/proto.sh generate` wrote `proto/descriptors/systemone.pb` and updated
`owned.pb`, and its compatibility, migration, module and profile checks
passed.

**Server code.** `psionic/lib/serve-proto.coax` reads the protobuf codecs
straight from the descriptor with `#import_proto`, and holds:
- `sp_flags`: Content-Type and Accept, read from the head;
- `sp_request_json`: protobuf to NIP-DEC JSON;
- `sp_bytes`: the host's read entry, delegating to chapter 16's `sv_bytes`;
- `sp_answer`: re-encodes the rendered JSON answer.

| Gate | Observed result |

| Command | `PROTO_PYTHON=… psionic/tests/check_serve_proto.sh`: exit 0, 38 s |

Four malformed or undersized cases are refused |

**Found while building it.** The answer encoder first alternated between two
buffers by turn and lost track of which held the response, so an append would
have overwritten its own input. The generated codec refused with its alias
error. It now records which buffer holds the response.

**Not claimed:**
- **Mutation:** `serve-proto.coax` isn't `#authority` (it decides nothing), so
  no mutation run.
- **Projected messages:** results, status, cancel and receipts are not
  projected.
- **The live host:** the host hooks in `serve-host.c` are added with the GPU
  engine, by the agent working on that file.
