# Chapter 229: an interpreter in weights, or one program in weights, 2026-10-30

**Environment:** macOS 26.4 arm64 (Apple M5 Max), coax0 0.24.0 built from this tree, Python 3.15.1. No model weights, GPU or network. The machine was shared with other agents' work during timing (load average 48 to 52).

**What landed**
- `psionic/lib/interpreter-weights.coax` (`#authority`):
  - a register machine with `ip`, `acc` and `r`, four instructions, programs of 1 to 5 instructions, values within 2^24, and its native interpreter;
  - `iw_universal`, one step of the interpreter as a gate graph for programs of up to `slots` instructions, with the program as input;
  - `iw_specialize`, a general partial evaluator over gate graphs: constant folding, known selects, identities, products by a constant, and dead-node removal that keeps inputs;
  - `iw_program_block`, which folds a program into the interpreter for its length and compiles the result;
  - `iw_weights_run`, which runs either block step by step, with the machine's range and halting rule.
- `psionic/examples/interpreter-weights.coax` and `psionic/fixtures/interpreter-weights.out`: the size table, the triangle program from 100, and 200 seeded programs run three ways.
- `psionic/tests/interpreter_oracle.py`: an independent machine and generator.

**Findings while building**
- **Halting.** A jump to itself leaves the state unchanged and would repeat forever. The weights can only see that the `ip` didn't move, so both the native interpreter and the weights now treat any step that leaves the `ip` in place as a halt.
- **Constants for short programs.** Making the slot count a parameter first sized the constants to the slots, so with fewer than three slots the op comparisons read past them. The per-length agreement test caught it.
- **Padding.** The first program blocks were specialized from the five-slot interpreter, and stayed between 27 and 33 nodes for every length. They now come from the interpreter for the program's own length.
- **Halt needs no comparison.** With an op from 0 to 3, the next `ip` for a non-jump is the slot's index plus the addi and addr bits. Removing halt's comparison brought the first layer under the 128-unit limit.
- **binary32 is not enough.** At the edge of the range, 66 of 400 sampled universal steps differ between binary32 and binary64, for example 16,777,213 computed as 16,777,212. A test pins one.

**Mutation history:**
- **First run:** 90 survivors. The report was cut short when reading it, so it was rerun in full after fixing what was shown: pinned outputs for the seeded generator, and negative cases for a test helper.
- **Second run, 58 survivors:**
  - Most were zeros in node fields the operation doesn't read. The graph builder now names only the fields each node uses.
  - Two defaults were set explicitly, and those lines were removed.
  - One term of the next-`ip` sum was only read when it didn't matter, and was removed.
  - The rest were closed with new tests: admission of the first instruction, padding over a junk buffer, a select between a known and an unknown operand, the evaluated step's refusals, and negative cases for the test helpers.
- **Third run, 2 survivors:**
  - A multiply-by-zero test checked a field, not the node kind.
  - The binary32 mutant, killed by the edge-of-range step above.
- **Fourth run:** see the table above.
