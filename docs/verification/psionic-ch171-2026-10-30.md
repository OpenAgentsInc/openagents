# Chapter 230: decode in logarithmic time, 2026-10-30

**Environment:** macOS 26.4 arm64 (Apple M5 Max), coax0 0.24.0 built from this tree, Python 3.15.1. No model weights, GPU or network.

**What landed**
- `psionic/lib/hull-memory.coax` (`#authority`):
  - an index of chapter 225's parabolic keys, one entry per distinct key, sorted, holding its latest write;
  - `hm_insert`, a binary search plus a shift;
  - `hm_read`, a binary search for the score's peak along the hull;
  - `hm_run`, chapter 225's machine with the index in place of the scan. It counts both methods' comparisons.
- `psionic/examples/hull-decode.coax` and `psionic/fixtures/hull-decode.out`: the squares program and a program that fills 64 cells 8 times, each checked against chapter 224's digest, plus one read after 512 writes.
- `psionic/tests/hull_oracle.py`: an independent machine, brute-force scan and binary search.

**Mutation history:**
- **First run, 35 survivors.** The real gaps:
  - a short keys array alone;
  - a trace of exactly the right size;
  - a step budget of 1;
  - a branch back to instruction 0.

  The rest were in test helpers: the sequence generator's constants, the agreement check with no negative cases, and the squares program's arguments, whose output wasn't pinned.

  Two survivors were equivalent in the code itself:
  - which of two tied vertices the search stops on, which the read now reports as `vertex`;
  - a `writes` reset that nothing observes, now removed.
- **Second run, 5 survivors.** All were in the test helpers' failure paths.
- **Third run:** see the table above.
