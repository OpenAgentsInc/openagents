# Chapter 234: a frozen exact core with a learned interface, 2026-10-30

**Environment:** macOS 26.4 arm64 (Apple M5 Max), coax0 built from this tree, Python 3.15.1. No model weights, GPU or network.

**What landed**
- `psionic/lib/core-interface.coax` (`#authority`), profile core-interface-v1:
  - a core of eleven gate-graph nodes (second + top, second − top, second × top, and ip + 1 when top is 0, else arg), compiled by chapter 227 and admitted by chapter 235 by pin, four cases and a recompiled source;
  - twelve interface sources: eight read from chapter 232's fold, and the core's four outputs from one run of the block per row, unavailable outside 2^26;
  - a controller with one softmax over the sources per instruction code and token, trained from zero by full-batch descent on −log P(a source that gives the machine's token); sources training never told apart are reported as ties;
  - a factorial family, to teach `mul`;
  - a rollout that copies each token from its routed source and ends refused when that source is unavailable, and a score that has chapter 232 replay the claimed rows and names the first divergent token.
- `psionic/examples/core-interface.coax` and `psionic/fixtures/core-interface.out`.
- `psionic/tests/core_interface_oracle.py`: an independent reimplementation using only the standard library, with its own machine, an integer core with the same range, its own training and its own replay.

**What the example shows**
- Each controller's training traces are admitted by chapter 245 into its own artifact over a shared exposure ledger: A has 8 traces (220 rows), B has 16 (440 rows). No row is unroutable.
- Controller A, trained on `count` and `sum`: exact on all 8 of their runs, up to n = 32. It is wrong on `stride` at its first `sub`, where `top` and `depth − 1` were never told apart and the tie went to `top`. It is wrong on `squares` and `fact` at their first `mul`, which it never saw and so routes to `zero`.
- Controller B, trained on `count`, `sum`, `stride` and `fact`: exact on 19 of 20 runs, including the held-out `squares` and every length up to eight times training. `fact 12` is refused at step 86 of 127, where the product passes 2^26. No run is wrong.

**Mutation history**
- **First run, 26 survivors.** These led to:
  - the cases give the core's inputs from fewer literals: ip, which it ignores when top ≠ 0, takes second's value;
  - an output exactly at −2^26;
  - the softmax shifting by the routed logit, tested with a logit of 800;
  - ties searched only after the route, which is the first largest logit;
  - a shared `fc_mass` helper with its own test;
  - a ret row only `zero` can give, two equal rows in the hand-computed step, and a row whose x is routable but whose y is not;
  - a run wrong at a token before the core refuses it, which must report the token, not the refusal;
  - the removal of a ret route equal to the default, and of an early return the general path already covers.
- **Second run, 8 survivors.** One admission case had second equal to the ip input, so swapping ip and arg went unseen; its second is now 6. Training's routable test is computed once per row, removing index arithmetic two equal masks hid. The code loop walks the controller's own table, since out-of-range codes are already refused.
