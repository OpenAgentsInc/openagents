# Chapter 186: outcomes become training rows, 2026-10-30

**Environment:** macOS 26.4 arm64 (Apple M5 Max), coax0 0.24.0 built from this tree, Python 3.15.1. No model weights, GPU or network.

**What landed**
- `psionic/lib/training-rows.coax` (`#authority`):
  - time cuts that split a feed into train, calibration, development and held out;
  - `tr_add_outcome`, which admits a decision outcome only with a label from a check or a diff, and refuses one with a missing label or the agent's own summary;
  - `tr_add_trace`, which replays a claimed trace with chapter 173's checker and admits it only on an `exact` verdict;
  - an exposure ledger shared across artifacts that gives each group one role, refusing a row as `crosses` (this artifact) or `reserved` (another artifact);
  - duplicate keys, and a SHA-256 digest over a set's rows.
- `psionic/examples/training-rows.coax` and `psionic/fixtures/training-rows.out`: a 48-outcome feed for two artifacts with different cuts on one ledger, and six traces for a third.
- `psionic/tests/rows_oracle.py`: an independent reimplementation of the feed and the rules, with `hashlib` digests.

**What the example shows:** the second artifact, with earlier cuts, has 19 of its 36 labelled outcomes refused as `reserved`, because the first artifact already uses those groups in another role. A trace that replays exactly is still refused when it is filed under group 9, which the first artifact uses for development. This is the pre-reset audit's failure, where all 41 replayed traces came from calibration or development groups.

**Mutation history:**
- **First run, 7 survivors:**
  - The word encoder's shift direction and width were untested above one byte, because every vector used small values. A key vector with a group of `0x0102030405060708` closes both.
  - A `budget>0` check in `tr_add_trace` duplicated chapter 173's own shape refusal. It was removed.
  - The tests' hex comparison had no negative cases. Three were added.
