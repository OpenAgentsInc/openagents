# Chapter 26: the Coax compute subset on CUDA, 2026-10-29

## What was built

- `coax cuda FILE` (coax0 0.23.0) emits CUDA C for NVRTC from the checked
  tree. Admission is the Coax policy `coax/lib/compiler/compute.coax`
  (`#authority`, 134 mutants, zero survivors, also gated by the bootstrap);
  `coax/src/compute.cpp` walks the kernels and reports E0700 and E0701.
- `psionic/lib/device/project.coax`: the BF16 projection kernels
  (`dv_project`, `dv_matvec`, `dv_reduce`), `#authority`, 231 mutants, zero
  survivors, debug and release checks.
- `psionic/platform/cuda-host.c`: the host effects. It opens `libcuda.so.1`
  and NVRTC with `dlopen` (no CUDA headers or toolkit at build time), compiles
  the generated source with `--fmad=false --prec-div=true --prec-sqrt=true
  --ftz=false` for the device's compute capability, loads the PTX with
  `cuModuleLoadDataEx`, and allocates, copies, launches and waits.
- `psionic/tests/device_project.c`, run by
  `psionic/tests/run_device_project.sh`.

## Tolerance, frozen before measuring

Device results were compared two ways before any device number was read:

1. Against the same Coax kernels compiled to C (`coax c --release`, built
   with `-ffp-contract=off`) and run over every work item: the outputs must be
   identical bit for bit. The kernels use only +, -, *, conversions and bit
   reinterpretation, which the profile rounds once each on both devices.
2. Against the CPU reference profile (`qm_project`, CPU-f32-wide-v1: f64
   products and compensated sums): for each output,
   `|device - reference| <= 2^-15 * sum |w x|`. The kernel's own worst case,
   `(258 + cols/256) * 2^-24 * sum |w x|`, is below that bound for every
   Elephant shape.

Weights were random finite BF16 values of magnitude 2^-8 to 1 and either sign;
activations uniform in [-1, 1]. The reference was sampled at four tokens per
shape.

## Results

Every case met both conditions: zero differing outputs against the same
kernels on the CPU, and the largest reference error was 1.2e-7 of
`sum |w x|` (bound 3.05e-5).

| --- | --- | --- | --- |
| 248,320 x 4,096 x 1 (vocabulary readout) | `dv_matvec` + `dv_reduce` | 3.49 ms | 583 GB/s |
| 12,288 x 4,096 x 1 | `dv_matvec` + `dv_reduce` | 0.196 ms | 514 GB/s |

| 1,024 x 4,096 x 86, 16 slices | `dv_project` + `dv_reduce` | 0.206 ms | 3.50 TFLOP/s |

Times are the mean of 20 launches after one warm launch, from CUDA events.
The one-token readout reads its 2.03 GB of BF16 weights at 81% of the card's
717 GB/s; the clocks were not pinned and other processes shared the GPU.
The batched kernel has no shared memory or tensor cores and reaches about a
quarter of the card's non-fused f32 rate (24 TFLOP/s).

Negative admission: `coax/tests/cuda.py` refuses each construct outside the
subset (strings, structs, enums, arrays over 1,024 elements, non-numeric
views, `while`, `defer`, `#assert`, `print`, `#foreign`, recursion,
`value_barrier`, results, a non-`int` work item, deep call chains) with its
named reason, and a file without a kernel with E0701.

Completion and lifetime: each launch completes before its buffers are freed,
and modules are unloaded after use. An out-of-bounds read in a generated
kernel traps the launch; the host reported `CUDA error 719 (unspecified
launch failure)` at the next completion point. The context cannot be used
after that, so the harness does it last.

## Limits

- One machine, one driver and one NVRTC version.
- Random data at Elephant's shapes, not the original weights; chapter 30
  records the original-weight decision.
- No shared memory, barriers, atomics, warp exchange or tensor cores in the
  subset. Performance counters were not available (`ERR_NVGPUCTRPERM`; see
  `NEEDS_OWNER.md`).
