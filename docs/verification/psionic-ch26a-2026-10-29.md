## Independent semantics and measured memory

`psionic/tests/tensor_ir_oracle.py` uses Decimal(100) equations and an independent
logical coordinate/storage representation; it calls no Psionic inference,
planner or arithmetic. The generated graph definitions and expected values
cover:

- Two affine/ReLU feed-forward blocks, `[2,3]→4→2` and `[32,48]→64→32`.
- Reverse/transposed views followed by constant gather and reduction.
- Contiguous reshape, scalar broadcasting and multiplication.
- Population LayerNorm and an axis reduction.
- A computed root used later through an alias, extending its liveness.
- Empty-axis sum, zero-inner matrix product and empty gather.
- Scalar output, noncontiguous view output and zero-stride broadcast view.

The tiny block's independent answer is exactly `[3.5, 5.5, 1.5, 2.5]`.
The maximum scaled error observed across the fixtures, including comparisons
with the CPU reference, is **2.08616257e-07** on CPU, CUDA and Metal in every
final build configuration. This is a fixture qualification, not a worst-case
error proof over all finite f32 inputs. Metal inherits the subnormal arithmetic
profile recorded in chapter 3b; no new universal bit-equality claim is made.

| Workload | Scalar work | Fresh intermediate storage | Planned workspace | Observed five-buffer payload |
| --- | --- | --- | --- | --- |
| Tiny feed-forward | 60 | 32 floats / 128 bytes | 16 floats / 64 bytes | 3,316 bytes |
| Larger feed-forward | 168,960 | 8,192 floats / 32,768 bytes | 4,096 floats / 16,384 bytes | 59,776 bytes |

The native allocator increments its counter and byte tracker only after each
successful allocation. The totals equal the Coax-admitted layout, and the
workspace allocation is tracked separately. No new tensor buffers are allocated
by a replay. These metrics measure requested live payload, not reserved driver
pages or process RSS. They include input/workspace/stage/flags/device metadata;
native graph/control structures, host readback/metadata copies, per-launch
argument/check buffers in the driver adapters, compiled modules/contexts and
allocator overhead are outside the explicit buffer budget.
The bound is conservative and does not claim allocator optimality or a
throughput improvement.

The native checks also cover changed shape/layout/dtype/compiler/device/backend/
module cache keys, copied graph ownership, occupied handles, budget/shape/
dependency failures, actual native input/output/metadata/workspace overlap,
short input/output spans, infinity/sNaN/qNaN, arithmetic overflow with complete
caller-output preservation, successful reuse after numerical failure, and
release of poisoned idle objects. Coax's lifecycle tests distinguish busy,
ready and poisoned states. A simulated effect error drives native poisoning;
a real driver fault is not injected.

## Metal compiler limitation and scope

Two attempts to create a pipeline from the initial bounds-checked MSL candidate
failed inside Apple's compiler with `XPC_ERROR_CONNECTION_INTERRUPTED` after
its internal retries. Its source digest was
`0281d1930b8ad5c314427730212b023a344672000ff166027807bbfaf952da62`.
Release emission ran the same candidate's equations successfully. The final
release artifact, including canonical positive-zero ReLU, then passed all
four final native configurations. The current gate therefore uses release
Metal emission and makes no checked-MSL pipeline qualification claim.
No compiler source or native handwritten arithmetic was substituted.

The IR is explicit library data, not automatic capture of arbitrary Coax
functions. The subset is static f32, read-only aliases and constant gathers;
unsupported dtypes/placements/layouts refuse. The native arena is separate
from chapter 3b's opaque `PtdTensor` handles; inputs are explicit host bindings,
with no implicit device fallback/readback. Dynamic shapes, direct tensor handle
binding, graph extraction, in-place updates, differentiation, fusion,
persistent compilation caches, physical GPU ordinal selection and full-model
throughput qualification are outside this chapter.

Full mutation runs were omitted under the owner's explicit instruction to use
focused changed-code checks. There is no zero-survivor mutation claim for the
new IR profile. No owner action is required.
