# Chapter 45: share the card, 2026-10-29

## What was run

Chapter 44's pinned original `baselabs/elephant-1` revision `b3f8a934`,
authenticated by chapter 14's session, on the RTX 4080 (driver 595.71.05,
coax0 0.24.0). The card was shared: another agent's gpt-oss-20b Responses

The request is chapter 14's sample (86 tokens, 49-token prefix).

## Changes

- `psionic/lib/device/plan.coax` (`#authority`): 277 streaming indices
  instead of 96: the 96 feed-forward matrices as before, 152 mixer matrices,
  and 21 head chunks of up to 12,288 rows. Residency streams feed-forward
  matrices first (unchanged order and plans for every budget chapter 30
  used), then the head, then whole layers of mixers in bit-reversed order.
  A copy carries a host byte range; the readout runs per chunk when the head
  streams. The smallest budget is the workspace, the f32 vectors (4.25 MB) and
  two 96 MiB slots: 283 MiB at 86 tokens, 676 MiB at 512.
- `psionic/platform/elephant-gpu.c`: copies read the op's byte range (and
  refuse one outside the pinned weight or larger than a slot); the stream
  array is `EG_STREAMABLE`; the default reserve below free memory is 256 MiB,
  not 512, so a 512-token placement fits beside gpt-oss.
- `elephant-metal.{c,h}`: the array size only (Metal still refuses streaming).
- `psionic/tests/elephant_device.c`: the plan line counts copies.
- Book: chapter 45, its example `psionic/examples/share-the-card.coax`;
  chapter 44's listing and limits; chapter 44's example resized.

## Checks

- `coax test psionic/lib/device/plan.coax`: 47 checks pass. Among them: a
  plan checker (`dp_resolve`) that tracks each slot through copies, waits and
  releases and rewrites slot views as host bytes. A plan streaming 42
  feed-forward matrices resolves to the resident plan's 1,092 launches with
  the same digest; a plan streaming all 269 matrices and chunks resolves to
  the resident launches up to the readout, then 21 chunk products covering
  all 248,320 rows. The resident plan's digest is unchanged.
- `coax mutate psionic/lib/device/plan.coax --shard I/4` (4 x 6 jobs): 2,490
  mutants, 0 survivors, 3 min. A first run left 26 survivors (equivalent
  range checks and untested checker branches); the code was restructured and
  the checker tested with crafted broken schedules, not exempted.
- Both book examples in debug and release match their fixtures;
  `python3 -I psionic/tests/book.py` passes.

`psionic-serve --elephant-gpu DIR --table psionic/fixtures/text/ch05/qwen35.pst
--port 8797 --capacity 512`. Placement: 0.22 GiB resident, 14.56 GiB pinned,
plan budget 0.90 GiB, in 8.5 s. Authentication took 253 s (load average 47).
Per-process device memory afterwards: gpt-oss 13,874 MiB, Elephant 1,140 MiB,
249 MiB free.

Six requests of `psionic/fixtures/models/serve/elephant-request.json`, `curl`
`time_total`: 689.5, 674.1, 677.7, 675.0, 673.2, 678.5 ms; all `200`, `yes`,

its API key was refused 401, as configured); its generation was not timed.

## Not done

- gpt-oss was idle during the measurements. Concurrent generation shares the
  link and the compute units and has not been measured.
- The C host was built with `-Wno-misleading-indentation` through a wrapper
  `COAX_CC`, because `cuda-host.c` (not changed here) fails gcc's warning
  under `-Werror`.
- Authentication took 195 to 253 s at each start, with the host's load
  average near 50 from other work; the identity cache is the next change.
