The first exhaustive run failed and found: `exp` returned infinity for inputs
between 88.72 and log FLT_MAX (threshold fixed to 88.7228394); `log` lost

range was moved to 2^-86 (40 bits); the bound was not changed, and results
between 2^-126 and 2^-86 are reported (5.96e-8), not judged.

- Session 1 (before the A-fragment cache): 3155.9, 2828.1, 2540.4, 2425.6,

Against chapter 30's 147 ms on the RTX 4080: about 19 times slower. The
second session ran while the served copy was resident and the machine was in
use, which may account for its higher median. Profile (one command buffer per
launch, session 2): 2028.8 ms of GPU time, `dw_project` 1828.6 ms (90.1%),
`dl_scan` 44.9 ms, `dv_reduce` 42.2 ms, everything else under 25 ms per kernel.
In the kernel benchmark the 86-token projections run at 0.44 to 0.94 TFLOP/s;
the shuffles that gather each lane's MMA operands set the rate. Register error
words (instead of atomics inside checks) made them 8 to 11 times faster;
keeping the gathered weight rows between MMAs on the same fragment, about 1.4
times; vector shuffles and `simdgroup_float8x8` tiles did not help.

Session open: authentication 113 to 215 s (hashing the 18.8 GB checkpoint on
the CPU), weight copy into shared memory 3.7 to 6.2 s, Metal compile 0.4 s.

## Limits

One request shape, one machine. The projections are shuffle-bound; the
compute subset has no threadgroup memory or barriers, so Apple's matrix units
are not used through shared tiles. No batching or prefix reuse. Mammoth has
not run. gpt-oss-20b on Metal is issue #12607.
