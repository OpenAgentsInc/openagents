The `cpu-topk-affine-v1` profile routes one token over 1–128 finite `f32`
logits, selecting 1–4 experts, never more than the number of logits. It sorts
descending by score with lowest-ID ties and softmaxes only the selected scores
using `f64` exponentials, compensated accumulation and `f32` weights. The tiny
forward path uses width 1–16 affine experts, resident descriptors in arbitrary
order, shared chapter 4 matrix/add kernels and a checked weighted combination.
Its output publishes only after all selected work succeeds.

The pinned local `openai/gpt-oss` source revision
`5681a6b6552635e7b29cde94a61ca6a7aee90ebd`,
`gpt_oss/torch/model.py`, lines 312–336, specifies sorted top-k followed by
selected-only softmax and expert dispatch/combination. No upstream code was
executed. The teaching profile's lowest-ID ties and wide CPU arithmetic are
explicit Psionic choices, not a cross-backend PyTorch or BF16 parity claim.

Reproduce from the repository root:

```shell
coax/build.sh
psionic/tests/check_moe.sh
python3 -I psionic/tests/book.py --coax coax/bin/coax
```

`COAX=/absolute/path/to/coax` selects an existing compiler. The main
`psionic/check.sh` includes this unit and its oracle/native harness; the entire
multi-chapter mutation suite was not rerun for this bounded addition.

The resident budget counts logical matrix/bias payloads, including unselected
entries, and is not an OS memory reservation or full process-memory bound.
The host adapter observes overlaps, while pointer validity, truthful extents,+alignment, model association, lifetime and exclusive access remain caller
obligations. The teaching expert matrices are synthetic `f32` affines, not
original gpt-oss projections. Normalization, learned gate projection, original
MXFP4 expert binding, clamped SwiGLU, residuals and complete gpt-oss execution
remain separate gates. No GPU or Linux target qualification is established.
