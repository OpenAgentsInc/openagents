# Chapter 52: bounded tokenizer families and templates, 2026-10-30

Started from chapter 49, 8d2b41e0fc. Profiles: `bert-ascii-wordpiece-v1`,
`t5-ascii-unigram-v1`, normalized UTF-8 Unigram and `jinja-chat-subset-v1`.
All work used CPU only: no GPU query/context/kernel or model decision.

- Debug and release: **38 check groups pass** each (including inherited UTF-8
  JSON checks). Exact limits, malformed syntax, nested conditions, inactive
  branches, whitespace, typed scalar unknown edges and fusion are covered.
- Mutation: **1,819 total, 1,819 killed, zero survivors**; no equivalent markers.
  Removed redundant conditions and exposed useful score/compiler-query
  contracts rather than accepting surviving mutants.
- Native debug/release (-O0/-O3), plain and ASan/UBSan: all four pass with
  `-ffp-contract=off -fno-fast-math`. Each checks **290 original-vocabulary ID
  vectors** and **12 Jinja outputs**. Native nonfinite vocabulary scores refuse.
- Original full BERT and T5 tokenizer DATA, exact Hugging Face revisions,
  SHA-256 identities, normalization mappings and upstream expected IDs are
  recorded under `psionic/fixtures/tokenizer-families/`. Expected IDs came
  from installed tokenizers 0.22.2, without model inference. Every ASCII byte
  is tested between letters. Jinja2 3.1.6 rendered the real TinyLlama template,
  plus separate conditional/concatenation fixtures with trimming enabled.
- Debug/release example stdout agrees byte for byte. Book source listings,
  inventory and local links, shell syntax and diff whitespace pass.

`tokenizer_families_capture.py` is opt-in tooling for local pinned JSON and
installed upstream packages. It never executes downloaded source. The normal
`check_tokenizer_families.sh` is offline and Python-stdlib-only. Its constituent
passing gates were run incrementally and not repeated unchanged.
`validation.json` records transitive compiler/source inputs and successful
logs. Coax 0.23.0 / GCC 15.2.0, Linux CPU.

Limits are material: the wrappers accept ASCII source, using complete pinned
ASCII normalizer mappings; full Unicode charsmap/accent/CJK processing,
SentencePiece BPE, sampling and upstream added-token/postprocessing behavior
are not claimed. The underlying Unigram accepts normalized UTF-8. The Jinja
interpreter is the chapter's documented bounded subset, not general Jinja.
It renders bytes; typed special-token boundaries remain adapter work.
All view storage remains immutable and valid for the call. Results own their
storage and return zero payload on refusal.
