## Full-size file-backed rows

Original shard 47 has a 664-byte header prefix and length 101,535,150,936;
shard 48 has a 672-byte prefix and length 101,537,926,640. Both place all
E4M3 code rows before their per-row/per-32 UE8M0 scales. The retained raw
headers confirm shapes, dtypes and intervals. Unit checks also admit reverse
tensor order, exact adjacency and gaps and reject overlaps or invalid extents.

The native harness creates sparse owned files with those exact lengths and
offsets: **203,073,077,576 logical bytes, 401,408 allocated bytes** on this
filesystem. Each contains 24 selected owned rows, using original hashed IDs
and the exact last row as a boundary case. The files are deleted on close.
For both `mmap` and `pread`, the two layers request **12,672 payload bytes**
and decode **12,288 BF16 words** equal to independent scalar equations.
This request count excludes OS pages, faults, readahead and cache effects;
physical disk traffic and whole-model memory were not measured.

A layer uses 6,336 packet bytes and 12,288 decode-work bytes, plus its BF16
output. The C adapter uses 48 planned and 48 draft descriptors on its stack;
it maps read-only lazily or reads only planned ranges. C observes span
addresses and actual file length and performs I/O effects. Coax owns shape,
identity, capacity, alias, range, numeric and publication decisions.

Failures cover real overlapping allocations, exact capacity limits, invalid
IDs, bad FD, shortened file and a malformed scale at the last row's last
group. Both I/O modes preserve every public output word and spare tail on
late decode failure. The whole packet is read before staging BF16 words, and
all decoded words stage before public publication. Private work may change.

The caller owns valid typed allocations/extents, immutable admitted map bytes,
complete-file authentication and correct unmodified tensor identity/metadata,
matching model/history, immutable file and FD lifetimes and exclusive disjoint
writes. Length observation is not authentication. Concurrent truncation of a
mapped file violates that lifetime contract.
