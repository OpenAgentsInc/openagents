## Placement and state contract

Seed counts enter as integer uses; initial slots remain empty until installation
succeeds. Heat uses 1,024 units per use. After recording a finished step's unique
selected global keys, every 256th finished step floors heat times 9/10. A hot
outsider must satisfy `4*hot > 5*cold + 4096` to replace a populated slot.
Incoming/seed ties use lowest expert ID; victim ties use lowest physical slot.
Frozen caches fill empty slots but never evict. A slot moves once per plan;
evicted IDs are reconsidered only in a later plan.

This owned integer placement policy can differ from the old floating heat
implementation. Its purpose is deterministic byte placement; it never changes
selected model IDs/weights, coefficient values or the arithmetic profile.
The per-layer planner uses a 384-entry presence set and work proportional to
`slots * (experts + slots)`.

A returned header carries identity, finished-step count, residency revision and
active/idle state. It is a single-owner value continuation, not a lock. Active
dispatch holds residency stable; prefetch derives only missing keys from the
next gate's actual selected IDs. It never increments heat or installs a slot.
Finish stages the complete heat and returns the next idle header. Installation
checks model/step/revision tickets, expected old occupants, unique destinations,
proposed bindings and completed-copy receipts before any public byte/slot write.
Late refusal preserves all public bytes and metadata; private work may change.
Finish enforces both the global use-count limit and eight uses per layer.

Callers own source/model/packet authentication, immutable lifetimes and FD
ownership, matching dimensions/identity, unmodified successful plans, truthful
receipts for completed copies, valid typed allocations/extents, accurate uses,
linear header ownership and exclusive disjoint writes. File length observation
is a shape check, not authentication. Cancellation/concurrent request fencing
and complete model-step publication remain engine responsibilities.
