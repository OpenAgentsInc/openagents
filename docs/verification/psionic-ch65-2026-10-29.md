## Math and grouping contract

Each matrix row/eight-token tile decodes a coefficient once, then adds products
to each output's independent TwoSum/correction state in increasing column
order. This is chapter 63's exact CPU reduction, not a tree sum or vendor GEMM.
FP4 retains low-first nibbles and per-row/per-32 UE8M0 scales; shared FP8 retains
its per-32-by-32 scale layout. Per-token FP8 activation quantization, clamped
SiLU/up, F32 route weighting before down-input quantization and output narrowing
are unchanged. Invalid encoded values or overflow refuse publication.

Grouping retains each original token/route ordinal. Gather keeps each row's
route weight attached; scatter restores that ordinal. Combine uses the token's
original route order, narrows the routed sum to F32 and then adds one shared
result. Missing receipts or late numerical failure preserve the complete public
output and spare tails. Private work/contributions can change on failure.

The cursor requires attention, route, every active expert, shared and combine
receipts before advancing a layer. Only the last layer can reach chunk commit.
It rejects wrong epochs, layers, phases, group ordinals and failed receipts.
It is a single-owner value continuation, not model authentication or a lock.
The caller owns model/history identity, valid immutable source/plan lifetimes,
truthful receipts, correct live-memory/cost calibration, valid typed allocations
and exclusive disjoint writes. Whole-model storage, request fencing and atomic
model-state publication remain engine responsibilities.

## Budget policy and independent scheduling evidence

Cost is `fixed + N*token + min(experts,N*selected)*expert` in integer nanoseconds.
The chosen chunk is the largest fitting both that target and the configured
workspace/live bytes per token. Grouped mode rejects maximum 1, and refuses a
budget that only admits a singleton while multiple tokens remain. A final
tail of one and explicit serial mode are reported separately. No configuration
silently selects the serial algorithm.

The native fixture calibrates its per-token cost from the two-layer serial
reference and its per-expert term from an actual file fetch, folded across both
layers. It records both prediction and observed chunk duration. This is an
estimate, not a hard real-time guarantee: some small debug chunks exceeded the
prediction. Calibration drift, context-dependent attention and contention must
be accounted by the integrating engine; no whole-model latency bound is claimed.

An independent owned oracle sorts bounded gate priorities and constructs
buckets by selection rather than the implementation's count/prefix/cursor
algorithm. The bounded fixture's gate jitter dominates its normalized data
term, making its selected IDs independently known. All keys, offsets, assignment
ordinals, routes and weights agree for chunks 2, 4, 7 and 13 over thirteen tokens
and two layers. All **832 output words** and the complete causal prefix cache
are bit-identical to token-major execution.

The attention fixture is explicitly an owned causal prefix mean plus a residual,
not V4.1 MLA. It supplies real cross-token/cross-layer dependencies for this
bounded scheduling test. Every selected expert packet is fetched once per
layer/chunk, through mapped or direct file I/O. Fetch counts are **33, 22, 12
and 6**, versus **52** token-major routed uses. The shared expert executes once
per layer/chunk. Late final-layer faults preserve an empty prefix and a prefix
already committed by an earlier chunk. Real aliases, dirty work, exact extents,
spare tails and ragged eight-token tiles are checked.
