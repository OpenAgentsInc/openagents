## Independent bit qualification

The standard-library oracle never imports upstream code. It enumerates a
monotone scalar codebook and chooses nearest values independently from Coax's
binary search. It computes exponent ceilings with `frexp`, and BF16 rounding
by comparing adjacent representable values instead of Coax's bit-bias formula.
F32 operations have explicit rounding boundaries. There is no numerical
tolerance: admitted codes, scales and reconstructed BF16 words must be exact.

Each of the three profiles checks all 65,536 BF16 patterns in uniform, sparse
and fixed-anchor groups: 589,824 group cases in each native build. Anchors
hold a maximum in another lane to expose rounding boundaries. Sparse cases
rotate the nonzero/bad lane and include all refusal cases.

All 73,728 scalar code/scale pairs also agree, including malformed and overflow
cases: 70,294 admitted, 2,862 invalid, 572 arithmetic refusals. Another 195,834

Native checks exercise real overlapping spans with truthful allocations,

consistent format/model/history identity and exclusive disjoint writable spans.

## Persistent cache and chunk work

The generic planner accounts for persistent code/scale payload and a separate
live codec inventory `6*N + 2*P` for a chunk with N values and P packed bytes.
It includes BF16 input, decoded output and decode scratch, plus packed output
and packing scratch. A chunk can exceed the persistent ring's row count.

The pinned Flash specialization counts 40 backbone windows and zero to three
draft windows, each 128 rows of 528 bytes. Only layers 2, 8, 14 and 20 own
compressed KV and index keys; the first three use ratio 2 and the fourth ratio
1. The remaining four indexer source layers reuse keys. The per-context source
rows are therefore `3*floor(context/2) + context`, each with 288 compressed KV
bytes and 68 index-key bytes. Codec work uses the larger 32×128 index-query
row, requiring 28,928 bytes per chunk token under the explicit inventory.

An independent per-layer inventory reads the retained original configuration,
enumerates owners and layouts and checks 72 context/chunk/draft combinations,
including odd contexts and context 1,048,576. Each checks exact admission and
refusal one byte below either budget. Context 1,024, chunk 64 and three draft
windows require 3,817,472 persistent bytes and 1,851,392 codec work bytes.

These logical counts exclude alignment, page tables, shared prefixes,
compressor state, attention scores/candidates, other activations, weights,
commands and scheduling overlap. No measured allocation or whole-model memory
claim follows from them. Full attention must budget those other allocations.
