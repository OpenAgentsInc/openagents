# Chapter 70: learning with arrays, 2026-10-29

Verified on macOS 26.4 arm64 (Apple M5 Max) with Apple clang 21.0.0, Python
3.15.1 and coax0 0.24.0. No model weights, GPU, network or upstream code were
used.

`psionic/lib/tabular.coax` implements profile `cpu-f64-sgd-v1`:
- binary64 storage and arithmetic, chapter 3's compensated accumulator for
  every sum, no FMA or reassociation;
- the deadline simulator `deadline-sim-v1`, up to 512 sessions of 8 requests;
- session-grouped splits (3:1:1 by session number) and feature scaling from
  training rows only;
- affine models (a line on half squared error, logistic regression on log
  loss) and one tanh hidden layer of up to 16 units, at most 8 features;
- minibatch SGD with hand-written gradients, L2 decay on weights only, a
  slot-indexed initialization and a Fisher–Yates shuffle whose counter
  persists across epochs;
- at most 4,096 rows, 512 epochs, batches of 1 to 256 and 2²⁴ row-parameter
  visits; features, targets and parameters within ±2²⁰;
- log loss, squared error, a constant predictor, cost-weighted decisions, a
  validation threshold grid (0.05 to 0.95) and an operator's handwritten rule.

## What mutation testing changed

The first run left 104 survivors. They were fixed in code and checks, not by
exemption:
- **Branches whose sides agree at the boundary** were rewritten without the
  branch: a sigmoid as `exp(min(z, 0)) / (1 + exp(−|z|))`, a batch loop that
  closes a batch on a count instead of clamping an end index, and the label
  and rule comparisons moved into `tb_on_time`, which a check exercises at
  exactly 9 s.
- **Shared admission helpers** (`tb_in`, `tb_row_ok`, `tb_table_ok`,
  `tb_model_ok`, `tb_budget`) with checks at every inclusive edge, including
  4,096 rows, 8 features and a work count exactly at, and one past, 2²⁴.
- **An unreachable check removed:** gradients can't overflow inside the ±2²⁰
  domain, so the gradient no longer tests for it.
- **Layouts that tell indices apart:** checks use 3 inputs and 2 hidden units,
  so `h·d` and `h + d` differ.
- **A two-epoch oracle check** pins the shuffle's starting counter, its
  persistence across epochs, the short last batch and the copied row order.

## Not claimed

- **Simulated data.** Chapter 14's measurements are not used yet.
- **No leakage claim.** A row-level split looked better at seed 70 but not
  across seeds 72–76; the chapter claims nothing about it.
- **No calibration measurement** of the predicted probabilities.
- **Five seeds,** not a benchmark of model families.
- **Process:** checks were written alongside the code, not run against stubs
  first.
