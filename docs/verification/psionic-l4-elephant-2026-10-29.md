(`cuModuleLoadDataEx`: CUDA error 222, PTX from an unsupported toolchain);

## Cold start

| Start | L4 | RTX 4080 |
| --- | --- | --- |
| First ever (harness): NVRTC compile 7.4 s, authentication 193.9 s, upload 14.79 GiB in 15.5 s, first decision | 220.7 s | 101-215 s (chapter 44) |
| Server, with chapter 19's verified-file record present: compile 0.73 s, authentication 0.33 s (hash skipped), placement 61.6 s | 62.7 s to listening | 76 s (ch16, full hash 72.7 s, placement 1.34 s) |

The L4's cold start is disk-bound: authentication hashed 18.8 GB at about
97 MB/s, and placement reads the mapped checkpoint from `pd-balanced` at
about 260 MB/s, because 16 GB of RAM cannot keep the file in the page cache.
A faster disk (pd-ssd or a local SSD) or a larger machine would shorten
placement; the hash is now cached.

| First request after start | 485 ms | |

All 100 answers were `200`, `yes`, p(yes) 0.757202773.

The served L4 decision is about 1.6x the 4080's. That is in line with the
cards: the L4 is a 72 W part with about 300 GB/s of memory bandwidth against
the 4080's 717 GB/s, and the 86-token projections that dominate chapter 44's
profile are compute- and bandwidth-limited. The card ran at 1,995 MHz,
54 C and 65 W during the run.

## Chapter 170 load generator

`bench-drive systemone 8797 elephant-1 115 150 600 50 --label
l4-g2s4-elephant-gpu-cap512` (chapter 170's built-in decision workload,
varied input lengths, open-loop arrivals every 600 ms +-50%):

| Metric | L4 |
| --- | --- |
| answered / refused busy / failed | 150 / 0 / 0 in 90.0 s |
| end to end P50 / P90 / P95 / P99 | 542.8 / 903.2 / 976.5 / 1,075.2 ms |
| server inference (`latency_ms`) P50 / P90 / P95 / P99 (n 132) | 505 / 780 / 789 / 797 ms |
| end to end less inference P50 / P90 / P95 / P99 | 39.1 / 376.3 / 413.3 / 676.5 ms |

The tail above inference is queueing: the server decides one request at a
time, and at this rate a request often waits behind the previous one. There
is no 4080 figure for this workload (chapter 170's decision run found the
server down). 18 answers carried no usable `latency_ms`, as chapter 170 saw
once on the toy.

The server runs as the systemd unit `psionic-elephant.service` (enabled, so
it comes back after a stop/start or a spot preemption), `--elephant-gpu
--port 8797 --capacity 512`, on `http://127.0.0.1:8797/v1/systemone` only.
Reach it through an IAP tunnel:


while stopped):

```shell

```

## Limits

- One spot VM, one driver, one request profile; clocks not pinned.
- The VM was preempted once, 16 minutes after creation, and restarted in the
  same zone. Spot capacity can stop it at any time
  (`--instance-termination-action STOP`).
- Prompts longer than 128 tokens (the Lab bodies, the load generator's
  workload) were not compared against the CPU reference, as on the 4080.
- The Coax outputs were generated on an Apple host, not by a compiler built
  on the VM.
