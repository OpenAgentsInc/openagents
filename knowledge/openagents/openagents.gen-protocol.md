## Answer

If the composition lived inside one application it would be a product architecture; because every step is a signed record it is closer to a public agent that applications run. The OpenAgents NIPs carry it: NIP-CJ the turn and its offers, NIP-DEC typed decisions, NIP-KB knowledge, NIP-EXT plugins as signed releases, NIP-PRG typed workflows, NIP-CAP operation descriptions apart from grants, NIP-RUN a run's lock and outcome, NIP-EVAL reports, checks, validations, and adoption, and NIP-XP credit.

## Details

- Three consequences: plugins are portable, evidence outlives the evaluator (a result names its subject, baseline, test set, gate, and signer, and a dispute is itself a signed record), and the agent is not owned by one vendor.
- Status is each contract's: NIP-DEC, NIP-KB, NIP-HOST, NIP-REACH, and NIP-XP are Implemented; NIP-CJ, NIP-EXT, NIP-PRG, NIP-CAP, NIP-RUN, and NIP-EVAL are Partial; NIP-SESS, NIP-ATIF, and NIP-OPT are Designed.
- Where it comes from: the essay The Return of the General Agent, linked on GitHub at `https://github.com/OpenAgentsInc/openagents/blob/main/docs/essays/2026-10-01-the-return-of-the-general-agent.md#part-iv-the-protocol-is-the-agent`.
