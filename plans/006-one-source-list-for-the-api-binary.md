## Why this matters

The list of C files that make up the API binary is written out by hand in
five places. Two of them were not updated when new units were added on
2026-11-02 and 2026-11-03, so `coax/web/api/mesh-test.sh` and
`coax/web/api/eval-builder.sh` no longer name every file that `api.c`
calls into. Both scripts should now fail at link time with undefined
symbols, which means the mesh route's test and the realm builder's eval
cannot run. Every new API unit needs five matching edits, and they are
easy to miss. This plan puts the list in one place for the four local
scripts and adds a check that the production Dockerfile agrees with it.

Conventions:

- A new shell file must carry a header line that starts `Firm reason:` and
  names one of six allowed reasons. An existing example is

  `# Firm reason: 5 (a thin wrapper: compiles the API and the CLI, starts a throwaway PostgreSQL and the API on it, and runs the Coax checks)`.

  The file this plan adds is a list and three `coax c` calls, which fits.

### Step 2: Create the shared list

Create `coax/web/api/api-sources.sh`. It is sourced, not executed. It
defines one function. The caller passes the directory of the API sources,
a work directory and the Coax compiler:

```bash
#!/usr/bin/env bash
# Firm reason: 5 (a thin wrapper: the one list of the API binary's C files, and the three coax c calls that make its policy C)
# Sourced by test.sh, realm-gate.sh, mesh-test.sh and eval-builder.sh. The production
# image's list is the Dockerfile's; test.sh checks that the two agree.
#   api_sources DIR WORK COAX   generates the policy C into WORK, and sets the array
#                               API_SOURCES to every file of the binary. Compile with -I"$WORK".
api_sources() {
  local a="$1" work="$2" coax="$3" m
  for m in anime-director-policy seat-policy progress-policy; do
    "$coax" c "$a/$m.coax" --library --header "$work/$m.generated.h" > "$work/$m.generated.c"
  done
  API_SOURCES=(
    "$a"/api.c "$a"/analytics.c "$a"/admin.c "$a"/player.c "$a"/rooms.c "$a"/npc.c "$a"/room.c
    "$a"/private.c "$a"/drops.c "$a"/villa.c "$a"/chat.c "$a"/realms.c "$a"/access.c "$a"/makers.c
    "$a"/inference.c "$a"/mesh.c "$a"/mesh-policy.generated.c "$a"/caller-policy.generated.c
    "$a"/nip98.generated.c "$a"/anime.c "$work"/anime-director-policy.generated.c "$a"/seats.c
    "$work"/seat-policy.generated.c "$work"/progress-policy.generated.c "$a"/nostr.c "$a"/email.c
    "$a"/jobs.c "$a"/relay.c "$a"/verse_packs.c
  )
}
```

If the drift check showed a unit added to `test.sh`'s list since this plan
was written, add it here too, in the same position.

**Verify**: `bash -n coax/web/api/api-sources.sh` exits 0, and

prints `ok`.

### Step 3: Use it in the four scripts

In each script, source the file once near the top, after `here` (or `a`) is
set: `source "$here/api-sources.sh"`.

- **`test.sh`**: replace the three `"$cli_coax" c ...policy...` lines
  (31-33) with `api_sources "$here" "$work" "$cli_coax"`, and replace the 29
  file arguments on the compile line with `"${API_SOURCES[@]}"`. Keep every
  flag, `-I` option and library exactly as it is.
- **`realm-gate.sh`**: the same, at lines 36-42. That script's variables are
  `$a` for the source directory and `$coax` for the compiler.
- **`mesh-test.sh`**: before the compile at line 14, add
  `api_sources "$here" "$work" "${COAX:-$here/../../bin/coax}"`. Replace the
  file arguments with `"${API_SOURCES[@]}"`. Add `-I"$work"` to the `flags`
  array at line 13.
- **`eval-builder.sh`**: before the compile at line 23, add the same
  `api_sources` call. Replace the file arguments with
  `"${API_SOURCES[@]}"`. Add `-I"$work"` to the compile line's include
  flags.

`mesh-test.sh` and `eval-builder.sh` had no compiler variable before. They
now need `coax/bin/coax`. If it is missing, `coax/build.sh` installs the
published build in seconds.

**Verify**: `bash -n` exits 0 for all four scripts, and
`grep -c '"$here"/analytics.c\|"$a"/analytics.c' coax/web/api/test.sh coax/web/api/mesh-test.sh coax/web/api/eval-builder.sh coax/web/api/realm-gate.sh`

### Step 4: Check that the Dockerfile agrees

In `coax/web/api/test.sh`, directly after the `api_sources` call, add a
comparison of the two lists by base name:

```bash
diff <(printf '%s\n' "${API_SOURCES[@]##*/}" | sort) \
     <(grep -o '/src/[a-z0-9_-]*\(\.generated\)\?\.c' "$here/Dockerfile" | sed 's|/src/||' | sort) ||
  { echo 'api: the Dockerfile and api-sources.sh name different files' >&2; exit 1; }
```

**Verify**: run just that comparison by hand from the repository root:


## Maintenance notes

- Adding an API unit now takes two edits: `api-sources.sh` and the
  Dockerfile. `test.sh` fails if they differ.
- A further step would have the Dockerfile read the list too, for example
  by having `deploy.sh` write it into the build context. That changes the
  production build and is left for a change the owner asks for.
- `realm-gate.sh` compiles with `-w`, which hides warnings, while `test.sh`
  uses `-Wall -Wextra -Werror`. This plan keeps each script's flags as they
  are.
