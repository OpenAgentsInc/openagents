# Psionic: ML From Scratch

This book builds a machine-learning library from small understandable pieces.
Every completed chapter runs the actual [Psionic library](../README.md), with
checks and independently specified results.

[Chapter 1](ch001-learning-a-number.md) starts with learning a single number.
You need basic programming and enough arithmetic to multiply and average two
numbers. It explains the small amount of calculus as it goes. For the
language, use [the Coax book](../../coax/book/README.md).

Coax listings, equations and short illustrative blocks use `jai` Markdown
fences for syntax highlighting. Command blocks use `shell`.

A chapter whose status is *Unimplemented: design draft* is written ahead of
its code. Its first line under the title is a quoted
`**Status: unimplemented — design draft.**` marker; it explains the method,
the design, what it will build and its acceptance checks, and has no
source-linked listings or examples. Sketches in it are illustrative only.
The physics engine and the spacecraft chapters, first drafted here this way,
are now Parts IV and V of [the Aethyr book](../../aethyr/book/README.md).

## Chapter status

The [chapter registry](chapters.json) records every chapter's number, title,
status, profile, dependencies and three separate facts:

- **Implemented source** (`source`): the code the chapter shows or runs.
- **Qualified targets** (`qualified_targets`): the targets, such as `cpu`,
  `cuda`, `metal` or `wasm`, with recorded evidence for the chapter's
  profile. Source that might compile for a target doesn't qualify it.
- **Adoption** (`adopted_by`): code outside the book that uses the chapter's
  implemented components today. A host, build binding or another library can
  consume one component without adopting the entire profile. Tests, examples
  and fixtures are evidence, not adoption. An empty list means no reviewed
  consumer is recorded, not that none exists.

A chapter's status is one of *implemented*, *partly implemented*, *design
draft* or *planned*. A design draft starts with the quoted design-draft marker above, and a partly implemented chapter with `**Status: partly implemented.**`. `python3 psionic/tests/book.py` fails when a status marker, a
contents label, the status column below or the registry disagree.

## Promoting a draft to a teaching chapter

A design draft or planned chapter becomes a teaching chapter only when it has
all four of the following:

1. **A worked calculation or trace.** A small input whose result the chapter
   works out by hand, step by step, before the program runs.
2. **Runnable source.** The code and an example in `psionic/examples/`, listed in [examples.json](examples.json), with an exact
   transcript that the book's checks compare in debug and release.
3. **A deliberately broken case and its diagnostic.** An input or an edit
   that the code refuses, with the exact error or refusal shown and its exit
   status checked.
4. **An independent check.** A result computed another way, such as a
   separate oracle, a reference implementation or a hand-derived value, that
   the checks compare with the code's result.

When all four exist, update the chapter's status in the same commit in four
places: the chapter's status marker, its entry in [chapters.json](chapters.json),
its label in the [contents](SUMMARY.md) and its row in the table below. The registry
check fails when they disagree. [Coax chapter 29](../../coax/book/ch29-units-and-frames.md)'s
affine section is an example: a hand calculation, `examples/ch29_frames.coax`,
a refused program with `E0834`, and a `#test` that compares the result with
plain arithmetic.

The same inventory may also record `libraries`: native-only Coax examples
with `kind: "native-library"`, a `chapter`, a host `consumer` and retained
`evidence` paths. They remain part of closed source/link coverage, but
`book.py --coax` executes only the runnable `examples` list. Library records
do not declare evaluator transcripts or qualify native evidence merely by
listing it; their separate native commands and receipts state that scope.
The inventory tooling regression is `python3 psionic/tests/book_inventory_test.py`.

To find a route through the four books, see [Paths through the
books](../../docs/books/paths.md). The [shared completion
milestones](../../docs/books/completion.md) distinguish runnable teaching
profiles from complete training, serving, game and robotics workflows.

The learning route starts with chapters 103–104, then the tensor/function
transforms in 106–107, the tiny decoder in 112–118 and nanochat in 123–139.
Their status rows distinguish bounded CPU implementations, actual device
training and the remaining generality/performance work. Chapter 218 checks a
Pylon before advertisement; chapters 215–225 and 239–249 supply calibrated,
measured decision/evaluation components with their stated real or simulated
inputs. The agent harness that started at chapter 200 is now the
[Coder book](../../coder/book/README.md), chapters 1–8 and 14–22.
The table and registry, rather than an unlisted-chapter rule, determine
which chapters are implemented, partial or drafts.

The [contents](SUMMARY.md) list completed chapters; the [chapter plan](PLAN.md)
sets the proposed full reading order: early Elephant/Mammoth and useful
retrieval, gpt-oss, Mistral and DeepSeek, then training/nanochat, vision,
motion, speech, physics, world models and robot policies (in worlds
simulated by [Aethyr](../../aethyr/book/README.md)), production hosting,
inference across a mesh and measurement.
Its prerequisite map lets independent branches start earlier than their
