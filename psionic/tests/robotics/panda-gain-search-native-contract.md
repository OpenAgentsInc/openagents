# Owned Panda gain search: native transport

Part A searches the nine frozen Kp/Kd scale pairs on four fixed owned scenarios.
Profile 1 is the previously qualified (1,1) family: its four fresh branches are
copied from the exact original PTO1 trace, never simulated again. The other
32 rollouts execute once, in release mode, for at most 24,000 committed updates.
A refusal retains its complete prefix and status; it does not publish a fake
state or trigger a retry. Existing plant, controller and reference proofs carry
by source identity. The gain family remains scenario conditioned: the brake
scenario already has a different seventh-joint derivative gain.

Coax owns gain construction, stepping, metric reductions, validity, feasibility
and selection. The C harness performs calls, byte transport, snapshots and I/O.
It cannot choose a gain or relax a goal. Part A never loads or links the SDK.

## Interfaces and bytes

The generated header is `panda-pd-gain-search.h`. The private build makes an
identical alias named `panda-joint-pd-tracking.h` for the unchanged shared record
header. The failed first include attempt and its exact tooling bytes remain in
the qualification history. No generated arithmetic was changed for that fix.

A private new rollout starts with five little-endian I64 words: profile, case,
committed count, failure stage, failure code. It then retains count complete
1040-byte fresh Pnt records. Interrupted files retain their actual extents,
complete payload rows and any trailing bytes even if the header was unfinished.
The final normal ledger has 64 before/after events, two per new rollout.

The public cache header is six U32 words: PGC1, 9, 4, 750, 208, 1. Each 208-byte row is
post-q9, post-v9, then eight I64 words: profile, case, tick, stage, code, Pjp clip,
actuator-control clip and actuator-force clip. The 36-row index contains six I64
words per row: profile, case, offset, count, failure stage and failure code.
Complete 750 rows require status0/0; shorter prefixes require a nonzero failure.

Extraction copies fresh-record bytes 808..951 without float conversion. Before
copying, every recorded pre-q/v must equal the initial state or preceding post
state exactly. Baseline extraction skips each old shadow suffix. Its full old
trace hash, original qualification, source, gains and references remain bound.
The public lineage records all 32 new raw identities and all 36 cache ranges.

Cached observations marshal to Coax's 256-byte record: q9, v9, previous-v9,
status stage/code, and three clip counters. Previous-v comes from the frozen
initial rate or previous cached post-rate. Scoring writes 36×360-byte case cards,
9×72-byte candidate cards and one 64-byte selection. Those bytes and all ABI
sizes/offsets are independently checked. All floating fields must be finite
before metric comparisons. Candidate failure is a finite invalid card.

## Execution and scope

Preparation emits two contexts once, builds three host profiles and checks new
shape/refusal/output snapshots, a score alias, a combine alias, a selector alias,
none-feasible behavior and a literal ordered-winner witness. Baseline step calls
must refuse before plant arithmetic. The canonical grid is one release run.
Only cached scoring runs in debug, release and fail-fast ASan/UBSan; its complete
score bytes must agree. This is not three independent physics grid runs.

The default shell gate, `check-panda-pd-gain-search.sh`, calls only the offline
cached adapter. It consumes committed data and emits/rebuilds the scorer for an
explicit compiler context; it has no private baseline or SDK dependency. Its
new adapter path is syntax/routing checked during packaging, with original
measured numerical results carried separately. The explicit one-shot prepare
adapter supplies the private header alias without repeating the historical
failed attempt; its new adapter path is likewise not numerically rerun here.

The fixed terminal band applies to all four cases. Hold additionally limits
peak drift; nominal tracking additionally beats the frozen stationary SSE.
Selection uses exact F64 lexicographic terminal score, total position IAE,
Pjp-clipped coordinate count and profile ID. No feasible candidate is a valid
outcome. Frozen heldouts are not evaluated in Part A. Feasibility is a study
metric, not a collision, hardware, clock, bounded-execution or safety certificate.
